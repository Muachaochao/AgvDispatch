# 自动充电状态机隔离烟测

从主工程目录运行：

```powershell
dotnet run --project tools/ChargingSmokeTest/ChargingSmokeTest.csproj
```

烟测只连接内存模拟车辆、模拟充电继电器、临时目录持久记录与独立临时SQLite数据库，不连接车辆、PLC、日常命名管道或5199服务，不修改运行数据库。

检查完整充电流程、80%退出与25%启动滞回、两车共享一个充电位的排队、当前业务结束后充电、对接超时、无正电流、过温保护、断网、导航发送及停止结果不确定、后台重启、人工停止和人工处置的资源保留边界。另使用生产交通管理器验证充电会话没有业务任务行时仍持久保持资源，过期与重建不会释放，明确完成后才交给后车。

补充验证终态业务仍保留设备归属或未闭合Outbox时禁止充电；持续业务运行完成整轮箱体循环、关闭设备责任且停稳后才交接。交接保留待处理呼叫，停止模拟器新增呼叫，不发送待机导航，也不由充电模块释放原业务路权。

人工停止通过独立安全控制门仅发送一次继电器关闭，即使启动恢复门禁未放行也可请求。之后保持充电位与车辆归属；只有人工核对续接原停止观察后才允许检查离位，不能自动退出。额外覆盖过温同时存在BMS阻挡报警仍执行一次保护停止，以及达到目标电量时电流自然趋零仍走正常停止流程。

厂家继电器接受请求与真实充电电流分别模拟。通过本测试仅证明软件在这些合成事件中的调度和持久化行为，不证明现场精确对接、充电桩握手、6005继电器策略、电流方向、温度阈值或物理离位已经验收。充电位需要按现场核定后配置启用。

当前策略把正数电流作为充电、负数作为放电，停止判断同时要求`Charging=false`。本地协议未定义电流正负方向，这一策略必须用现场实测核定后才能启用；模拟负电流通过不代表厂家已确认方向。
