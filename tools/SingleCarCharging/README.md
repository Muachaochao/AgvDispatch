# 单车激光反光板识别与充电对接工具

## 2026-11-01 修复后的使用边界

本目录仍是分阶段现场工具，不是一键自动充电调度器。当前车辆为插头式对接；桩屏通用的“刷板”字段不能作为本车型接触、伸缩或退离依据。以下旧试验记录仅用于溯源。完整流程与参数归属见[充电流程设计](../../docs/architecture/单车充电流程与恢复契约-20261101.md)。

- `charger_session_runner.py` 维持 20207、20204 两条 TCP 连接，核对每次握手和心跳应答；每次读取有效 BMS 上限，指定电压/电流只能下调。未知、零或 `-1` 上限不能用配置兜底。
- `charging_interval_verified` 只表示结束前连续的充电观察通过：DO7、两路 charging、有限正电流和有界采样间隔均成立，默认至少 60 秒。历史最长区间不能代替最后一段。`charging_test_passed` 还要求 `shutdown.verified=true`；`full_docking_cycle_verified` 始终为 false，因为本工具不负责导航、接合和退离。
- 停机期间继续保持 TCP，核对关闭命令应答、车端 DO7 关闭、两路充电状态结束和电流停止，以及桩侧退出自动模式与电流停止。桩仍返回自动/20A 时报告 `shutdown_not_confirmed`，不得据此自动退车。`output.current` 的厂家含义尚未核定，保守拒绝不能替代厂家核对。
- `is_stop=false` 不能简单当作误报删除：充电观察同时记录 vx/vy/w，要求全部为有限零速且 chassisIsStop=true。移动准备与移动完成仍要求停止标志和速度一致；软件急停与阻挡仍保留。
- 识别须有三个稳定样本，位置跨度不超过 20 mm、角度默认不超过 2°，不再允许放宽至 4°/5°。跨 ±π 的角度按环形角差计算中位数。识别失败停止该阶段，不能改用另一辆车的历史世界坐标直插。
- 末端只允许沿已核定对接轴作有界前后移动。未标定的横向、转角或复合路径会在移动前拒绝；偏差较大时退回粗接近重新识别。避障停止距离限定为 0.05～0.10 m，不允许设为 0。这个软件范围不等于厂家已核定本车插接参数；如果保护阻止插入，应核对机械结构与厂家的近场对接策略。
- 每次任务查询必须返回本次请求的唯一任务；完成判定不沿用前一轮缓存。上传后重新核对位姿，未知结果保留原 ID、只查询、不重发。历史已完成/已取消任务只有新的 1110 核对后才能作为车辆空闲的证据，这不会关闭后台业务记录。
- `detour_runner.py` 是隔离单车工具：为每轮生成唯一分段 ID，先核对后台整图有向道路/几何、封路和他车占位，再核对车端 1303 直连边。后台未运行、地图不一致或占位未知均拒绝发送。它不提供原子交通资源预约，不能代替多车调度器；也不能把停用车辆当成从现场消失。

离线回归命令（不会启动实车测试）：

```powershell
python -m unittest discover -s tools/SingleCarCharging -p 'test_*.py'
```

源码小补丁由 `Build-SourcePatch.ps1` 生成，只有受审源码、测试和维护文档，无 .NET 运行时、数据库、通信配置或现场位姿。原始 `dock-poses-20261031.json` 是现场证据，只有 AGV-01、AGV-02，不能作为 AGV-03 标定，也不纳入补丁。

当前 `charger/c0001.charger` 配置采用激光反光板识别，输出世界坐标；这里的“视觉对齐”不是已接通相机视觉。`probe_runner.py` 与 `charge_dock_probe.py` 只验证识别结果，不导航、不控制电机或 DO、不启动充电、不抢占控制权，也不取消其他任务。识别成功不能记为自动充电通过。

完整对接步骤已拆成独立工具，尚不是一键自动充电闭环：

| 阶段 | 工具与完成依据 |
| --- | --- |
| 原地识别 | `probe_runner.py`：三次稳定的激光反光板识别，保留目标与车辆世界坐标、车体相对位姿 |
| 坐标转换与粗接近 | `approach_runner.py` / `charge_dock_approach.py`：从识别参考系计算接近点和世界/车体坐标转换，`setPathUseOdo(True)`、`setPathOnRobot` 后循环 `goPath` |
| 末端校准 | `advance_runner.py` / `charge_dock_advance.py`：在已核定间隙内执行一次有界里程计路径，允许前后、横向和朝向修正；到点不证明触点接合 |
| 桩侧握手 | `charger_auto_handshake.py`：按实时 BMS 限值构建或显式发送一次桩侧 `1001`，核对响应、自动模式及报警；应答不证明刷板伸出或充电建立 |
| DO7 与电流观察 | `charger_relay_once.py`：显式执行一次 `6001 / id=7` 并观察；必须以新鲜的车辆充电状态和连续有效正电流确认电气充电，仍不代表完整退出循环已通过 |

Web/C# 的通用充电管理仍是“导航到已核定充电点 → `6005` 车端继电器 → 电流观察 → 停止及退出”的框架，尚未集成上述激光识别、坐标转换、末端校准、桩侧 `1001` 和现场 DO7 全流程。`6005` 与本工具的 `6001 / DO7` 不是同一控制命令，不能仅开启 Web 配置就声称已接通当前充电桩。地图到点、任务完成、继电器应答和完整充电成功需要分别记录。

当前现场充电站参数、双触点观察和继续条件见[现场参数与对接观察](site-parameters-20261031.md)。

需要 Python 3，仅使用标准库。默认 `inspect` 只查询机器人身份、状态、电池、机构脚本列表和充电识别文件目录。指定 `--charger` 仅建立并关闭 20207、20204 的 TCP 连接，不发送充电桩应用数据；端口连通不证明协议兼容。

```powershell
python .\tools\SingleCarCharging\probe_runner.py --robot 192.168.98.66 --charger 192.168.98.11
```

`probe` 会对同目录的固定 `charge_dock_probe.py` 计算 SHA256，只使用派生的 `charge_dock_probe_<sha12>.py` 名称。先核对硬件 ID 和空闲状态，再查询是否已存在该文件：已有文件须逐字节一致，否则拒绝；不存在时用 4021 上传。4022 下载校验成功后，再次读取身份和状态，最后只发送一次 3066 `SELF_POSITION`、`RecognizeOnly` 任务。无法选择其他脚本或任意动作。

```powershell
python .\tools\SingleCarCharging\probe_runner.py probe --robot 192.168.98.66 --expected-id 1ccbd798eee24ccc --evidence-dir .\artifacts\single-car-recognition
```

运行前应确认该 ID 仍对应测试车。前置检查要求：车辆空闲、脚本空闲、未完成路径为空、底盘停止、车端未充电及未急停、控制权已释放、`dispatch_mode=0`；已返回的错误和严重错误也必须为空。车辆可能保留已完成(4)或已取消(6)任务 ID，须用新 1110 确认该唯一原任务的相同终态；失败任务只接受本工具固定充电前缀并再次核对。其他门禁全部保留。这不会清除后台业务记录，也不会取消或重发上次任务。`manual_charge=false` 只说明车端未报告手动充电，不能单独证明插头已拔掉。若控制权不允许发送，保留拒绝结果，不自动抢权。

每次运行创建独立证据子目录，包含固定源码、精确请求报文、发送前意图、原始响应和本机接收时间。上传、执行遇到超时或损坏响应，结果视为未知并立即停止；不会自动重发。执行收到确认后，最多观察 30 秒，通过 1110 匹配原任务 ID，并优先解析 1100 的 `move_status_info`，兼容 `script_res`；两个原始通道均保留，`report_source` 标明实际采用的通道。只有任务完成且结果同时匹配探测标记和本次 `run_id`，并给出三次成功采样，才报告 `recognition_probe_completed`；充电验收状态始终为 false。

退出码：0 为查询完成或识别探测完成，2 为明确拒绝或失败，3 为结果未知。出现未知结果后，先核对证据和车辆状态，不直接重跑。结果中的相对位姿是识别参考系，不能据此直接让车辆移动同样距离；接触偏移、进退路线及桩侧握手仍需另行核定。

后续对接需按本车单独标定识别参考系到车辆停靠中心的偏移，包括车辆触点位置、桩侧插头位置和接合/退出行程。地图上的当前站点名称、车体外形的前伸长度及识别返回距离均不能替代该偏移。接近点与最终对接点应分别配置，核定前保留现有业务站点。

识别和移动工具不向充电桩发送应用数据；单次桩侧握手由 `charger_auto_handshake.py` 负责，连续会话使用 `charger_session_runner.py`。桩侧 `1001 input/status` 含充电控制参数，不能当作只读状态查询；机器人 `6005` 或 DO7 关闭应答也不证明桩已停止输出。启用实际充电与退离前，应核定当前桩适用的握手、插头接合、停止输出与允许退出定义。

每次握手必须重新读取 `1007` 的 `max_charge_voltage`、`max_charge_current`，仅接受有限正数。未显式指定电压/电流时使用本次 BMS 限值；显式指定也不得超过它。`-1`、`0/-0.0`、缺失或无效字段均不能当作不限值；不能沿用照片或历史试验的 **58.8 V / 22 A**，也不能用厂家参考脚本的默认值补齐。历史参数只用于回看当次证据，不是下次发送许可。

## 粗接近测试

`charge_dock_approach.py` 每次只执行一个“识别后低速停靠”的移动阶段。默认从当前 LM52 粗接近到桩前约 0.875 m；车辆先完成三次稳定识别，再校验当前中心距、横向偏差不超过 0.45 m、朝向误差不超过 0.35 rad、单次前进不超过 0.60 m。以首次现场识别值约 1.274 m 计算，第一段预计移动约 0.48 m，速度上限 0.03 m/s；到位后再次识别并停在粗接近位置。通过 `--standoff-m 0.675` 可在已到粗接近位置后执行第二段约 0.20 m 的接近，但不执行最终接触。脚本不控制充电继电器、不向充电桩发送应用数据。

2026-10-31 现场测试中，第一段从 `1.2747 m` 低速移动到 `0.8889 m` 后，三次识别结果稳定；第二段移动到约 `0.688 m` 后，近距离复测返回识别状态 3，但车辆已在规划点停稳、未充电且无错误。近距离阶段因此以有界路径到点作为完成条件，不再把近距离识别作为完成门禁；后续退出或重新接近仍必须重新识别。

执行前应确认现场人员位于急停按钮旁，并能观察双触点。命令必须显式填写车辆和当前站点，不能由脚本猜车：

```powershell
python .\tools\SingleCarCharging\approach_runner.py --robot 192.168.98.66 --expected-id 1ccbd798eee24ccc --expected-station LM52 --evidence-dir .\artifacts\single-car-approach --stage-only

python .\tools\SingleCarCharging\approach_runner.py --robot 192.168.98.66 --expected-id 1ccbd798eee24ccc --expected-station LM52 --evidence-dir .\artifacts\single-car-approach
```

第一条命令只上传并回读校验脚本，不下发导航；第二条才执行一次粗接近。出现未知结果时只保留证据，不自动重发。第一段完成后重新核对桩侧缩回触点与车侧自动触点间隙，再决定后续接近点和末端标定参数；不能将历史分段距离直接当作当前接触行程，也不能把约 0.875 m 的粗接近记为充电通过。

完成粗接近并核定接触间隙后，`advance_runner.py` 会重新核对车辆当前坐标和朝向，再执行一次有界末端路径。`path` 模式使用 `setPathUseOdo(True)`、`goPath`，仅允许沿对接轴前后 -0.30～0.15 m，速度为 0.002～0.02 m/s；默认速度 0.01 m/s、路径到点容差 0.001 m。横向、转角修正会拒绝，避障停止距离不得低于 0.05 m。这些是软件允许范围和控制器容差，不是现场推荐行程，也不证明机械触点达到毫米级对接精度。实际参数必须来自本轮识别、接触偏移标定和现场间隙核对；脚本本身不重新识别、不控制充电继电器，也不与充电桩通信。

```powershell
python .\tools\SingleCarCharging\advance_runner.py --robot 192.168.98.66 --expected-id 1ccbd798eee24ccc --evidence-dir .\artifacts\single-car-advance --distance-m 0.10 --max-speed 0.01 --stage-only

python .\tools\SingleCarCharging\advance_runner.py --robot 192.168.98.66 --expected-id 1ccbd798eee24ccc --evidence-dir .\artifacts\single-car-advance --distance-m 0.10 --max-speed 0.01
```

第二条命令会移动车辆，只在现场已核定插接间隙、路径无人且急停可操作后执行。同一位置不可自动连续补发多个 0.10 m 分段。

可选 `open_speed` 仅为短时速度诊断，限定前进不超过 0.01 m，不允许横向或转角。它按持续时间停止，不能证明实际移动了指定距离；脚本报告 `stopped_unverified`、`distance_verified=false`，runner 分类为 `open_speed_stopped_distance_unverified` 并以退出码 2 要求核对。即使定位坐标变化，也不能据此宣称完成毫米级插入；旧脚本只按计时给出的 `completed` 同样不会被提升为距离完成。出现该结果后不自动追加试动。
