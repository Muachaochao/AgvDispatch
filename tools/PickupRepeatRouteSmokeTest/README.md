# 同工位再次取箱路线回归

```powershell
dotnet run --project tools/PickupRepeatRouteSmokeTest/PickupRepeatRouteSmokeTest.csproj -c Release
python tools/PickupRepeatRouteSmokeTest/check_lab_template.py
```

此测试使用临时 SQLite 和随机 loopback TCP 端口，不连接现场设备、不修改工程运行库。

覆盖：

- 同点的运输规划必须选择已启用有向图中的非零闭合路径，携带完整边序及资源；考虑双向边、禁用、占用与拥堵代价。
- 普通最短路查询仍可返回零长度结果；正式首段预览、手动可达性、建单、派车使用运输路线规则。
- 已在取货点的车辆实际沿相邻边离开并返回；这是有真实移动的进出路线，取箱动作仅附在返回末段，不是原地动作。
- 无合法闭合路则拒绝；不得拼造同点边、瞬移车辆、直接完成首步骤或用人工改位置绕过。
- 同点首段闭合路排除等待点及倒料点，不能在本轮 PLC 许可前借用业务倒料路线绕行；独立进出路线被占用时继续等待。
- 正式 Outbox、不可变发送快照与 3066 相邻段/原子任务编号保持一致，1303 拒绝回程直接连接时禁止发送。
- 实际出区的当前地图核验：唯一坐标绑定、地图名/MD5、稳定性、载入、本地版本；用真实 Robokit 1300/1022/1302 loopback 回归正常及 MD5 不符。

图中的已启用道路、方向和车辆可通行范围仍需现场核定。合成回归夹具不证明厂家固件、载荷及现场路线已验收。
