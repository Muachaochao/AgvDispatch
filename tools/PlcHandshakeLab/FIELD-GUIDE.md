# PLC人工联调台：厂家测试操作

双击“打开人工联调台.cmd”。请复制整个发布目录到测试电脑，不能只复制EXE。不需要.NET、Python或Web虚拟设备。

## 接好调度

1. 打开“连接与点表”。监听IP填本工具电脑的网卡IPv4；允许调度IP填调度电脑IPv4。两者同机时均填127.0.0.1。
2. 默认端口10200；调度端也要填写10200。需要102时可改，端口必须未被占用。跨电脑连接需网络互通并允许该TCP端口。
3. 核对DB号、字节、位及工位/倒料设备编号。默认是下表，实际使用前与调度的CSV核对。导出CSV使用主工程14列点表格式，导出JSON可留作本工具的配置模板；均不会自动覆盖调度配置。
4. 点击“启动S7服务”。调度使用SiemensS7驱动连接。状态条区分断连、等待数据交换、正常和超过3秒通信停滞。H保留值会变灰并标“·旧”；逐点显示S7交换时间和最后变化时间。只有连接/协商不代表采集正常。
5. 保持“人工控制全部P点”，按实际情况操作。车辆连接、地图、路线和建单仍在调度端完成。

## 逐阶段测

手动发满箱呼叫 → 看调度H应答 → 清呼叫 → 看AGV实际取箱 → 箱体检测给0 → 看AGV实际到等待点及H申请 → 核实条件后给Ready → H撤申请后清Ready → 看AGV实际到倒料点及H倒料周期 → 实际倒料完成后给Done → 看车辆实际退出及H闭合 → 按约定清Done → 实际放箱后箱体检测给1 → 看H各通知和返箱责任闭合。

- P点用明确的“置1”“清0”操作；H点由调度写入，不能手动操作。
- 请求/应用时间是模拟DB状态，鼠标停在行上可查看最后来源。它不代替物理传感器或车辆实际动作。
- 28阶段由人工选择，查看条件、待观察H点、待操作P点及停留时长。选阶段不会改信号，不能靠跳步让任务成功。
- 需要故障试验时，可手动设置工位故障、下游离线或倒料故障，观察调度是否等待或报错。
- 调度契约须为 `plc-28-stage-v2` 并显式启用。旧版 `sender-owned-return-confirmed-v1` 任务保留原记录，不自动迁移。工具不会强改H信号来凑表。
- 第7阶段取箱通知保持1到返箱后的第25阶段；PLC不要因检测无箱就清H取箱通知。
- 第19阶段应在车辆及箱体实际退出已核定倒料区域后观察H周期清0，再于第20阶段撤Done，核对Ready及申请已低。调度持久化交接后后车可接用倒料设备；原车返箱责任保持。
- 第25阶段清取箱通知，第26阶段清放箱通知，第27阶段最后清返箱责任。原车收尾不应再改后车正在使用的共享倒料位。
- 若出区配置、车体/箱体包络、定位或地图身份不满足，调度保持占用并说明原因；点击“实际已退出区域”只是观察日志，不能强制放行。当前位置进度需在可核定直线段；返程曲线只有完整保守边界加整车误差包络完全区外才可作为后续不再入区证据，否则保守保持。
- 看到受理应答1后必须撤满箱呼叫0，首段才开始。取箱清应答及最终清返箱责任前仍要求本轮呼叫0；旧需求不撤、原工位无箱或返程/交接证据不足时，不能继续清通知和责任。H清0.6之后PLC可以锁存新的满箱事件，后台保留新呼叫并完成前轮闭合；不能把旧呼叫高电平留到返箱。

## 自动模式

“自动握手（箱体仍人工）”自动撤呼叫、完成Ready握手，并在有效许可下按配置延时模拟Done。倒料周期撤销后自动清Done。箱体检测仍由人确认。

自动Done是定时模拟结果，不是实际倒料完成。厂家逐动作核实时优先使用人工模式。切回人工保留所有电平及已消费的许可；12/13阶段切回自动可继续原保留。工位故障/下游离线只抑制本站自动撤呼叫，共享自动倒料由倒料故障点抑制；这是模拟策略，现场联锁另行核定。

倒料故障期间不计成功时间，周期持续有效时故障解除后重新等待完整延时。若周期提前撤销、等待握手未闭合就进倒料周期、许可消费后重新申请、人工接管Ready/Done，或有活动许可/共享信号时通信中断，会显示“暂停待核对”；不能靠重连或切模式自动恢复。请切人工，核实原任务、设备及实际区域，等待调度撤H申请/周期，按约定清P的Ready/Done和故障，使共享四位全部低；在观察备注填写依据，点击“确认模拟周期闭合”，再切自动。该确认不改变点位、不关闭调度任务、不释放任何路权。

## 逐阶段测试结果

在参考阶段填写车辆、任务、观察依据，选择“通过/失败/跳过”。通过需要勾选“本阶段实际条件已核实”，且通信正常、10点均有3秒内并不早于最后变化的交换记录、电平符合、无工位/倒料故障、下游在线、无恢复门禁。未建单时任务栏可明确填“未建单”。不能把旧值或只符合电平当作通过。

“逐阶段测试结果”页显示本工位本轮全部28阶段，未记录为“未测”。“新一轮记录”只创建记录分组，点位和调度任务不复位；可保存两轮及复测历史并导出完整阶段报告。切换阶段或工位会取消实际条件勾选，避免沿用上一阶段确认。记录只表示操作者核验，不替代厂家验收。

## 记录与停止

填写车辆/任务编号，选择“实际已取箱”“实际已退出区域”等观察项，可加备注。记录包含时间、人工阶段和当时点位快照，不会自动修改信号。

完整日志和本次配置保存在 `%LOCALAPPDATA%\AgvDispatch\PlcHandshakeLab\日期\`。界面仅显示500条，点击“导出完整会话CSV”可保存全部记录。

1.3.0新增“一键导出联调证据ZIP”：选择保存位置，后台打包本会话原日志、配置、点表、完整CSV、阶段报告、版本摘要和SHA256清单。导出期间仍可操作P点，调度可继续S7交换；内容截至点击时刻。可点击“取消导出”，原目标文件不会被半成品替换。导出目标写盘失败不停止PLC服务；原会话日志本身写入失败仍会停服务。

返场查看旧测试时，点击“历史会话只读回看”，进入日期目录选择原 `.jsonl`，保留同名 `.config.json` 在旁边。可按工位、轮次查看28阶段、车辆/任务和原始事件，也可导出历史证据包。无需启动PLC；不会恢复旧P/H或操作调度。未测仍是未测，失败和复测都保留；日志尾部损坏或缺配置会显示提示。证据包不包含厂家车辆或调度数据库，需要这些记录时仍从对应系统正常采集。

停止服务会断开调度连接，原值只留作回看；再次启动是新会话，重新使用点表初值。它不会暂停车辆，也不会撤销调度任务。运输中的停止与恢复应按调度流程处理。
