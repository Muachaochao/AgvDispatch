# PLC 握手时序实验台

独立 WPF 工具，保留用户于2026-10-21与电控统一使用的 **28阶段 / 10信号** 表。主工程对应显式启用的 `plc-28-stage-v2` 契约；工具支持离线演示、独立S7人工PLC和连接WebSingleVehicleLab。选择表内阶段不会替主工程推进检查点。

## 独立人工PLC网络联调（2026-10-21新增）

运行仓库根目录 `Start-PlcHandshakeLab-Network.cmd`，或 `PlcHandshakeLab.exe --network`；原窗口也有“打开独立PLC人工联调台”按钮。新模式内置独立S7 TCP服务，**不依赖Python、WebSingleVehicleLab、本地文件通道或主程序服务**。它只扮演PLC，不替调度派车、不控制或模拟真实AGV。原离线和本机虚拟设备联调仍保留，三种模式相互独立。

### 厂家操作步骤

1. 复制 `artifacts/PlcHandshakeLab-current.json` 所指的版本化发布目录，或解压本次 `PLC人工联调台_1.4.0_*.zip` 到测试电脑，运行其中“打开人工联调台.cmd”。不需要安装.NET。`release-manifest.json`记录源码提交和逐文件SHA256，旧发布包保留供追溯。
2. 在“连接与点表”中填写测试电脑本机网卡IPv4、S7端口及允许连接的调度电脑IPv4。默认 `127.0.0.1:10200` 仅用于同机调试；跨电脑时使用测试电脑实际IP，调度端填同一个IP/端口，网络及防火墙需允许该TCP端口。工具不自行修改防火墙。
3. 核对DB、字节、位和初值，可导入/导出JSON配置、添加/移除工位、导出正式 `PlcSignalCatalog` 可读取的14列CSV点表。默认CNC-001=DB1第0字节、CNC-002=第2字节、共享倒料=第610字节，共21点；不当作现场已核定地址。倒料站编号默认DUMPER-001，可配置。
4. 点击“启动S7服务”。调度端使用现有SiemensS7驱动、相同连接参数和匹配CSV；调度的工位、倒料设备编号也必须匹配。真实车辆、地图、路线、派车权限仍由调度配置，本工具不修改它们。工具不会自动把导出的CSV应用到主工程。
5. 保持“人工控制全部P点”，手动发满箱呼叫、观察H呼叫响应后清呼叫；实际取箱后给箱体检测0；实际到等待点、联锁成立后授予Ready；消费后撤Ready；实际倒料完成后给Done；退出闭合后撤Done；实际放箱后给箱体检测1。
6. H侧6个业务信号始终只读，由调度经S7写入。信号表给出请求值、应用时间和当前模拟DB值；它们不是物理传感器反馈。停止服务会断开调度连接，停止后的值只供回看。再次启动是新会话，按点表初值初始化；不恢复旧H输出。
7. 人工选择28步参考阶段，查看待观察H点、待操作P点和阶段停留时长。选阶段不改变任何电平，不自动断言到站或完成。可标记实际取箱、等待点、倒料点、倒料完成、实际退出、实际放箱，附车辆/任务编号和备注；观察事件包含当时点位快照。

除原10个业务信号外，提供工位故障、下游在线及倒料设备故障输入。人工模式允许保留异常电平以测试调度等待及错误处理，不强行跳步、闭合或清零。

### 自动模式与人工模式

自动模式是**自动PLC握手（箱体仍人工）**：收到H呼叫响应后撤呼叫；收到等待申请后授予Ready，申请撤销后撤Ready并保留内部许可；本轮倒料周期通知成立、许可已消费后，按配置延时模拟Done；倒料周期撤销后撤Done并结束内部许可。该延时不是实际倒料结果。箱体检测一直由操作者确认，不按运输耗时推断取放箱。

切回人工模式不改变已有电平，自动反馈立即停止。Ready消费后（12/13阶段）内部保留随模式切换继续，不会丢失许可。已有倒料周期、Ready、Done或恢复门禁时不允许切入自动，先核对闭合。工位故障/下游离线只抑制本站自动撤呼叫；共享自动倒料只由共享倒料故障点控制，这是模拟器策略，不能推定现场PLC联锁相同。

共享倒料故障暂停计时；周期保持有效且故障解除后，重新等待完整延时。未完成倒料即撤周期、许可消费后重新申请、未消费许可就进周期、人工接管Ready/Done或活动周期通信中断，都进入“暂停待核对”。恢复通信不会清掉门禁。切人工，核实调度原任务及实际设备，等待H申请/周期撤销，按实际条件清P的Ready/Done并清倒料故障，在观察备注写明依据，点击“确认模拟周期闭合”，再切自动。该按钮只清模拟器内部保留，不写任何P/H、不取消调度任务、不释放调度路权。

### 通信质量和逐阶段结果（1.2.0）

状态条区分未连接、已连接待交换、正常、超过3秒无S7数据交换、停止回看。COTP连接或协商不算数据交换；断连和恢复持续写入JSONL。H旧值显示“·旧”并变灰，不能当新反馈。每点“最后变化”和“S7交换新鲜度”分开记录，重复同值写入也刷新交换时间；只读取某个BOOL不会把同字节其他位伪装成已交换。交换表示调度读取或写入模拟DB，不代表物理动作。

人工选阶段后填写车辆、任务和观察依据，勾选“本阶段实际条件已核实”，再保存“通过/失败/跳过”。通过还要求通信有效、10点均有3秒内且不早于最后变化的交换记录、电平符合及无恢复门禁。未建单阶段可在任务栏明确填“未建单”。“逐阶段测试结果”页列出全部28阶段，未记录为“未测”，保留复测历史；“新一轮记录”只分组，不复位点位。可导出完整Markdown阶段报告，并继续使用全量CSV/JSONL保存原始证据。工具不会自动证明到站或出区。

### 历史回看和证据导出（1.3.0）

窗口底部“导出完整会话CSV”“一键导出联调证据ZIP”和阶段报告均后台执行。仅在取得原日志句柄、完整字节边界和本会话配置时短暂锁定，后续读取、压缩、写盘不持有通信锁。导出时可继续P输入及S7通信；导出内容固定为点击时的日志范围，不随新事件无限延长。可取消；正常取消/导出失败会清理临时文件并保留原目标文件，不停止S7。关闭窗口会取消并等待本窗口及历史窗口的导出结束。

“历史会话只读回看”选择 `%LOCALAPPDATA%/AgvDispatch/PlcHandshakeLab/日期/` 中原 `.jsonl`，自动读取同名 `.config.json`。无需启动S7，独立窗口显示原工具版本、工位/轮次、28阶段最后结果、车辆/任务及最近500条事件；完整导出保留所有事件和复测。回看不写P/H、不恢复旧内存、不创建调度任务，也不替换正在运行的会话。缺少或无效配置时明确提示、不推测点表；损坏记录跳过解析并提示，原文仍进入证据包。

ZIP包含原始日志前缀 `session.jsonl`、会话配置（存在时）、正式格式 `plc-signals.csv`（配置有效时）、完整 `session.csv`、`stages.md`、`summary.json` 及逐数据条目的SHA256 `manifest.json`。摘要区分原会话工具版本与当前导出工具版本，记录边界和解析异常；清单不自校验自身。校验用于确认包内内容一致，不证明人工观察或源日志真实性。包中不收集调度数据库、其他应用日志、授权码或实车验收结论。

### 现场操作界面（1.4.0）

人工联调面板固定分为4个P输入和6个H只读反馈，显示地址、当前内存、阶段参考和每点交换新鲜度；H区不显示输入按钮。未启动时实际值为“—”，不把点表初值当作当前设备值。工位故障、下游在线和倒料故障集中在P区下方的折叠项，折叠时仍显示当前内存的联锁异常摘要。短窗口自动缩小核心点位行高，默认面板已检查1120×740及1380×900下10点无需滚动；故障和说明展开内容可独立滚动。

右侧固定突出当前人工标记、阶段条件、“现在该操作什么·P”“正在等待什么·H”。选阶段只改人工标记，不写任何点；只符合参考电平仍须核实逐点新鲜度、设备联锁和实际动作。现场观察、结果填写与恢复说明分别折叠，避免长说明占据主操作区。

“逐阶段测试结果”新增28格进度及“仅显示失败”。进度条统计本工位本轮**已记录**的阶段数，包含失败/跳过，不等于已通过。每格保留结果文字提示与颜色；点击数字或结果行只查看，不切换人工标记、不写日志或点位。右侧按所查看阶段列出10点的参考值、当前内存及差异/质量，阶段22箱体检测正确显示0/1；下方展开查看上次保存结果的车辆/任务、观察、差异和原快照，与当前内存明确分开。勾选失败筛选不改变完整报告或28格统计。

“会话日志”独立页提供全部/业务/通信/异常筛选，主面板也有直接入口，查看日志不挤占核心信号区。通信包含S7反馈写入及连接事件；异常包含断连、协议/写入拒绝、自动恢复门禁、人工置故障/下游离线和保存为失败的阶段，允许与业务/通信视角重叠。筛选仅作用于最近500条显示，导出和原JSONL仍保留完整记录，界面显示筛选后数量。

发布脚本仅允许已提交且匹配HEAD的工具源码、验证源码、所带文档及继承构建配置发布，并在清单记录`sourceScope`；独立工程不打包主应用未提交修改。新包仍先自检通过再切换`PlcHandshakeLab-current.json`，原启动脚本自动读取新指针。

### S7实现范围

实现S7 ISO-on-TCP的COTP连接、通信协商、DB BOOL/BYTE读写子集，已用主工程同版本HSL S1200驱动验证连接、批量读取、BOOL写入及回读。兼容Rack/Slot连接协商，不模拟CPU启停、程序下载、PLC程序、M/I/Q区或所有西门子诊断API。每个DB固定8192字节，最多8个连接，仅接受配置的调度IPv4。P位和未映射位不能由调度改变，BYTE写入先核对整项，防止读改写覆盖P位；多项写入按S7逐项返回结果，不保证跨项事务。

默认初态有箱、下游在线、无故障，Ready和Done低，H初值只能为0。点表完整性、地址唯一性、范围及责任方向均在启动前检查，运行中锁定点表。新模式和旧Web设备模型是不同的PLC服务，联调同一个调度实例时应选择其中一个端点，不能把两个DB当作同一设备。

日志及启动配置保存在 `%LOCALAPPDATA%/AgvDispatch/PlcHandshakeLab/yyyyMMdd/`。JSONL持续落盘，记录连接、P输入、H变化、拒绝写入、模式、人工阶段和现场观察。界面显示最近500条，CSV导出读取完整会话。阶段编号0表示连接/共享设备等未归属某工位的事件；工位阶段均为人工标记。日志异常会停止服务，避免无记录继续自动反馈。

调度必须使用 `plc-28-stage-v2`：第7阶段取箱通知置1后保持到第25阶段；返程途中核实真实出区，撤倒料周期并等PLC退出闭合后交接设备/已验证区域；第26阶段撤放箱通知，第27阶段最后解除返箱责任。已有 `sender-owned-return-confirmed-v1` 任务不静默迁移。工具如实显示H写回，阶段选择与观察记录不能替代调度出区判据或实车验收。完整定义和恢复边界见 `../../docs/architecture/28阶段统一执行与联调-20261021.md`。

## Web联调（2026-10-21）

1. 启动WebSingleVehicleLab实例。运行仓库根目录 `Start-PlcHandshakeLab.cmd`，从当前发布指针选择工具及其`defaultLabReady`指定的新实例；未指定默认实例时使用 `artifacts/web-single-vehicle-20261021-28stage/ready.json`，不存在时明确报错。也可运行 `Start-PlcHandshakeLab.cmd --lab "<设备实例绝对目录>"` 显式选择其他实例，或在新发布的程序中通过“选择目录”“连接虚拟PLC”连接。入口只选择目录，不迁移配置或数据库，不自动回退旧20261020实例。
2. 选择CNC-001或CNC-002，点击“触发满箱呼叫”（或满箱呼叫卡片的0按钮）。只发布置1事件，不修改任务、车辆位置、数据库或H输出。
3. 等待“满箱呼叫已反馈为1”，在Web创建任务表单中刷新条件、选择车辆、核对路线、提交。工位呼叫满足不代表首段路线必然可执行，车辆当前就在取料点时现有路线校验可能拒绝零长度首段。
4. 实验台每500ms读取虚拟设备实际状态，显示呼叫应答、箱体检测、返箱责任、等待申请、倒料周期、Ready和Done。设备快照超过3秒、停止、损坏或不可读取时显示未知并禁止输入，不沿用旧值。
5. H侧输出只读；箱体、Ready、Done由现有设备模型产生。联调模式关闭离线播放、跳步和标准值恢复，不通过28阶段表替后台推进任务。返回离线模式仅切换观察，不停止设备或清零点位。CSV分别导出当前模式事件。

联调通道复用设备已有 `device-input.json` / `device-state.json`：实验台发布带唯一编号的外部呼叫，设备模型应用到自己的DB1，正式后台仍经真实S7驱动读取；后台H写入由同一设备快照回显。不存在另一份PLC电平，也不直接改写设备状态文件。单个实例同时使用一个输入控制器，避免多个工具争用单槽输入文件；输入文件写成不代表已生效，必须观察设备反馈。输入按钮在反馈前禁止再次触发，5秒未观察到反馈则提示核查日志。

只接受PLC和AGV均为127.0.0.1、关闭自动建单的独立实例。工位故障、下游离线、无箱或本轮责任未闭合时不触发新呼叫；这些限制不影响离线28阶段学习。既有20261020实例仍可能运行旧二进制和旧契约，不能因为工具已更新就视为28阶段实例。应先保留旧任务证据，再创建匹配新版本和 `plc-28-stage-v2` 的新实例，不直接修改活动旧库或把阶段表套到旧任务上。`WebSingleVehicleLab/prepare_lab.py` 提供的 `SIM-ONLY` 倒料区边界、载箱包络及定位参数足够用于本机虚拟联调，无需等待现场标定；这些合成参数不能作为实车标定。连接实车时须另行核定实际边界、载箱尺寸与定位误差，并完成现场测试。

dotnet run --project tools/PlcHandshakeLab -- --lab <设备实例绝对目录> --live-smoke-test <绝对PNG路径> --station CNC-002

## 使用

- 自动演示：按所选间隔播放；默认末步停止，勾选循环后从初态重新开始。
- 上一步、下一步、点击表格行：暂停播放，加载目标阶段的标准模拟值。跳转是假定该阶段条件成立，不验证物理动作。
- 亮灯代表1，暗灯代表0；本次变化的灯闪烁。表内↑/↓对应相邻标准阶段的电平变化，0/1表示两种电平均有效。
- 点击点位卡片右侧的0/1，翻转本地电平并暂停播放；红框及偏差文字标出与当前阶段的差异。偏差未修正时禁止自动推进。可以手动改回或点击“恢复本步标准值”。
- 第22步箱体检测允许0或1，进入该步保留当前检测值；第23步要求为1。信号相同的相邻阶段仍逐步显示，因为操作条件不同。
- 重置只重置模拟周期，不清事件历史；日志保留最近500条，导出为带UTF-8 BOM的CSV，包含时间、阶段、来源、点位及前后值。

离线模式P/H为责任方，`0.0` / `610.0` 等为用户表内标识；联调模式显示虚拟实例明确的DB1映射（CNC-001为0字节，CNC-002为2字节，共享倒料为610字节），不把它当现场地址核定。本工具没有现场写入或AGV下发功能。离线值不与主工程共享；联调值来自同一虚拟设备，不能证明真实固件或现场联锁通过验收。

到站、任务持久化、设备独占、Done旧低基线、真实退出区域和返箱动作等在离线演示时人工假定成立。网络模式实现模拟许可保留及明确的恢复门禁；它不是厂家PLC内部程序，也不能代替现场故障恢复协议。

后续接入真实点位需要先核定PLC型号、连接参数、工位/设备归属、实际DB地址及访问方向。建议先实现只读监视、数据质量和新鲜度，再实现独立于演示器的受控H侧单点测试；P侧点位不能作为上位机可写位。现场写操作不得由自动演示定时器驱动。
