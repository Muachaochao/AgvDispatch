# 28阶段持久化执行与多任务交接集成回归

运行：`dotnet run --project tools/Handshake28IntegrationSmokeTest`。

使用独立临时SQLite数据库，调用真实TaskHandshakeStore、PersistentHandshakeExecutor、命令Outbox和交通租约管理器。PLC、车辆查询和定位为受控内存设备替身；合成地图用于验证逻辑，不代表真实固件或现场验收。

覆盖取箱通知保持、未知写入与重建执行器、明确恢复核对、原发送返程快照、返程仍执行时两次实际出区证据、Done闭合后的独占交接、只释放自身倒料租约、返箱责任保持、后三阶段清位顺序、第一车收尾不清后车共享输出、三任务顺序竞争及旧契约不静默迁移。原运输动作完成在夹具中受控提供，不通过SQL跳过被测握手阶段。

首段Outbox准备后，箱体离开、0.5/0.6/0.7异常置位或原点表地址变化都会阻断发送，恢复后仍发送同一原命令。另以厂家站点别名配置跑完独立循环，核对合法别名能返箱收尾，而缺失、重复、禁用及与倒料位同点的映射不能作为原站到位证据。

证据数据库保存在控制台打印的独立临时目录；不连接现场设备、不复用运行数据库、不自动删除其他实例。
