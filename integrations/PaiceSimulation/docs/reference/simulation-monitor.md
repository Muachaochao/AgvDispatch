# 任务与车队监控

「任务与车队」显示主工程隔离实例的呼叫、车辆、九步任务及路权记录。

| 区域 | 显示规则 |
| --- | --- |
| 车间路网 | 默认使用运行总览的二维地图，保留编号搜索、拖动、缩放、全屏和小地图。三维复用同一份地图、车辆位置与导航路线。选择车辆、工位、资源后可在地图定位。 |
| 车队状态 | 按工程车队列出车辆，包括暂无反馈的车。显示电量、载荷、位置、当前任务、当前目标与等待时长。标签区分业务、导航、充电和可识别的故障恢复或回待机。目标来自当前命令或步骤；数据缺失时保留未知状态。 |
| 呼叫进度 | 按计划序号区分重复工位。主表显示工位、状态、正式车辆、当前步骤、等待时长和简明原因。候选车只出现在原因中。原始日志、计划和触发时间留在详情。若前一次同工位呼叫尚未闭合且后一次已到触发时间，显示关联的上一单。 |
| 交通资源 | 默认按任务和步骤显示等待申请，区分候选与派车，列出占用车、发生冲突的资源、申请时长和当前连续阻塞时长。连续阻塞期间占用方可能变化，计时以申请最近一次观察到阻塞的起点为准。可展开检查全部关联资源、地图位置与释放记录。切到「按资源查找」可搜索完整编号、查看容量和持有车。 |
| 九步任务 | 呼叫、车体、车队卡片和资源相关任务可打开同一详情。切换对象清除旧导航选择。当前与历史命令明确区分，九步记录保留起止点、用时、导航状态、机构及 PLC 证据。缺少历史采样时显示当前可核对的记录。 |
| 报告回放 | 使用报告自己的地图与车辆采样，可定位车辆和工位。历史坐标按与实时地图一致的转换显示。 |

运行时自动通道占用使用调度后台发布的资源边界定位。旧实例缺少边界时仍可按完整编号查看占用和等待，地图定位仅在有对应节点、道路或边界时可用。

等待详情分别列出本窗口涉及的路段数、资源数、当前占满的资源数及本步骤仍持有的资源数。单项容量表示该资源可同时容纳的占用数，一条线路可以涉及多项资源。候车位不可达时，`waitingCategory: "ReferenceRoute"` 记录一条参考路径，供核对沿线冲突。这类记录不加入路权队列，也不构成实际阻塞链。旧版候车诊断记录继续按参考路线显示。按资源查找时，参考路径经过的资源不产生等待车或阻塞状态。

Global 首次派车缺少可执行候选时，按发车使用的窗口规划核对参考路线。首窗确有容量冲突时，只把首窗的资源写入候选等待队列。若首窗无容量冲突、冲突只在后续路线，且当前找不到可安全分段的方案，整条路线仅作为参考显示。无独立安全落脚点时，实际首窗仍可能覆盖整个通道，直到出口或目标站。通过候车位找到的分段路线在登记前须按最新地图和占用重新规划，并复核候车点与车辆状态。

逐段释放时，发送路线复核读取当前不可变地图快照的规范摘要。地图在激活时计算一次摘要。车尾进度、滚动窗口、租约、释放凭据和写库时的身份核验仍按当轮证据执行。

逐段释放优先使用独立采集的最近两帧有效车辆反馈，避免每次检查都从下一轮采集等起。两帧必须匹配当前发送的命令、路线及采样顺序。反馈断开、过期或切换命令时，原帧不能充当新进度。领取释放凭据后，提交仍需以凭据的第二帧或更新帧为起点，再确认一帧向前的反馈。进度可用时及时复核，实体净空、剩余路径保护及原子写库条件保持原有要求。

候车位独占资源已经占满时，后续运输跳过该泊位的可执行路线搜索。空出泊位后按最新快照正常参加选位。入队与实际获权仍使用原窗口和独占泊位的原子复核。

运行监控显示隔离实例名称、运行包、实际倍率和业务计时。业务计时来自设备时钟或已完成报告，实际耗时按该轮倍速换算。缺少时钟或报告时不补造用时。

轻量实时接口 `/api/simulation/live` 的 `scenario.startedAt` 返回场景开始的 Unix 秒数。空闲时该值可以为空。呼叫表用它计算计划是否到时，缺少起点的旧实例依然能显示呼叫计划及已经观测到的触发时间。

## 候车位续行

长路线在首个安全可停点之前必须保持原子路权。为减少车辆在待机区久等，全局派车可在以下两项都满足时尝试先驶入候车位：

1. 候车位是启用的 `WaitingPoint`，只允许停车，拥有独立且容量为 1 的车位资源，并且进入、离开该点都只有一条单行线段。
2. 以车队中最大已核定载荷车体半径、位置误差和安全间距计算，候车位周围没有任何其他节点或其他道路进入车体包络。

候选搜索比较直接路线和经候车位路线的预计行驶、拥堵、绕行及等待时间。只有首段全部资源可用、完整目标仍可达、候车位本身可用且总成本更优时才采纳。普通 `Waypoint`、未核定车体、双向共用路段、交叉口和缺少净空数据的位置都不能成为提前停车点。

车辆到达候车位并确认静止后，后台立即用最新占用状态复核剩余路线。前方释放时优先续行，原计划被占用时重新比较可执行路线；续行命令仍须取得下一窗口的全部原子资源。已经通过且几何净空确认的路段在续行前释放，候车位及其他重叠资源保持连续租约，避免释放后反复排队或形成持有等待。

配置的候车位全部不可用或不适合当前车辆时，调度可从同一活动地图补充安全候车位。补充条件与本节的净空规则一致：启用的 `WaitingPoint`、允许停车、独占容量 1 停车资源、单入口和单出口、车队最大满载车体与定位误差都不覆盖其他节点或道路。候车位一经任务持久绑定，重试不得换位；后续路线规划和倒料准入使用这个实际绑定位置，界面显示地图可定位的名称及完整资源编号。

验收至少同时满足：直接和经候车位两种路线使用同一地图版本和同一批呼叫；只有满足净空的候车位被选中；车辆未在普通路径点停车；90 个业务步骤完成；持续互锁、超容量和车体包络重叠均为零；收尾租约为零；释放写入提交 P95 不超过 1.2 秒；采用统一业务时钟时，报告中的业务时间不因显示倍率失真。

## 倒料准入

车辆在候车位等待倒料许可时，设备归属必须与“候车位到倒料位”的完整入口路径在同一原子申请中取得。只拿到倒料设备、却把入口路段留到下一步再申请，会让前车持有设备等待入口、后车持有入口等待设备，形成可复现的互锁。申请失败时不新增任何入口租约，车辆继续停在原候车位并保留自己的停车资源。

准入资格按倒料设备资源、入口路径资源和当前呼叫优先级共同排队。前方候车位中的车辆仍占用通往倒料位的必经路段时，后车不能越过它先取得设备。前车取得完整资源后进入倒料位，已确认通过且不再复用的路段仍按车体包络逐步释放，候车位资源在车体完整离开后释放。返箱、进入倒料位和倒料出口保护继续沿用同一套原子窗口规则。

验收需覆盖两个方向：前车持有候车位时，后车申请设备不得先成功；前方释放后，后车应在下一轮重新申请，并以一次事务取得设备与完整入口路径。该场景同时要求持续互锁为零、资源超容量为零、车体包络重叠为零，且等待记录能指出设备持有车辆和入口阻塞车辆。

# 回放速度

载入报告时间轴后可以选 1×、2×、4× 或 8×。默认 1×，每 125 毫秒前进一帧，倍速按比例缩短显示间隔。播放中选倍速从当前帧继续，暂停和拖动时间轴保留定位能力。时间轴显示原采样时间，导出视频仍使用原有导出节奏。正在运行的隔离实例使用其设备和调度时钟。

仿真倍率只缩放车辆、业务步骤和调度时钟。虚拟设备启动、正式后台连接、地图恢复、PLC 连接和报告收尾等操作系统或外部进程等待始终按墙钟计算。选择 8× 时，90 秒的启动观察窗口仍应实际保留 90 秒，不能缩短为 11.25 秒。

Robokit 状态与任务反馈、PLC 读取和连接状态的采样时间使用隔离实例的业务时钟。这样 4× 或 8× 下，新采样和地图激活门禁使用同一时间基准。未启用隔离倍率时使用系统时间。网络超时和通讯响应耗时仍按实际时间统计。

首次地图激活仅因车辆或 PLC 反馈暂未就绪而被后台拒绝时，在 30 秒墙钟窗口内重试同一切图记录。每次都通过正式地图激活门禁重新校验。遇到故障、位置异常、已有任务或其他门禁拒绝时立即停止启动并显示原原因。接口超时需要核对原请求结果。

一键开测在环境就绪后提交已核对的呼叫计划。提交时暂缺新鲜设备反馈的情况在 15 秒墙钟窗口内重试。已有场景、用户停止、计划校验失败或回执不明确时结束自动提交，保留现场状态供核对。
