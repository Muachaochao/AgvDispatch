# 充电优先仿真验收

本参考定义隔离实例中的充电优先配置、运行时行为和验收证据。适用于主工程 `ChargingService`、Robokit `1007/6005` 协议和虚拟充放电模型。

## 配置结构

工程方案的 `chargingPriorityTest` 为可选对象。未提供或 `enabled=false` 时沿用原仿真行为。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `enabled` | boolean | 必填；启用后至少配置一个充电位 |
| `startBatteryPercent` | number | `0 < critical < start < target <= 100` |
| `criticalBatteryPercent` | number | 严重低电量阈值 |
| `targetBatteryPercent` | number | 停止充电并驶离的目标电量 |
| `sites` | array | 1 至 32 个唯一充电位 |
| `sites[].id` | string | 唯一，字母数字及 `-`、`_` |
| `sites[].chargingSiteId` | string | 必须为已启用的 `ChargingPoint` |
| `sites[].exitSiteId` | string | 必须为已启用节点，且不同于充电点 |
| `sites[].resourceId` | string | 必须为容量 1 的 `ChargingBay`，并与充电点关联 |
| `sites[].allowedVehicleIds` | string[] | 只能包含方案车辆，不能为空 |

地图节点支持 `allowChargingWaiting` 三态属性：

| 值 | 语义 |
| --- | --- |
| `true` | 明确允许该节点同时承担倒料候车和充电排队安全等待。仍须满足可停车、不可穿行、独占容量 1 停车资源、完整载荷车身包络和实时路权条件。 |
| `false` | 明确禁止该节点用于充电排队安全等待。 |
| 缺省 | 保持旧方案兼容。独立 `WaitingPoint` 仍可按原规则选择，已配置为倒料候车位的节点不能兼作安全等桩位。 |

充电点、充电出口、工位取货点、倒料作业点、检修点和充电返回待机点始终不能作为安全等桩位。即使把 `WAIT-04`、`WAIT-05` 这类充电出口错误标记为 `allowChargingWaiting=true`，配置校验和运行时复核仍必须拒绝。

每辆虚拟车可使用现有车辆字段：

| 字段 | 含义 |
| --- | --- |
| `batteryPercent` | 初始电量，范围 0 至 100 |
| `travelCostPercentPerMeter` | 每行驶 1 米消耗的电量百分点 |
| `idleCostPercentPerHour` | 待机每小时消耗的电量百分点 |
| `chargingGainPercentPerHour` | 虚拟充电每小时增加的电量百分点，最大 1000 |

## 运行时行为

1. 车辆电量不高于启动阈值时停止接新单，即使暂时没有可用充电位。遥测新鲜且满足充电排队条件时，创建唯一 `CHARGE-*` 会话。
2. 当前业务、PLC 责任或路权未闭环时，会话保持 `WaitingForBusiness`。已发车的取箱步骤分段续行仍核对原任务、上一段命令、车辆状态和本段路权。新接单的电量和充电排队门禁仅用于接新业务。车端反馈正在充电时，发送前检查会拦截导航。
3. 可申请充电的车辆按当前电量升序、创建时间升序处理。当前电量更低者优先。
4. 每个充电位使用容量 1 的独占资源。充电点和退出点的完整路线在发送前持久化。车辆在充电点停稳后只保留充电位资源，来车、出口和返回道路全部释放，避免长时间充电堵住倒料进场线或等待区汇流路口。
5. 到达充电点并确认停稳后，只发送一次 `6005 status=true`。
6. `charging=true` 与正电流同时成立后才进入 `Charging`。只有继电器应答不能证明已经充电。
7. 达到目标电量或收到停止要求后，只发送一次 `6005 status=false`。
8. 停止状态、电流归零后，按普通交通重新申请出口路线；出口被占用时保持 `AwaitingStop` 并显示等待原因，不进入 `Hold`、不发送导航。实际位于退出点并完成退出导航后，才完成会话并释放资源。
9. 低电量、正在充电或存在未完成充电会话的车辆不接新业务。充电完成后按主工程候选规则恢复接单。
10. 任何身份、时效、电流或位置证据不明时进入 `Hold`，保留资源，禁止自动重发未知命令。

## 虚拟车端协议

| API | 端口 | 验收字段 |
| --- | --- | --- |
| `1007` | 每车状态端口 | `battery_level`、`charging`、`current`、`battery_temp`、`manual_charge`、`auto_charge` |
| `6005` | 每车独立其他 API 端口 | 请求 `{"status":boolean}`，响应 `{"ret_code":0}` |

隔离实例为每辆车分配唯一 `OtherApiPort`。五车共享同一虚拟 PLC，但每辆车保留独立状态、导航、电量和充电继电器端口。

## 验收项

| 编号 | 通过标准 |
| --- | --- |
| CP01 | 配置拒绝不存在的充电点、停用的退出点、非 `ChargingBay` 资源、容量不为 1 的资源、重复资源及未配置车辆 |
| CP02 | 初始电量不高于 25% 的车辆生成唯一充电会话 |
| CP03 | 22% 车辆先于 24% 车辆取得可用充电位 |
| CP04 | 第 1 步首段到位后触发低电量，原任务能通过续行发送检查并继续九步，业务责任闭环后才转充电 |
| CP05 | 车辆达到启动阈值后停止接新单，含充电位全占用；车端反馈正在充电时拦截续行导航 |
| CP06 | 每个充电资源在任意采样时刻不超过容量 1 |
| CP07 | 到达充电点后 `6005=true` 只发送一次 |
| CP08 | `charging=true` 与正电流同时出现后才显示正在充电 |
| CP09 | 达到 80% 后 `6005=false` 只发送一次 |
| CP10 | 停止后电流归零，车辆完成退出导航并实际离位 |
| CP11 | 实际离位后才释放充电资源和退出路线；充电期间除充电位外不持有其他道路资源 |
| CP12 | 充电会话最终为 `Completed`，全车电量曲线和阶段时间可追溯 |
| CP13 | 一轮十单全部完成九步，没有重复执行、资源超容量或车体包络重叠 |
| CP14 | 结束时没有残留路权、未闭合 PLC 周期或未完成充电会话 |
| CP15 | 报告记录地图身份、五车输入、阈值、充放电参数、`1007/6005` 证据和运行倍率 |

## 派单续航预估

隔离充电方案在每次全局匹配时，从候选车当前位置估算取箱、送箱、返箱、等待和完工后到桩的耗电。结果附在候选详情，包含当前电量、预计业务耗电、预计完工电量、预计到桩电量及参考桩。到桩使用遵守封路的参考路线，实际进桩仍须取得路权。倒料位的候车耗电使用仿真配置的估算时间。找不到完整参考路线或缺少电量参数时，显示无法估算。

`chargingPriorityTest.energyForecast` 支持 `Observe` 和 `Enforce`。旧方案以 `Observe` 计算并显示，保留现行派车。`Enforce` 排除缺少完整预估或扣除误差后低于到桩安全余量的组合，并用预计到桩电量计算候选的电量风险成本。正式后台未配置此实验时沿用现行匹配。

`minimumArrivalBatteryPercent` 默认 15%，`predictionErrorPercent` 默认 3 个百分点。两项独立于充电触发线。

两桩都占用时，已达到启动阈值的车辆仍显示充电排队。车辆原业务、PLC 和路权未闭环时继续原任务。车位只有在车辆实际离位并释放后才能重新分配。报告保留全局派车登记时的首次续航估算，历史回放显示采样中的实际剩余电量和充电反馈。

## 仿真边界

- 虚拟 `1007` 返回合成电量和电流，`6005` 只切换虚拟继电器，不验证真实桩握手、绝缘、急停或机械联锁。
- 加速耗电和充电参数只用于压缩测试时间，不可作为现场续航或充电能力结论。
- B07 的充电节点和资源可用于隔离调度验收，不代表现场对接姿态、车体净空和充电机地址已核定。
- 本验收通过后仍需在现场完成真实车辆、PLC、充电桩和授权联锁测试。
## 车队卡片实时充电数据

`GET /api/simulation/live` 可返回 `chargingSessions`。数组元素包含 `vehicleId`、`phase`、`message`、`phaseSince`，以及可用的 `site`、`targetBatteryPercent`、`battery`、`returnSiteId` 和 `shutdownVerified`。数据来自当前隔离实例的正式充电接口，后台按墙钟每 5 秒至多刷新一次，地图轮询可独立返回。字段缺失或为 `null` 表示暂无已确认会话快照，兼容旧控制器。历史已完成会话不参与实时标签。

## 等桩、续航复核与选桩时间

| 条件 | 调度规则与验收 |
| --- | --- |
| 所有可用桩被占 | `Charging:WaitingSiteIds` 默认为空。仅在业务和设备责任闭环后，从显式核定的等待位中选择可达点。等待位必须允许停车并绑定独占停车资源。倒料候车位只有 `allowChargingWaiting=true` 时才能兼作等桩位。充电进出口、工位取货点、倒料作业点和检修点始终排除。已有安全停点时就地等待。 |
| 驶往等桩位 | 先保存导航意图并取得进路及停车资源。确认原命令完成且实际停稳后释放来路，保持停车资源直至驶入充电位或完成经核验的人工处置。发送结果未知时保留资源。 |
| 预计选桩时间 | `Charging:EstimatedGainPercentPerMinute` 默认为 0，表示空桩时间未知。配置后用最新充电电量、目标电量估算剩余充电时间，并加上 `Charging:EstimatedDockExitSeconds`（默认 30 秒）。`Charging:EstimatedApproachWaitSeconds`（默认 0，表示未知）用于正在占用的进桩路权的估计。综合预计空桩、行驶与路权等待；实际派发依赖实时空桩和路权获取。 |
| 绕行或滚动续行 | 用最新电量、当前剩余路线及后续箱体循环估算到桩余量，写入该次决策证据。`Observe` 记录，`Enforce` 在安全复核点拦截余量明确不足的路线。启动充电阈值仍用于新接单。 |

验收时先配置 `WAIT-01` 至 `WAIT-03` 为可安全等桩，并保持 `WAIT-04`、`WAIT-05` 的 `allowChargingWaiting` 缺省或 `false`。再故意把 `WAIT-04` 标为 `true`，配置必须报错。正常配置下，双桩占满后的第三台低电量车只有在停车资源为空、完整载荷车身能放进边界且进路到手后才可移动；业务车和充电等桩车争用同一 `WAIT-01` 至 `WAIT-03` 时，独占停车资源容量始终不得超过 1。

双桩均充电时，核对第三车只在已核定等桩位可达且路权到手后移动。释放其中一桩后，核对第三车从实际位置进桩。注入障碍或持续占用下一段道路，核对路线复核使用最新电量，且原任务责任保留。

隔离方案可保存 `chargingPriorityTest.waitingSiteIds`（默认 `[]`）和 `estimatedApproachWaitSeconds`（默认 `0`，上限 `3600`）。空桩时间按占用车配置的虚拟充电速率计算，字段缺失的旧方案继续可加载。运行中可查看当前等待位、候选桩的空桩时间、交通等待时间和行驶时间，历史报告区分派单、续行和受阻改道时点。等待位没有核定或续航不足时，车辆保留在原位置并等待核对。
