# 充电优先仿真验收

本参考定义隔离实例中的充电优先配置、运行时行为和验收证据。适用于主工程 `ChargingService`、Robokit `1007/6005` 协议和虚拟充放电模型。

## 配置结构

工程方案的 `chargingPriorityTest` 为可选对象。未提供或 `enabled=false` 时沿用原仿真行为。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `enabled` | boolean | 必填；启用后至少配置一个充电位 |
| `startBatteryPercent` | number | `0 < critical < start < target <= 100` |
| `criticalBatteryPercent` | number | 严重低电量阈值 |
| `targetBatteryPercent` | number | 停止充电并驶离的目标电量 |
| `sites` | array | 1 至 32 个唯一充电位 |
| `sites[].id` | string | 唯一，字母数字及 `-`、`_` |
| `sites[].chargingSiteId` | string | 必须为已启用的 `ChargingPoint` |
| `sites[].exitSiteId` | string | 必须为已启用节点，且不同于充电点 |
| `sites[].resourceId` | string | 必须为容量 1 的 `ChargingBay`，并与充电点关联 |
| `sites[].allowedVehicleIds` | string[] | 只能包含方案车辆，不能为空 |

每辆虚拟车可使用现有车辆字段：

| 字段 | 含义 |
| --- | --- |
| `batteryPercent` | 初始电量，范围 0 至 100 |
| `travelCostPercentPerMeter` | 每行驶 1 米消耗的电量百分点 |
| `idleCostPercentPerHour` | 待机每小时消耗的电量百分点 |
| `chargingGainPercentPerHour` | 虚拟充电每小时增加的电量百分点，最大 1000 |

## 运行时行为

1. 车辆电量不高于启动阈值时停止接新单，即使暂时没有可用充电位。遥测新鲜且满足充电排队条件时，创建唯一 `CHARGE-*` 会话。
2. 当前业务、PLC 责任或路权未闭环时，会话保持 `WaitingForBusiness`。已发车的取箱步骤分段续行仍核对原任务、上一段命令、车辆状态和本段路权。新接单的电量和充电排队门禁仅用于接新业务。车端反馈正在充电时，发送前检查会拦截导航。
3. 可申请充电的车辆按当前电量升序、创建时间升序处理。当前电量更低者优先。
4. 每个充电位使用容量 1 的独占资源。充电点和退出点的完整路线在发送前持久化。车辆在充电点停稳后只保留充电位资源，来车、出口和返回道路全部释放，避免长时间充电堵住倒料进场线或等待区汇流路口。
5. 到达充电点并确认停稳后，只发送一次 `6005 status=true`。
6. `charging=true` 与正电流同时成立后才进入 `Charging`。只有继电器应答不能证明已经充电。
7. 达到目标电量或收到停止要求后，只发送一次 `6005 status=false`。
8. 停止状态、电流归零后，按普通交通重新申请出口路线；出口被占用时保持 `AwaitingStop` 并显示等待原因，不进入 `Hold`、不发送导航。实际位于退出点并完成退出导航后，才完成会话并释放资源。
9. 低电量、正在充电或存在未完成充电会话的车辆不接新业务。充电完成后按主工程候选规则恢复接单。
10. 任何身份、时效、电流或位置证据不明时进入 `Hold`，保留资源，禁止自动重发未知命令。

## 虚拟车端协议

| API | 端口 | 验收字段 |
| --- | --- | --- |
| `1007` | 每车状态端口 | `battery_level`、`charging`、`current`、`battery_temp`、`manual_charge`、`auto_charge` |
| `6005` | 每车独立其他 API 端口 | 请求 `{"status":boolean}`，响应 `{"ret_code":0}` |

隔离实例为每辆车分配唯一 `OtherApiPort`。五车共享同一虚拟 PLC，但每辆车保留独立状态、导航、电量和充电继电器端口。

## 验收项

| 编号 | 通过标准 |
| --- | --- |
| CP01 | 配置拒绝不存在的充电点、停用的退出点、非 `ChargingBay` 资源、容量不为 1 的资源、重复资源及未配置车辆 |
| CP02 | 初始电量不高于 25% 的车辆生成唯一充电会话 |
| CP03 | 22% 车辆先于 24% 车辆取得可用充电位 |
| CP04 | 第 1 步首段到位后触发低电量，原任务能通过续行发送检查并继续九步，业务责任闭环后才转充电 |
| CP05 | 车辆达到启动阈值后停止接新单，含充电位全占用；车端反馈正在充电时拦截续行导航 |
| CP06 | 每个充电资源在任意采样时刻不超过容量 1 |
| CP07 | 到达充电点后 `6005=true` 只发送一次 |
| CP08 | `charging=true` 与正电流同时出现后才显示正在充电 |
| CP09 | 达到 80% 后 `6005=false` 只发送一次 |
| CP10 | 停止后电流归零，车辆完成退出导航并实际离位 |
| CP11 | 实际离位后才释放充电资源和退出路线；充电期间除充电位外不持有其他道路资源 |
| CP12 | 充电会话最终为 `Completed`，全车电量曲线和阶段时间可追溯 |
| CP13 | 一轮十单全部完成九步，没有重复执行、资源超容量或车体包络重叠 |
| CP14 | 结束时没有残留路权、未闭合 PLC 周期或未完成充电会话 |
| CP15 | 报告记录地图身份、五车输入、阈值、充放电参数、`1007/6005` 证据和运行倍率 |

## 仿真边界

- 虚拟 `1007` 返回合成电量和电流，`6005` 只切换虚拟继电器，不验证真实桩握手、绝缘、急停或机械联锁。
- 加速耗电和充电参数只用于压缩测试时间，不可作为现场续航或充电能力结论。
- B07 的充电节点和资源可用于隔离调度验收，不代表现场对接姿态、车体净空和充电机地址已核定。
- 本验收通过后仍需在现场完成真实车辆、PLC、充电桩和授权联锁测试。
