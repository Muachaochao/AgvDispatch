# 测试充电优先

本指南用于在最新五车工程中验证低电量车辆先完成当前业务、按电量排队、前往充电位、建立充电电流、达到目标电量后退出并恢复接单。

## 适用场景

- 使用当前 B07 全厂地图和五辆虚拟 AGV。
- 使用隔离实例、虚拟 PLC、虚拟 Robokit 车端和回环端口。
- 验证充电调度、资源独占、业务与充电互斥、九步收尾，不替代真实充电桩或安全联锁验收。

## 前置条件

1. 停止准备修改的隔离实例，保留其运行记录。
2. 在「工程与地图」加载包含 305 个工位、5 个等待位和至少 1 个 `ChargingPoint` 的最新五车方案。
3. 确认每个待测充电点关联一个容量为 1 的 `ChargingBay`，并选择一个已启用的退出节点。
4. 确认虚拟车初始电量、耗电速率和充电增益属于测试参数。加速充电只用于缩短仿真时间。

## 配置方案

1. 在「工程与地图」打开「编辑配置」。
2. 在「充电优先实验」选择启用。
3. 设置启动、严重低电和退出三个阈值。默认分别为 25%、15% 和 80%。
4. 每个充电位选择地图上的充电点、独占资源和退出点，并勾选允许停靠的车辆。选择充电点后，独占资源会自动带出该点关联的 `ChargingBay`。
   - 退出点应是允许停车、且不在主通道唯一通行线上的位置，例如等待位。充完电的车会停在退出点等下一单。
   - B07 上 CHARGE-01 的默认出口 CAD2-J0631 是倒料机唯一进场点，车停在那里会挡住倒料作业。建议改用 WAIT-05。
   - CHARGE-02 的接驳边位于倒料机 1.13 m 净空内，规划不出路线，只能用于验证配置校验。
5. 逐车设置初始电量。建议至少设置一台略高于启动阈值、两台低于启动阈值和一台正常电量车辆，以同时观察业务结束转充电、最低电量优先、排队和正常接单。
6. 可提高测试车的 `chargingGainPercentPerHour`。该值只影响虚拟耗电模型，报告必须记录实际使用值。
7. 输入新方案名称并另存。修改后的方案应保留地图、PLC 点表、工位和倒料配置。

## 启动与观察

1. 在「场景与呼叫」选择刚保存的方案。
2. 点击「检查并预览」，确认地图摘要、五车起点、电量、充电位、允许车辆和阈值均与输入一致。
3. 开始隔离实例并确认虚拟设备、正式后台、地图恢复和现场初态四项检查通过。
4. 运行十单呼叫，期间分别观察：
   - 低电量车辆是否停止接新业务。
   - 正在执行的箱体循环是否先完成九步和 PLC 收尾。
   - 等待充电的车辆是否按电量和排队时间排序。
   - 同一 `ChargingBay` 是否始终只有一辆车。
   - 到达充电点后是否先出现 `6005 status=true`，随后电量上升。
   - 达到退出阈值后是否先出现 `6005 status=false`，电流归零并驶离后才释放资源。
5. 运行结束后下载报告和证据包，按[充电优先仿真验收](../reference/充电优先仿真验收.md)逐项核对。

在「任务与车队」查看车辆卡片。停在桩上且后端确认充电时，卡片显示「充电中」、充电位、目标电量和已确认电流。排队车辆显示「排队充电」及具体原因，例如没有到第二桩的可用路线。车辆仍在执行九步业务时，业务进度和下一目标继续显示，充电栏说明何时转充电。停充、离桩、返回待机点各有状态。完成后卡片恢复显示车辆的新任务。

在卡片上对照隔离后台的 `Charging`、`Queued` 和 `AwaitingStop`，确认标签分别显示「充电中」「排队充电」「等待离桩」或「确认已停充」。切换实例后核对旧充电位和等待原因已清空。

## 停止与复核

只有充电会话进入 `Completed`、车辆已驶离充电点、充电资源已释放且后续任务能够重新派车，才可把本轮充电优先测试判为通过。

若页面显示 `Hold`，保留原会话、道路和充电资源，按页面提示核对车辆位置、载荷、电流和设备状态。不要通过重复点击开始来绕过保持状态。
