# 从软件助手管理排策智演

本文说明如何通过「AGV 软件助手」统一查看和启停独立的排策智演前后端。

## 适用场景

需要确认排策智演是否已绑定到最新独立运行目录，或需要从日常运维界面完成启动、停止和打开操作时使用本指南。算法建模、地图导入和实验运行仍在排策智演自身页面完成。

## 前置条件

- 已发布「AGV 软件助手」。
- `发布包/最新版Web.json` 存在 `paiceSimulation` 配置。
- `paiceSimulation.directory` 指向当前独立应用目录，`startScript`、`stopScript` 和 `url` 指向同一套应用。

配置示例：

```json
{
  "paiceSimulation": {
    "directory": "..\\DispatchingSystem\\integrations\\PaiceSimulation",
    "startScript": "..\\DispatchingSystem\\tools\\Start-PaiceSimulation.ps1",
    "stopScript": "..\\DispatchingSystem\\tools\\Stop-PaiceSimulation.ps1",
    "url": "http://127.0.0.1:5270/"
  }
}
```

## 操作

1. 打开「AGV 软件助手 → 服务管理」。
2. 查看「排策智演」分组。前端对应 `5270`，后端对应 `5271/api/health`。
3. 点击“启动排策智演”。工具调用统一起动脚本；首次构建可能较慢，已有构建产物时只启动两个回环进程。
4. 点击“打开排策智演”进入 `http://127.0.0.1:5270/`。
5. 需要停止时点击“停止排策智演”。工具调用统一停止脚本，并同时停止前端与后端。

<!-- manual -->

启动完成后应看到：

- 前端状态显示 `已就绪 · 127.0.0.1:5270`
- 后端状态显示 `健康 · 127.0.0.1:5271`
- 页面标题为“排策智演 · AGV 调度仿真”

## 失败边界

- 端口 `5270` 或 `5271` 被非本应用进程占用时，启动脚本拒绝启动。
- `.runtime/processes.json` 仍记录存活进程时，软件助手拒绝重复启动。
- 记录中的 PID、启动时间或可执行路径变化时，软件助手拒绝自动清理并保留记录供核对。
- 记录中的进程全部退出时可清理失效记录，再调用统一起动脚本。
- 5199 是否运行不影响原生算法页面；只有“主工程调度”页签需要 5199。
- 如果后台日志出现 `ClassNotFoundException: com.agv.algorithm.sim.SimulationResult`，停止排策智演后运行 `pwsh -File tools/Start-PaiceSimulation.ps1 -Rebuild`。脚本从源码重新构建普通算法库和可执行后台包，并等待两个端口就绪。
