# 单车单工位业务仿真

本指南用于在排策智演中执行一次主工程九步业务。入口默认选择主工程调度。

<!-- manual -->
1. 在业务场景中选择保存的工程方案，点击“加载方案”。当前隔离实例须已停止。
2. 从方案车辆中选择一辆车，设置合法初始节点，选择一个已绑定 PLC 的 CNC 工位。
3. 点击“开始单次业务”。系统复制方案生成新的隔离实例，仅保留所选车辆，空载、速度倍率 1；地图、PLC 点表及设备绑定继承原方案。保存方案不被覆盖。
4. 后台就绪后发出一次满箱 PLC 呼叫，由主工程自动派车；不创建原生起终点任务集。旧方案的批量呼叫不会执行。
5. 在同页查看九步状态、导航命令、载箱反馈和 PLC 信号。数据过期必须显示，不能将历史反馈当作实时完成证据。
6. 只有实际任务、九步及业务报告闭环才可判定通过；导航到达或写输出成功不能单独作为通过依据。机构反馈仅按虚拟设备实际提供的字段展示，未提供的反馈标为未提供。

请求扩展（兼容原有仅 id 的方案选择/启动请求）：
`POST /api/dispatch/main/simulation/scheme-start`

```json
{"id":"保存方案编号","business":{"vehicleId":"AGV-01","initialSite":"WAIT-01","stationId":"CNC-001"}}
```

business 三项均必填，车辆与工位必须属于所选方案，初始点必须启用且通过原有连通性校验。业务模式不允许载箱起步，默认超时 7200 秒，只生成一个 atSeconds=0、vehicleId=null 的 dispatch-backlog 呼叫。运行中拒绝替换实例；用户须停止当前隔离环境后重新配置。

验收包括：原方案不变、仅一辆车、只呼叫所选工位一次、拒绝未知字段及失效绑定、页面默认主工程、既有原生算法仍可显式选择。随机呼叫及五车测试在本闭环验证后进行。

启动或停止状态仅读取控制器状态，后台运行后才读取任务详情，避免启动期间显示连接拒绝。批量任务与旧实验记录收在可展开的高级区域。

单条呼叫复用 PLC 呼叫执行器，验收完整业务及准入不超卖；仅两条及以上的积压计划要求观察到排队。单条呼叫不承担积压覆盖验收。

## 机构反馈与随机业务计划

虚拟车辆 mechanism 字段包含 operation、taskId、state（Idle/Executing/Completed/Interrupted）、upperLimit、lowerLimit、source=synthetic。上下位仅为合成终点反馈，不表示真实行程毫米值。动作未完成或取消时不得更新载箱、PLC箱体状态或成功终态；中断后上下位均未知。页面按新鲜度展示。

scheme-start 允许与 business 互斥的 plan 对象，字段 seed（0..2147483647）、count（1..500）、intervalSeconds（0..60）、stationIds（非空且属于方案的唯一 CNC 工位列表）。继承方案全部车辆及合法初始位置，统一空载、速度倍率1。固定种子按排序工位列表生成呼叫，首条在0秒、随后按固定间隔，每条 vehicleId=null。运行目录 business-call-plan.json 保存完整输入及调用时间表，供复现。使用正式PLC执行器，同工位周期未闭合时保持待发。持续业务计划不强制要求出现积压，但继续检查准入容量、九步、出区、资源释放及命令证据。旧 dispatch-backlog 压测保持积压覆盖要求。

运行中及刷新页面后显示当前实例计划的种子、总量、间隔和工位范围，并可下载完整计划 JSON。完整状态接口 businessPlan 来自本实例的 business-call-plan.json，没有计划时为 null。业务证据包本轮目录另存与 calls 一致的计划，避免仅保留随机后的呼叫而丢失输入参数。机构栏显示车辆最近一次反馈及对应机构指令编号，历史任务详情不将车辆新动作误称为该历史任务的完成证据。

### 页面场景配置与检查

打开「工程与地图」，在全厂地图上方查看点位检查结果。点击地图下方的异常明细可定位到该点。要查某台机床，打开「查工位与车辆起点」，选择 CNC 工位或点击地图上的工位。用「地图定位」也可以查找节点并查看原始坐标。倒料资源编号和同时执行上限分别显示，上限按任务单数计。用已有方案开测时，在「场景与呼叫」选择方案，逐车确认本轮起点，再用启动检查核对计划。

要改停车点，打开「编辑配置」，先选 CNC 工位，再从下拉框选停车点，或点「在地图上选新停车点」后在图上点一个已启用的工位节点。地图选点每次只替换当前工位的一个绑定，之后恢复查看。需要更换 PLC 点表时，在编辑区导入 CSV。输入 1 至 80 个字符的方案名称，点击「另存为新方案」。后台校验通过后可在「场景与呼叫」选择该方案。点击「取消编辑」丢弃未保存的改动。运行、启动或停止过程中暂停修改和保存。想核对 PLC 信号时，展开「查看 PLC 信号」，即可查看名称、地址和读写方向。

`scheme-select`接受可选`checkOnly: true`与`vehicleStarts: [{id, initialSite}]`。checkOnly默认false，为true时返回`preflight`、验证后的configuration与businessPlan，保持当前实例不变。vehicleStarts默认沿用保存方案，提供时必须完整覆盖方案车辆且ID唯一，节点必须有效并具有不同初始位置。旧请求保持兼容。`scheme-start`也接受vehicleStarts，并保留这些位置进入实际运行。checkOnly仅供scheme-select使用。

检查包含方案与地图绑定、工位与PLC点表、车辆初态及业务路线配置、当前发布程序与算法选项、呼叫计划。端口占用与历史设备残留在创建后的实际启动阶段检查，启动后继续验证车辆和PLC观测就绪。页面分别显示配置检查与环境启动状态，运行前检查通过不代表设备已连接。

前端加载方案与启动请求允许最多180秒，检查和开始期间禁用重复点击。检查失败显示服务端具体错误，开始请求超时后查询后台实例状态，显示是否已创建或正在准备，避免不明状态下重复提交。
