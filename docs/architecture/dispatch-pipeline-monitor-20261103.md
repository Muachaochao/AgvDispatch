# 六层调度详情监控

日常入口仍为 `http://127.0.0.1:5199/`。工程工具中的“六层调度监控”进入 `/#/dispatch-pipeline`；滚动派车优化页也可进入，并按层跳转。

本页用于核对当前条件与已有记录。原有滚动派车优化页继续负责推荐组合比对和策略配置。

## 查看顺序

1. 顶部核对 PLC 接单、自动创建、业务派车、命令发送和地图执行状态，确认当前是否会自动发车。
2. 在六层导航中选择需要查看的层，读取数量、检查项的实际值与预期值，以及阻止或等待说明。
3. 在明细中按工位、任务、车辆或资源查找对应记录，展开原始身份、时间、路线、命令及其他证据字段。相关入口可查看完整业务任务或现有交通页面。
4. 需要核对某一时刻时冻结观察，或选择本页面会话内最近一次观察。恢复实时后查看最新采集结果。

## 各层数据

| 层 | 可核对的记录 | 解释边界 |
| --- | --- | --- |
| PLC 呼叫队列 | 原任务、呼叫时间、优先级、PLC 应答状态及工位缓存条件 | 工位缓存满足条件不等于已持久化接单；原活动任务仍按既有规则去重 |
| 候选筛选 | 当前车辆遥测与最近优化周期的候选、排除依据、估算成本 | 当前遥测与上次匹配结果分别标明时间；没有计算时不显示已通过本轮筛选 |
| 滚动全局匹配 | 窗口、候选、推荐车辆、传统派车选择和实际登记结果 | 推荐、已登记命令与车辆执行是不同事实 |
| 交通路权 | 真实申请、资源容量、持有车辆与任务、原步骤及等待原因 | 等待不等于已授予；过期心跳不自动释放物理占用 |
| 安全复核 | 执行门禁、运行地图、最近实际复核结果和 PLC 缓存证据 | 读取监控页不主动执行绑定或安全操作；未复核、未知和过期不显示通过 |
| 执行与恢复 | 原任务步骤、Outbox 状态、发送尝试、下一次重试及厂家编号 | 未来重试仍属于原命令；历史已发送样本与当前未闭环命令分开说明 |

## 时间与数量

`capturedAt` 表示本次只读采集时间，`optimizationCapturedAt` 表示最近可用优化观察的时间，各层和证据有各自的观察时间。多源数据分别读取，不代表一个数据库事务内的全局原子快照。

未取得数据、未执行复核、停用、等待、阻止、过期均有明确文字状态。页面断连后保留最近成功读取的资料供查看，同时显示过期提示。未知值不替换为“正常”或零。

明细采用有上限的样本，显示总数、当前展示数和截断说明。单层样本总数可能同时包含不同类型的记录，不能将它解释成待派任务总数。完整记录仍通过现有任务与资源页面查询。

最近观察仅保留在当前页面会话中，最多 60 次；刷新或离开页面后不保留，不能替代持久化任务审计。导出的观察 JSON 是当次采集证据，不授予执行许可，也不自动触发现场动作。

## 实现边界

`GET /api/dispatch-pipeline` 经现有查看权限和 Named Pipe 返回 `DispatchPipelineInspectionSnapshot`。采集模块只读当前队列、步骤、命令、缓存、优化快照及路权资料，不调用申请/释放路权、车辆发送、Outbox 领取、握手绑定或 PLC 写入。

发布仍按原流程备份运行数据、校验完整发布包，并更新唯一 5199 根入口。监控界面升级不改变已有现场执行开关或影子比对策略。
