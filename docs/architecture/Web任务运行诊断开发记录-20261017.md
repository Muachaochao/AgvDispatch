# Web任务运行诊断开发记录

日期：2026-10-17。

## 已实现

- 保留九步和现场置复位顺序，增加统一的任务诊断字段。每步返回现有执行器完成依据、证据边界、当前观测阶段、原命令状态说明。
- PLC执行器与查询层共用TaskSignalPredicate：Good且BOOL有效才可以满足；未知/null不按0。沿用现有采集端质量判定，没有新增未经确认的时序门禁。
- TaskStepProgressRules统一描述当前五个PLC步骤条件，执行器记录与查询端使用同一定义。当前活动步骤显示实际条件；历史/未来步骤不使用当前PLC值重判。
- 条件记录包含规则编号、中文名称、期望/实际值、质量、采集时间、信号版本及解释。收尾行明确为复位目标，不假称新增的业务接收门禁。
- 执行器在条件值/质量变化时写StepConditionsObserved证据，不因轮询时间变化重复记录。重启或重新进入观察会产生新观察，不宣称捕获PLC扫描间的所有边沿。
- 事件时间线汇合持久化执行证据及任务/步骤/命令的数据库时间戳，按时间和身份稳定排序，最多返回最近100项并给出总数。与原取消/恢复/释放操作历史分开，HTTP详情关闭原操作历史仍可读取。
- 浏览器不接收任意原始证据JSON或设备身份基线；只返回限定字段及解释。坏JSON、非对象历史数据不能被当作成功证据。
- Web任务详情改为可选择九步的运行详情，包含条件表、原命令、资源和时间线。Ready步骤状态显示“待协调执行”，避免误认为全部条件就绪。
- 断线/诊断观察过期时取消“当前有效”含义；后台不提供新字段时明确提示，不构造示例轨迹。

## 尚未实现或未核定

观测阶段是后台根据已有状态/当前条件返回的诊断解释，并非新增的持久化握手状态机。条件变化证据持久化不等于PLC业务ACK。下一批需在电控契约定版后实现可靠保持/接收、Ready消费、本轮Done防残留、实际离站与资源交接、收尾基线门禁。

未新增PLC位，不改变Read/Write权限、写入时点、车端动作或任务放行条件。未启用现场写入/调度/Web提交，也未重启用户主服务。旧服务程序需要更新后才会提供完整诊断字段；仅更新浏览器不能取得新后台能力。
