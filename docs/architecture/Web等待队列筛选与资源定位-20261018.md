# Web等待队列筛选与资源定位

更新：2026-10-18。当前主工程使用快捷AGV Robokit TCP，本批为只读界面，不改变调度优先级、资源占用或设备开关。

## 使用顺序

1. 根发布包“启动最新版Web.cmd”打开本机软件，进入“调度大屏”。中央地图下方选“联动任务”，点击红色阻塞资源旁“定位 编号”。地图移到该资源边界并画白色定位框；原路线绿、持有资源橙、阻塞资源红的含义保持。
2. 点击“清除资源定位”移除定位框；“复位”回全图。普通后台刷新保留定位，不反复把相机拉回原位置。切图、切演示或断连/失效时清理旧定位。
3. 滚动到大屏下方“交通等待队列”。选择阻塞资源、输入最低优先级0—100（留空为全部），选择等待最长优先或任务优先级优先。改筛选自动从第一页查询，每页25条；上一页/下一页使用后台分页结果。
4. 每行显示任务、车辆、步骤、任务优先级、等待时长、阻塞资源与占用车、地图/版本和原因。点击任务进入原步骤详情；点击行内“定位 资源”定位当前图上的阻塞区域。
5. 查询默认每5秒刷新，亦可点“刷新等待队列”。观察超过7秒、后台断连或查询失败时不可按旧队列定位。新响应要匹配当前页面和地图上下文，旧响应不会覆盖新筛选。
6. 演示模式中，点击原有“开始/重置演练”可得到合成等待队列；资源筛选、优先级和排序在浏览器内演示，不请求后台等待或控制接口。模拟处置原占用后该示例不再等待，列表为空是预期。

## 怎样读数

- 等待时间使用后台本次观察的WaitingSeconds，不能从任务创建时间或请求更新时间推算，也不在浏览器自行补历史。已知起点显示分/秒，起点不明显示“已观察…（实际起点未知）”；未提供有效时间显示未知，时钟倒退/无效显示暂停计时。
- 优先级0是有效值，“未知”不是0。最低优先级筛选排除无法比较的未知优先级，不修改实际任务优先级。
- 等待总数、筛选命中、排序和分页来自原GetTrafficWaiting后台读事务，不用大屏生命周期截断的200条记录重新计数。它们仍是一次观察，不是设备原子快照。
- 资源筛选针对后台明确阻塞归属，不按道路交叉猜测。心跳过期不自动释放原占用，也不把车当作已经离开。
- 跨图/旧图记录可以在队列阅读，但定位要求查询响应、行、阻塞资源归属均为当前活动地图ID/版本，且响应内容摘要与当前图一致。
- 逻辑交通资源可能没有多边形边界。没有唯一、有限有效边界时不能定位，界面说明原因，不拿车辆或站点位置代替。不能定位不等于资源可以放行。

## 接口与边界

`POST /api/traffic/waiting`是只读查询，接受原TrafficWaitingQuery（阻塞资源、最低优先级、排序、页号、页大小），Web每页最多50，界面用25。优先级0—100，页号1—100000；无效请求拒绝，不透传任意Named Pipe操作。

接口沿原后台View权限，查询前后核对活动图ID、版本、内容摘要，切图则拒绝该观察。页面未新增控制权限、设备地址或协议字段。当前Web仍只监听本机；完整包默认现场控制/上传关闭。原生激光底图、点云和现场验收仍按既有范围。
