# 动态倒料候车位自动发现

## 问题

当前地图已经声明以下独立容量 1 资源：

- `LM35 / DUMPER-WAIT-LM35`
- `LM36 / DUMPER-WAIT-LM36`

但运行时任务参数只保留了 `LM35`。三车同时取箱后，AGV-02、AGV-03 的下一运输步骤都申请 `DUMPER-WAIT-LM35`；AGV-01 占用该位时，后两车只能在原取货点等待。调度器本身支持按任务选择多个空候车位并持久绑定，缺口在运行时没有采用地图已声明的第二个明确候车位。

## 本次优化

多车调度启动并加载活动地图后、任务执行器启动前，后台自动扫描地图中的额外倒料候车位。只接受同时满足以下条件的节点：

1. 已启用的 `WaitingPoint`；
2. 绑定容量为 1 的 `DUMPER-WAIT-*` 资源；
3. 一个候车资源只映射到一个节点，模糊或重复映射不采用；
4. 保持原配置的第一候车位不变，仅追加额外空位。

普通 WaitingPoint、待机点、容量大于 1 的资源以及无法唯一映射的节点不会自动加入。已绑定工程来源的冻结参数和单车间模式不改写。已有任务及其候车位绑定不会迁移或换位。

## 实际效果

调整后，三车可以同时向不同候车位行驶。示例：

- AGV-01 取得 `DUMPER-WAIT-LM35`；
- AGV-02 自动选择空闲的 `DUMPER-WAIT-LM36`；
- 两车进入 `LM39` 后，原候车位在车辆离位条件满足时立即释放，第三车继续前往空出的候车位；
- `DUMPER-AREA-001 / LM39` 仍为容量 1，真正倒料继续一车一车执行。

选位、路径资源和任务绑定在同一持久化流程中完成；重试只使用原任务已保存的候车位，不因前车释放而临时换位。

候车位提前释放采用独立条件：车辆通信与定位有效、无阻挡/急停/打开报警、已静止停在
`LM39` 核验范围、存在唯一有效车体包络，并且后续返程路径不会重新进入该候车位。满足后只删除
`DUMPER-WAIT-*` 租约；`DUMPER-AREA-001`、倒料设备归属和其他任务路权继续保留。

## 验证

- `FleetTestSmokeTest`：150 项通过；新增自动发现、明确资源过滤、模糊映射排除、运行时参数同步及幂等检查。
- `WaitingBaySmokeTest`：32 项通过；覆盖两任务选择不同空位、容量 1 竞争、重启保留绑定、命令重试不换位，以及离位后仅释放候车位而保留倒料资源。
- `MapSwitchSmokeTest`：93 项通过；确认独立地图加载顺序和地图切换恢复未受本轮修改影响。

本优化只改变调度选择，不替代真实道路碰撞验证、现场候车位占用核对或 PLC 许可。
