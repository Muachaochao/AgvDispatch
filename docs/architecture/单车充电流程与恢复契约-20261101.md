# 单车充电流程与恢复契约

这是后续后台集成的设计契约。当前 `tools/SingleCarCharging` 是可审计的分阶段工具；现有 Web/C# 通用 ChargingService 尚未接通本型号激光识别、插头对接、1001 双端心跳与 DO7 全流程。工具回归通过不等于下列整体状态机已实车验收。

## 状态与责任

| 状态 | 进入和完成依据 | 异常处置 |
| --- | --- | --- |
| 准备 | 按硬件 ID 核对车辆、型号、固件、实际地图 MD5、后台生效地图和原任务；保存本轮原待机点 | 存在活动/未知任务时只查询原记录 |
| 预约 | 后台原子预约容量 1 的充电桩、接近位与必要进退路权；资源有运行 ID、租约与占位反馈 | 超时不代表车已离开，不能自动释放实物占用 |
| 去程 | 基于实时位置和有向道路规划至接近位；每段有唯一任务 ID | 受阻先停车定位实际受影响边，更新封路后重算；查原链、定向取消、核实停止，再发新链 |
| 识别 | 本轮三次稳定激光反光板识别，保留目标和车辆世界坐标 | 不稳/不可见就停在本阶段，不放宽阈值、不套历史世界坐标 |
| 粗接近 | 使用本车型标定的反光板到插头接合偏移，世界/车体坐标转换后有界低速 goPath 与里程计控制 | 轨迹不可行或偏差大则退回可识别位置重新对正，不让差速车执行未核定的纯横移 |
| 插接 | 轴线已对正；按照本车已核定间隙执行一次有界轴向移动；有效机械/电气接合依据独立记录 | SDK 到点、地图坐标接近、路径容差不能代替接合反馈；保护阻挡时不自动关闭保护硬推 |
| 建立充电 | 新鲜 BMS 限值；双 TCP 握手自动模式成立；核对当前车仍停止、未手充，再单次开启 DO7 | 未知应答不重发 ON，执行可审计停止并进入核对 |
| 充电观察 | 心跳持续，双 charging、DO7 和正电流同时成立；默认最后连续区间至少 60 秒 | 每次使用本轮动态 BMS 上限，数据缺失/超时、新告警或保护触发停止；告警消失不算新增 |
| 停止核验 | 单次 DO7 OFF、持续桩停止心跳；至少两次车端关闭/停止充电与电流停止反馈，桩退出自动且电流停止 | 命令 ACK 不能放行退车。字段不明或相互矛盾进入收尾未确认，保留资源和现场状态 |
| 退桩 | 停止反馈闭合后，按本车标定退出包络、距离与速度作有界退离 | 不把历史三段距离盲重放，也不以关闭继电器应答代替拔离许可 |
| 返回 | 从实际退离位置规划回本轮原待机点，重新核对道路和占位 | 返程受阻也改道，不能只为去程处理障碍 |
| 完成 | 到原待机点、全链终态、车停止、停止充电、资源实物占位已清；写总结后释放资源 | 任一未闭合状态不报整轮成功 |

每个阶段在发送前持久化意图、运行 ID、车辆硬件 ID、地图身份、原/新任务链、请求哈希与当前阶段。发送结果未知、进程退出、网络断开或服务重启后先恢复查询；恢复连接不会补发移动或开启输出。取消必须针对已知原任务 ID，不使用无任务范围的批量取消。

## 参数归属

| 配置归属 | 参数 | 更新要求 |
| --- | --- | --- |
| 车辆 | 业务 ID、IP、硬件 ID、车型、运动学、尺寸及最大载荷包络 | IP 可配置，但硬件身份不匹配即拒绝；不同车型不共享盲偏移 |
| 地图 | 后台地图/版本/规范哈希、车端地图名/MD5、有向边及几何 | 全图核验，站点数或坐标一致不能替代道路一致 |
| 桩 | IP、20207/20204、协议/固件、插头类型、接合和停机反馈来源 | 通用刷板字段不映射为插头接合；厂家未核定字段标成未知 |
| 本车与本桩标定 | 反光板到对接轴变换、接近点、接合依据、末端距离上限、退出包络/距离 | 绑定硬件 ID + 地图 MD5 + 标定版本 + 证据；任一变更使旧标定失效 |
| 运行策略 | 速度、阶段超时、心跳、采样、数据最大空洞、正电流最短区间 | 以实际接收时间验收；默认值是软件策略，不是厂家精度或机械行程证明 |
| 实时 BMS | 允许最大充电电压/电流、当前电流、电压、温度、charging | 逐次更新；0、-1、缺失不是无限制，也不从另一辆车补参数 |

当前工具默认策略：识别三样本、20 mm/2°；粗接近 0.875 m、0.03 m/s、75 s；末端轴向范围 -0.30～0.15 m、默认 0.01 m/s、30 s、SDK 到点容差 0.001 m；末端避障距离不得低于工具默认 0.05 m。范围只约束请求，不证明本车全部范围都可安全执行。

会话默认心跳 1 s、采样 0.5 s、连续正电流至少 60 s、接收数据空洞/一次状态读取不超过 5 s、收尾核验 15 s。设备时钟允许与本机不同；存在来源时间戳时核对同源递增，不拿其绝对日期当当前日期。只收到新网络包仍不能证明未知传感器的采样年龄，记录这种限制。

## 工具结果分层

- 识别通过：只证明当前目标可稳定识别。
- `advance_completed`：SDK 有界路径到点且观察到车停止，不证明毫米级实测、机械接合或充电。
- `charging_interval_verified`：最后一段持续正电流观察通过。
- `shutdown.verified`：保守的多源停机反馈通过；桩 output.current 的字段含义待厂家核定，矛盾时必须保持未确认。
- `charging_test_passed`：本工具电气会话与停止反馈均通过；`full_docking_cycle_verified=false`，不能当整车自动返回闭环通过。

独立 detour 工具会读取后台新鲜地图、封路、启用车辆占位与车端导出，并执行发送前复核，但没有原子路权预约。仅用于现场隔离测试，不能据此开放多车同时争用充电桩。当前 AGV-03 的手工编排改道成功也不能标为 Web 自动改道验收。

## 实车回归次序

先分别验证稳定识别、保留保护的低速接合、连续充电、停止反馈和退离，再组合去回程；随后测试去程受阻、返程受阻、TCP 断开、ON/OFF 应答丢失、进程重启恢复及双车排队。成功标准包含“无人补推、没有阈值临时放宽、没有重发未知任务、停机反馈闭合”。这些物理与故障测试需要现场验证，离线单元测试不能替代。
