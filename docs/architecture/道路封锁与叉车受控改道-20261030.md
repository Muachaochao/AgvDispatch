# 道路封锁与叉车受控改道

日期：2026-10-30。依据当前主工程、用户本轮确认及已留存的 Robokit TCP 协议。本文承接《障碍受阻状态与原任务恢复完善-20261030》，区分已交付软件行为与待现场验证的车辆能力。

2026-11-09 补充：厂家 `3051` 原页确认支持 `source_id=SELF_POSITION`、`method=backward` 和限速。本文件描述 2026-10-30 批次的保守实现；道路中段自动退站已在《Robokit障碍恢复接口审计-20261109》中另行设计并接入隔离仿真，生产默认关闭。

## 交付行为

1. 短时受阻保留原任务，车端安全保护优先；不把受阻、取消应答或发送应答当作到点完成。
2. 总览增加“道路封锁与绕行”面板，操作员核对运行地图、版本、明确道路及方向后封锁。封锁记录持久保存，包含原因、来源、身份、时间与追加审计。清障后显式人工解封，不因计时结束自动解封。
3. 调度 Dijkstra 规划排除封锁，新任务及尚未规划的后续行驶步骤可走替代道路。已入 Outbox 的旧路线经过最终发送门禁，不能因为封锁发生得较晚而继续发出；本批不会偷偷改写已持久化的旧 Outbox 路径。
4. 叉车单次导航页增加受控改道，保留同一个测试 TaskId、原终点以及原/新厂家任务编号。默认模式继续通过两次明确操作分开“取消原导航”和“发送新导航”；仅显式追加 `--auto-navigation-detour` 的单车测试启动允许后台按同一安全状态机自动执行。普通业务的 PLC 握手、箱体和工位归属不由此入口接管。
5. 障碍移除但车端把原任务保留为 Suspended 时，单次导航页可对同一活动厂家任务发送一次官方 3002“继续当前导航”。发送前要求阻挡和52200已清、车辆静止、无外来任务、原路线未封锁；发送意图先持久化，结果不确定或后台重启后只查询原任务，不自动重发。

封锁是针对运行道路的调度限制，不等同于传感器已识别障碍种类。自动候选依据“车辆所在唯一厂家站点 + 原任务下一站”推断当前有向路段，并使用当前 4011 地图和运行图核对；不用可能短暂吸附到相邻边的 `nearestEdgeId` 直接决定封锁。车辆不在唯一站点或原路线不能唯一给出下一站时保持等待。

## 叉车 LM1 到 LM3 用例

2026-10-30 开发时只读核对的日常运行图为 AMB-01 叉车测试三站点图，包含 LM1、LM2、LM3 之间六条有向连接。测试地图和车端地图仍以操作当时读取结果为准。

- 初始直接线路可为 LM1→LM3。
- 操作员确认封锁 LM1→LM3 通道后，候选规划可变成 LM1→LM2→LM3，前提是这两段道路启用、方向合法且未被封锁。
- 如果叉车已停在 LM1—LM3 中段，LM1 只是历史起点，不能把它直接当作普通 `3066` 的 `source_id`。普通指定路径仍要求相邻站点；道路中段受控恢复改走独立的 `3051 SELF_POSITION` 低速倒走端口，不能把最近站点冒充当前位置，也不能跨空地接入 LM2。
- 仅在车辆定位、坐标及 CurrentStation 唯一匹配真实站点且停稳时，允许从该实际站点核验候选。站点匹配采用现有单次导航的 0.25 m 软件阈值；该阈值不是厂家安全停车距离，也不证明中途接入能力。

## 受控替换顺序

1. 当前测试持续受阻至少 5 秒（SingleNavigationTestOptions.DetourWaitSeconds 的项目默认值），基于连续新采样计时；采样断档重新观察。这不是厂家或行业标准超时。
2. 默认手动模式在总览明确封路后，再到单车导航页读取实际接入点并预览。自动测试模式则在连续受阻达到门槛后，以车辆实际站点和原任务下一站生成只读候选；预览阶段无取消、导航、PLC 写入或路权释放。
3. 规划适配器只读下载当前 4011 地图，检查地图名/MD5稳定，将导出坐标还原为 RobotWorld，核对本地启用子图的站点坐标和有向道路几何，并比对本次 1301 站点。不能只因两张地图都有 LM1 就复用业务地图。导入器的 Enabled=false 为离线保守展示状态，不用于推断车端道路开关；发送前另查逐段 1303。
4. 日常总览对 `RobotWorld` 米制运行图允许在线、Good 质量、路线位置 Normal 且当前站点属于该图的车辆直接叠加车位；项目业务地图绑定仍用于需要额外坐标核定的地图。车位显示只代表当前遥测，不放行任务或导航。
5. 人工确认结束原导航后，先持久化精确取消意图，再对原链一个明确活动厂家任务 ID 发送一次 3003。取消应答不能证明原任务已经结束；缺失历史或未知状态保持等待。
6. 只读查询原所有厂家 ID 的终态，核验地图、控制权、无外来活动任务、动作空闲、定位及实际起点，取得至少两次、间隔 500 ms 的停稳证据。严重报警、急停、充电或未知安全状态不放行。
7. 手动模式显示 Ready 后人工确认执行。自动模式只在原所有厂家任务都已终态且连续停稳证据成立后自动执行。两条路径都会重新检查全部条件，并对候选每一相邻站点查 1303 的两点直接路径。持有与封路操作串行的发送门禁，核对封锁 Revision、地图版本及指纹，先持久化新 ID 链与发送意图，再发送一次 3066 明确站点链。
8. 查询全部新厂家 ID；只有全链正常完成、车辆安全状态与原终点实际位置一致时才记录完成。部分接受、回执丢失或历史未知都不自动补发。

GET 状态查询不会发出取消或运动指令。未发送阶段后台重启进入 ReviewHold，保留原责任；原所有 ID 已终态且实际站点可核定后，可显式重新预览、重新确认候选，不能重复取消原链。已尝试发送后重启只核对新 ID，不重发。

## 自动测试模式

自动模式是单测车专用能力，必须同时满足：

1. 运行入口显式传入 `--navigation-test-vehicle AGV-xx --auto-navigation-detour`。
2. 后台收到 `NavigationTest:AutoDetourEnabled=true`，且仍处于业务执行、PLC 写入、派发、命令队列及握手全部关闭的独立测试模式。
3. 后台专用轮询每秒只查询该车一次，不依赖浏览器保持打开。
4. 连续受阻至少 10 秒后才进入规划；障碍提前消失、急停、Fatal、充电、控制权变化、地图身份变化、外来活动任务或车辆离开唯一站点均不发送取消。
5. 无可执行的不同候选路线时不取消原任务，状态记为 `Unavailable` 并继续只读查询。
6. 取消与发送仍沿用一次性意图审计。回执丢失、历史未知或部分新任务被接受时只查询已记录编号，禁止刷新候选绕过或重发运动。

LM47→LM46 现场用例中，直接道路为 `SMAP-PATH-79`，预期自动候选是 `LM47→LM48→LM45→LM46`，对应 `SMAP-PATH-83→SMAP-PATH-68→SMAP-PATH-85`。该结果已用当前运行图和当前车端 `ZM-AGVtest` 地图只读预览核对；实际车辆是否走完仍以新厂家任务终态和终点状态验收。

## 封路与交通边界

- 封锁绑定 MapId、VersionId、DefinitionHash 与明确方向，不能直接修改已发布地图。
- 3066 只携带站点对，当前没有已核定的 path_id 选择能力，因此同一站点对的平行路径保守一并封锁；双向封锁也包含反向站点对。
- 封锁重叠时，解除一条记录不会撤销另一条。无可达路线返回等待提示，不反复取消重发。
- 当前地图有封锁时，3051 自主选路不能保证避开中间封锁，因此新的普通 3051 测试会被拒绝；原已接受任务仍可只读查询。受控替换使用 3066。
- 2026-10-30 本批不启用自动倒车、强制释放路权、取消低优先级业务、生产 PLC 业务任务执行中自动改道，也未证明车端局部侧向绕障。2026-11-09 已在隔离仿真接入 `3051` 道路中段低速倒走并完成集成回归；生产环境仍默认关闭，待现场逐车型核验。

## 验证与现场验收

全部软件验证使用隔离数据库、环回 Robokit 模拟及临时 Web 端口，无现场运动命令。测试结果见本次交付说明；软件模拟不能替代车辆实际安全验收。

现场需分别验证短暂障碍自动恢复、持续受阻不假完成、LM1 附近可接入时经 LM2 受控改道、中段停车拒绝冒用 LM1、无路保持等待、封路变化旧候选失效、急停/Fatal 优先，以及原任务与新链编号及到点证据完整留存。测试期间使用厂家认可的障碍物和受控方法，不以人员突然进入车辆路径作为软件回归手段。

日常入口继续使用 http://127.0.0.1:5199/，数据库与通信设置承接发布包/运行数据/后台5199，工程方案承接发布包/运行数据/Web工程方案。升级不自动恢复单次导航发送许可，也不自动运行本用例。
