# PLC信号责任与新旧时序对照（待核定）

日期：2026-10-19。依据：用户本轮提供的16阶段旧表、当前13项点表、2026-10-18责任草案及当前持久化握手执行器。

本文件是下一版契约建议，不是当前程序已经实现的时序，不是现场验收结论。不修改地址、PLC程序、点表、软件执行器或任何写入开关。用户本轮旧表优先用于本次对照，代码只用于列出差异。

## 一、先看要改什么

用户旧表列了10个流程信号；加上排屑工位异常、排屑机到总控通信状态、倒料机异常，就是当前13项。13项是按一个排屑工位及其共享倒料设备描述，不是全厂一共13个物理位。

|事项|用户旧表|本次建议|是否涉及软件/PLC变更|
|---|---|---|---|
|写入责任|复位条件已有，但部分未写执行方|谁拥有信号，谁置位、保持、复位；对方通过自己的信号确认|需要核定双方责任|
|呼叫响应|保持到取箱后撤销|任务已持久化受理后应答；PLC撤销呼叫后，上位机撤销响应，独立完成呼叫握手|时序修改；任务执行进度另看任务状态，不再用呼叫响应长期代表|
|取箱通知|接收后清0，机制待确认|新增PLC取箱接收确认，完整闭合后才结束通知|新增1个PLC位|
|Ready|设备就绪与本次许可混用|保留为设备能力/可接入新任务状态，新增本车入站许可|新增1个PLC位；当前新执行器等待Ready回0的逻辑需改|
|倒料完成|允许离开时即撤销倒料位|倒料周期通知保持到真实离站已确认；Done不能作为实际离站证明|时序修改；当前新代码保守等到返回取货点，本建议不是现状|
|实际离站|缺专用通知及确认|新增上位机离站通知、PLC离站确认|新增1个上位机位、1个PLC位|
|放箱通知|接收后清0，机制待确认|新增PLC放箱接收确认|新增1个PLC位|

建议最小电平方案合计：原13项＋5个业务位＝18项逻辑信号。周期、会话、编号及质量字段另计；18项不等于完整的断电恢复协议。

## 二、13项责任表

约定：H＝上位机；P＝PLC。表内写入方同时负责置位和复位，其他方只读。所有“本轮确认”都须匹配设备及周期；尚无周期字段时只能先验证正常电平流程，不能声称已解决历史反馈与重启混淆。

|序号|现有信号/变量|唯一写入方|置位或有效条件（建议）|撤销或复位条件（建议）|完成含义及注意|
|---|---|---|---|---|---|
|1|满箱呼叫 FullBoxRequested|P|新一轮满料需求已锁存|P确认H已持久化受理本轮请求后清0|不是AGV已到达；本轮忙碌期间禁止重复重装同一呼叫|
|2|箱体检测 BoxPresent|P|实际检测到箱体|实际检测不到箱体|持续物理状态；不能当取箱/放箱通知Ack，也不能识别箱体身份|
|3|排屑工位异常 Faulted|P|工位故障条件成立|故障解除且PLC复位条件成立|H不能直接清故障状态；如需复位请求另订字段|
|4|通信状态 CommunicationOnline|P|排屑机与总控通信正常|该通信异常|不代替H与总控PLC连接质量或数据新鲜度|
|5|呼叫响应 FullBoxRequestAcknowledged|H|本轮任务/呼叫关联已持久化，并被去重受理|H看到本轮满箱呼叫=0后清0|仅表示任务已受理，不表示派车或取箱完成；此处与旧表不同|
|6|满箱拉走 FullBoxRemoved|H|本轮AGV取箱结果核实且BoxPresent=0|H看到匹配的FullBoxRemovedAck=1后清0|PLC锁存消费通知；Ack不代替物理取箱证据|
|7|空箱任务响应 EmptyBoxTaskAcknowledged|H|确认满箱取走，承担本轮返空箱责任|空箱物理放置核实、放箱通知闭合，且倒料周期已闭合后清0|业务责任保持位；超时、断连或取消请求不能直接清0|
|8|空箱放到位 EmptyBoxPlaced|H|本轮AGV放箱动作结果已核实，发送放箱通知|BoxPresent=1且匹配EmptyBoxPlacedAck=1后H清0|PLC接收与真实在位要分开核实|
|9|AGV等待位 AgvAtWaitingPosition|H|本车实际到等待点后发起入站请求|取得匹配EntryPermit=1并持久化消费记录后清0|建议界面名称改为“等待位入站请求”；不是持续物理在位状态|
|10|AGV倒料位 AgvAtDumpingPosition|H|本车实际到倒料点，旧Done低基线及本轮许可有效|实际离站核实后，匹配AgvExitedAck=1且Done=0时H清0|建议界面名改为“倒料周期到位/占用通知”；保持到周期退出，不等于持续物理在位|
|11|Ready DumperReady|P|设备具备接入新任务能力，由PLC逻辑计算|设备占用、故障等使能力不成立|能力状态；不以其下降沿作为握手消费确认，不要求为闭合而强制清0|
|12|允许离开 DumpingCompletedMayLeave|P|本轮倒料真实完成且允许车辆按路线退出|P接收并核实本轮实际离站通知后清0|Done/允许离开不是车已离开，也不是资源已释放|
|13|倒料设备异常 Faulted|P|倒料设备故障条件成立|故障消除且PLC复位条件满足|与第3项属于不同设备信号；有故障时暂停依赖它的新阶段|

本方案保留“空箱任务响应”作为返箱业务责任，不另把它当四相请求。物理检测、故障、通信状态、Ready也不统一按事件四相复位。

## 三、建议新增5个业务位

这些是拟议逻辑变量名，尚未分配实际地址。双向区按驱动实际写粒度隔离，不能仅凭不同DBX位就认定整字节读改写没有覆盖风险。

|新增项|拟议变量|写入方|何时置1|何时清0|能证明什么|
|---|---|---|---|---|---|
|取箱接收确认|FullBoxRemovedAck|P|收到本轮拉走通知，已校验并锁存一次业务接收|P看到FullBoxRemoved=0|PLC接收一次取箱通知，不代替AGV结果和箱体检测|
|空箱放置接收确认|EmptyBoxPlacedAck|P|收到本轮放箱通知并锁存业务接收|P看到EmptyBoxPlaced=0|PLC接收一次放箱通知；H仍独立检查BoxPresent|
|本车入站许可|EntryPermit|P|本轮等待请求已受理，倒料设备已为该周期保留，允许指定车辆进入|P看到AgvAtWaitingPosition=0|一次授予/消费的确认；撤销该位不取消已授予的设备保留|
|实际离站通知|AgvExited|H|独立核实本车已退出约定倒料区域，归属本轮车辆及任务|H看到AgvExitedAck=1、Done=0，并撤销自己的倒料周期通知后清0|H已核实离站；发了返程指令不满足此条件|
|实际离站确认|AgvExitedAck|P|已接收匹配周期的离站通知并完成约定的PLC核验|P看到AgvExited=0且AgvAtDumpingPosition=0|PLC已处理离站闭合；自身不代替实际车辆位置证据|

Ready与EntryPermit的分工：Ready可提前为1；申请获批后PLC保留该设备，按本建议的可接入新任务语义，Ready在设备已被保留时应为0；这一下降不承担握手确认含义。H只依赖匹配EntryPermit完成许可握手。许可位回0之后，PLC内部保留的设备归属仍要一直维持到本轮离站闭合；否则许可消费到真正入站之间存在第二辆车抢入的空档。

PLC对离站通知的核验至少应明确活动周期、倒料完成及设备联锁；若没有独立离站检测，AgvExitedAck只证明已接收并处理H通知，不能当作第二份物理离站证据。H仍须独立核实本车实际退出区域。

若PLC只能提供持续“Ready”，不能加EntryPermit，则必须另行明确车辆归属、许可锁存、撤回及排他策略；不能直接沿用本表声称已获得本车专属许可。

## 四、排屑工位时序（便于对照旧表）

符号：↑＝0→1；↓＝1→0；保持＝不因等待或超时自行变化。下列按H/P轮询观察拆开，跨行先后有意义，不是一个周期内任意同时写完。各信号必须属于同一设备与业务周期。

|阶段|满箱呼叫 P|箱体检测 P|呼叫响应 H|满箱拉走 H|取箱Ack P（新）|空箱责任 H|空箱放到位 H|放箱Ack P（新）|
|---|---|---|---|---|---|---|---|---|
|正常接料|0|1|0|0|0|0|0|0|
|PLC锁存满箱需求|↑|1|0|0|0|0|0|0|
|H持久化受理、应答|1|1|↑|0|0|0|0|0|
|P消费应答，撤销呼叫|↓|1|1|0|0|0|0|0|
|H看到呼叫撤销，闭合呼叫|0|1|↓|0|0|0|0|0|
|AGV前往取箱|0|1|0|0|0|0|0|0|
|取箱结果及无箱核实|0|↓|0|↑|0|↑|0|0|
|P接收取箱通知|0|0|0|1|↑|1|0|0|
|H看到匹配取箱Ack|0|0|0|↓|1|1|0|0|
|P看到通知撤销，闭合取箱握手|0|0|0|0|↓|1|0|0|
|运输、倒料、返回|0|0|0|0|0|1|0|0|
|放箱结果已核实，H发通知|0|0或1|0|0|0|1|↑|0|
|P接收放箱通知|0|按传感器|0|0|0|1|1|↑|
|H确认BoxPresent=1及匹配Ack|0|1|0|0|0|1|↓|1|
|P看到通知撤销，闭合放箱握手|0|1|0|0|0|1|0|↓|
|全部物理/业务闭合，H撤返箱责任|0|1|0|0|0|↓|0|0|
|本轮完成，允许重装下一次呼叫|0|1|0|0|0|0|0|0|

放箱阶段BoxPresent和Ack到达顺序不作假设，H需要两项都成立且匹配本轮，才能撤销放箱通知。PLC可以在Ack前核实传感器，但最终规则需双方确认。

“满箱呼叫”在本轮业务忙碌期间保持未重装：PLC需记住已受理周期，直至返箱业务闭合，再按新一轮满料条件发出新请求。呼叫响应早清零不能导致同一满料条件反复生成任务。PLC重启不能丢掉这个已受理事实后重新派同一轮。

## 五、倒料设备时序（替换旧表中歧义较大的部分）

R＝PLC按设备真实能力给出的Ready值；它不是握手Ack。故障及数据质量另作门禁。到位和离站都需车端任务归属及新鲜有效位置证据，区域退出判据尚需结合实际地图核定。

|阶段|等待位入站请求 H|倒料周期通知 H|Ready P|本车入站许可 P（新）|允许离开 P|离站通知 H（新）|离站Ack P（新）|
|---|---|---|---|---|---|---|---|
|初始、未占用|0|0|R|0|0|0|0|
|本车实际到等待点|↑|0|R|0|0|0|0|
|P核实可用并为本轮锁存设备保留|1|0|R|↑|0|0|0|
|H持久化本轮许可消费后撤销请求|↓|0|R|1|0|0|0|
|P撤销许可位，设备保留仍有效|0|0|R|↓|0|0|0|
|本车按有效许可进入并实际到倒料点|0|↑|R|0|0|0|0|
|倒料执行中|0|1|R|0|0|0|0|
|本轮倒料完成、允许离开|0|1|R|0|↑|0|0|
|车辆尚未实际退出区域|0|1|R|0|1|0|0|
|H核实实际离站，锁存离站通知|0|1|R|0|1|↑|0|
|P核实本轮离站并确认、撤Done|0|1|R|0|↓|1|↑|
|H看到匹配Ack及Done=0，撤销周期通知|0|↓|R|0|0|1|1|
|H再撤销自己的离站通知|0|0|R|0|0|↓|1|
|P看到两项撤销，闭合离站握手|0|0|R|0|0|0|↓|
|P按设备实际条件解除内部保留/重新就绪|0|0|R|0|0|0|0|

倒料设备可能在本轮空箱返回原工位之前完成离站闭合；排屑工位的返空箱责任仍继续保持。倒料设备可否服务下一辆车，须同时满足PLC设备保留闭合及调度路权的实际释放规则，不能只看Ready或离站Ack。

这里“倒料周期通知”是对原AgvAtDumpingPosition的建议语义。若现场坚持该变量表示实时在倒料位，必须保留实时语义并另增周期占用字段；不得沿用同一名字却悄悄改变PLC含义。等待位变量同理。

## 七、还要补哪些编号与异常字段

先将电平表定清，再核定下表。不要把5个新增位当作完整的故障恢复方案。

|字段组（逻辑建议）|双方责任与用途|待确定项|
|---|---|---|
|呼叫序号与受理回显|P生成CallSequence；H回显受理的序号，防止重复创建同一呼叫|工位作用域、PLC启动会话、掉电保持、溢出及重装|
|业务周期号与活动周期回显|H持久化分配BusinessCycleId；P接收/锁存并回显ActiveCycleId；通知和结果关联该周期|映射到原呼叫、任务、车辆及设备；各字段更新与提交次序|
|PLC启动会话标识|P产生BootSession，H检测会话变化|变化规则、保持区、重启后恢复流程；不能自动将清零解释为闭合|
|周期执行状态/错误码|P报告已接收、执行中、完成、异常，H报告自身请求/核对状态|双方各自拥有的字段，不共写一个State；无完成反馈时的处置依据|
|双向心跳和采样质量|各端维护自己的心跳；H检查质量和新鲜度|频率、最大陈旧时间、超时提示；心跳不当业务Ack|

字段名、数据类型和真实地址均未确认；不猜厂家字段，不把H本地ID直接写入现有PLC区域。多字段须约定先写参数、再提交/校验序号或等价一致性机制。重发同周期是否只返回状态、怎样保证PLC动作只执行一次，都要PLC侧实现并测试。

## 八、超时与重启处理表

|场景|规定的行为（建议）|禁止的误判|
|---|---|---|
|取箱/放箱Ack延迟|H保持原通知与周期，显示等待原因和时长；超时转待核对|不能只凭输出回读当PLC已接收|
|重复呼叫或重复通知|同周期同内容只处理一次并返回已记录状态；同周期不同内容拒绝|重连不能自动分配新号重发同一动作|
|旧Ack、旧Done残留|先核对周期/会话/基线；不匹配则阻止本轮推进|1不能自动等于本轮完成|
|Ready一直为1|它只代表能力；仍必须有匹配本车许可|不能等Ready必须下降，也不能据Ready放行多车|
|收到Done但车辆没走|保持倒料周期及必要占用，等待真实退出证据|不能在Done=1时当作离站|
|通信中断或数据过期|状态未知，停止依赖失效证据的新控制推进，保留责任及占用；已接受动作可能仍在执行|不能把未知当0，不能声称设备已停止|
|H写后丢响应/H重启|读原持久化意图，再核对P周期、Ack和设备状态；未知则待人工复核|不启动即清零，不无条件重发机械动作|
|P重启/所有位清零|检测新会话并核对实际设备、任务和保持区；不能直接闭合|0不能证明任务从未执行或已安全结束|
|取消任务|等待AGV取消结果及箱体/PLC/区域状态核实，按已达到阶段退出|取消请求不等于设备停止、箱体归位或返箱责任解除|

接收确认、设备动作、车辆到位、通知闭合分别配置超时；具体秒数待PLC扫描周期、轮询和现场动作时长确认，不在草案中随意定死。

## 九、下一步与核定顺序

1. PLC方先确认原13项写入归属、Ready语义、两个“在位”字段是否允许按本方案明确为握手通知。
2. 核定5个新增业务位与周期/会话字段；若采用命令字+状态字实现同等语义，另给字段布局，不把本表直接当地址分配表。
3. 软件与PLC模拟器实现同一新契约版本，验证正常闭环、确认延迟、重复请求、历史残留及各阶段重启；这批设计整理尚未执行新的模拟用例。
4. 双方完成时序核定后再改现场地址映射及程序，保留旧任务的版本隔离，避免在执行中切换语义。

本文件与2026-10-18草案一同保留：前者明确本次推荐路线，后者记录先前问题定位；任何现场落地以双方后续核定版本为准。
