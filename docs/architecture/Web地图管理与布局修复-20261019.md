# Web地图管理与布局修复

本批针对用户提供的三张截图：工程配置内容被设备栏遮挡、激活弹窗表单错位、地图发布入口分散。保留现有界面风格与后台控制门禁。

## 页面职责和使用方法

1. **工程编辑**：新建或导入导航地图，绑定业务节点与厂家站点；关联后台地图，点击“保存地图草稿”。本机方案保存与后台草稿保存是两个操作。
2. **地图管理**：地图卡片点击“发布草稿”，先核对后台已保存版本、点位/道路数量和坐标单位，勾选本次核对，再发布。弹窗不包括工程编辑尚未保存的内容。
3. **激活与安全切换**：发布后按原安全流程核对、激活及处理待放行阶段。激活依据、现场安全、车辆兼容要求仍需逐项满足；按钮灰色时不能绕过条件。结果不明使用原编号只读复核。
4. **调度大屏**：中央地图显示后台当前运行图，标明运行地图/未激活/断连。发布本身不替换大屏地图。演示地图继续明确标记合成数据，不代替真实运行图。
5. **工程配置**：读取后台配置后，在页面内容区向下滚动至动作、九步超时、厂家地图绑定及保存按钮；底部设备栏不遮盖内容。步骤显示中文名称。
6. **底部PLC状态卡片**：点击进入“联调检查”，查看通信与执行门禁；它不是设备启停按钮。

“发布草稿”生成后台地图版本，不是上传车辆。现场车辆上传仍未开放。没有地图、没有已发布版本、通信过期、待核对激活、权限或安全条件不足，均可能阻止后续操作；界面调整不代表这些条件已核定。

## 实现

- 工程配置页面独立滚动，内部段落/字段组不被flex压缩；操作标题和卡片按钮可换行，长地图编号断行。
- 弹窗直接子表单字段按整行排列；复选框恢复固定尺寸并对齐文字；底部操作可换行。
- 顶部“地图查看”改为“地图管理”；发布入口集中于地图卡片，工程编辑仅保留前往管理入口。
- 发布弹窗核对精确MapId、草稿VersionId、EditToken和后台来源；断连/切换来源使本次确认失效；请求失败后不自动重发。
- PublishMapRequest新增可选ExpectedEditToken；新版Web必须携带。旧客户端可省略。后台拒绝旧编辑令牌；事务中发布更新同时核对读取时的EditToken，避免校验后并发保存导致发布未经校验的内容。
- 当前活动地图、车辆控制、PLC写入、地图上传、恢复和安全切换门禁保持原控制范围。

## 复现与验证

- 前端：`npm.cmd run build`、`npm.cmd test`。
- 原生发布/切换：`dotnet run --project tools/MapSwitchSmokeTest -c Release`，包含旧编辑令牌拒绝发布，及合法令牌发布；旧客户端省略令牌的已有路径仍覆盖。
- 隔离界面夹具：`dotnet run --project tools/WebLayoutFixture -c Release -- <完整候选包绝对目录>`。夹具在新临时目录创建数据库、合成活动图和待发布草稿，启动自己的Service/WebHost、唯一管道及随机loopback端口，输出ready地址。写入输出root目录的`stop`文件退出；20分钟自动退出。仅停止夹具自身进程。
- 浏览器按步骤验证配置长表单、地图管理发布、激活弹窗、当前运行图和窄屏换行。通过本机HTTP读取与地图版本发布验证功能，不连接现场设备，不执行真实激活或放行动作。

证据保存在本地`artifacts/ui-layout-20261019`及本批commissioning目录；截图不入源码库。此前PLC责任草案属于独立工作，本批未修改PLC点表或握手执行器。
