# 滚动窗口安全点零占用交接

## 现场现象

B07 五车十单隔离仿真在 2026-11-21 18:30 场景中运行至 2152.53 秒时，AGV-01 与 AGV-03 在安全点同时零速等待 46 秒，独立检查判定为 `traffic-resource-cycle`。

数据库和逐帧观测确认这是一个真实短时资源环：

- AGV-03 停在 `SIM-SAFE-CAD2-E01832`，持有下一窗口还要复用的 `AUTO-CORRIDOR-C5312196CB270FFD59E2`，等待 AGV-01 释放倒料位旁的 `X-CAD2-J0652`。
- AGV-01 停在 `DUMPER-001`，持有 `X-CAD2-J0652`，等待 AGV-03 释放 `AUTO-CORRIDOR-C5312196CB270FFD59E2`。
- 两车都已在明确安全点停稳，原厂家窗口已完成，原业务任务和路权没有被删除。

## 原因

滚动窗口到站释放服务在申请下一窗口前，会先按完整车体包络释放已经离开的旧资源。原实现把所有“下一窗口将要复用”的资源列为受保护项，即使车辆已在安全点停稳、该资源又不在当前停点，也继续保留。

这条保护形成了不必要的先占后等：

1. AGV-03 尚未取得下一窗口，却继续持有 `AUTO-CORRIDOR-C531…`。
2. AGV-01 的下一窗口需要该资源，无法整组取得。
3. AGV-03 的下一窗口又需要 AGV-01 车体当前覆盖的 `X-CAD2-J0652`。
4. 双方都不能继续，直到 45 秒互锁门禁终止场景。

车辆在安全点等待下一窗口时没有开放导航命令。此时先释放已经由几何证据证明离开、且不在当前停点包络内的旧资源，不会产生行驶中的路权空窗。当前停点、仍被车体或定位不确定度覆盖的资源、未知且无法映射几何的资源继续保留。

## 修复契约

- 只在下述条件全部满足后进入窗口释放：原厂家窗口完成、原任务/步骤/命令/地图身份一致、车辆在线且定位新鲜、当前位置与安全点一致、线速度和角速度停稳。
- 下一窗口资源不再被无条件保护。仅当资源属于当前停点、车体或定位不确定度仍在资源边界内、生成走廊无法映射几何、或证据不完整时才保留。
- 释放和下一窗口申请保持分离事务。释放成功后若下一窗口仍不能整组申请，车辆留在安全点继续等待；不授予部分资源。
- 下一窗口取得全部资源后，再准备并发送原车下一窗口命令。失败时按原回滚规则处理，不伪造 PLC、完成状态或厂家命令。
- 不允许通过提高互锁阈值、删除租约、降低车体包络或忽略定位不确定性让测试通过。

## 验收

1. 合成到站回归覆盖“下一窗口复用资源已被车体完全离开”的情况，证明切窗前释放。
2. 当前停点资源继续保留，另一辆车路权不受影响。
3. 未知且无法建立几何关系的生成走廊继续保留，不能仅凭资源编号删除。
4. B07 五车十单使用相同地图、算法、车辆数、随机种子、呼叫顺序和车速重新运行。
5. 验收报告必须同时给出资源释放耗时、资源环数量、五车接单分布、十单九步完成率、碰撞与超容量检查、回放和页面证据。
