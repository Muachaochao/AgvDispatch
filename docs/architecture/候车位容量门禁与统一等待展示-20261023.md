# 候车位容量门禁与等待展示（2026-10-23）

本批补上单等待位容量门禁：多车模式下，等待节点必须绑定容量1、且不与倒料节点共用的独立交通资源，并使用当前28阶段持续保持路权契约。取得名额后才能准备送往等待位的命令，后车载箱停在原取箱点。正常两车闭环及取消／重启保留测试均通过。

## 实现与使用

`Dispatching.MaxConcurrentTasks > 1` 时，创建选项和第3步预览会检查等待位配置。手动创建、自动派车、首段绑定及送箱／入站发送前都执行核验。单车模式兼容原配置。未配置的多车旧图不会自动补资源、生成假站点或放行；应先在地图管理配置并按正常流程发布激活。

配置顺序：

1. 在工程地图中核对“业务等待节点”和它的实际厂家站点映射，保持两个编号各自明确。等待与倒料必须是两个不同节点。
2. 新建候车位交通资源，容量设为1，绑定到等待节点；不要直接共用倒料节点的资源。区域边界需结合实际车辆、箱体和现场测量核定，不能照抄模拟尺寸。
3. 保存、发布、激活并完成原地图／车端映射及恢复门禁。配置缺失时，创建页面会指出第3步的候车位问题。
4. 在大屏的交通等待队列查看资源、占用车辆、等待时长与原因。点击阻塞链可看占用步骤和最近事件；这里是只读核验，不授予放行、不解锁。

本轮合成示例为`R4_候车位`，绑定业务节点“等待”，厂家编号为测试值`TEST-LM107`。这不是现场编号建议。

### 当前释放策略

候车位按**原任务整单闭环**保持，取消、故障、断连、租约心跳过期和后台重启均不能自动腾出名额。第一车离开等待点后仍可能继续持有R4，直到取箱、倒料、返箱和PLC收尾完成。这是当前保守策略，会降低设备周转；尚未实现“实际离开等待位后提前释放”。

资源容量按不同任务计算，同一任务的送箱和入站步骤可各保留一条租约，不表示放进两辆车。界面暂时仍可能把同一车辆在两个步骤上的占用显示两次，完整步骤证据保留，后续应完善汇总展示。

### 等待类型

- 路权／候车位等待：持久化记录诊断路线、阻塞资源及占用方；没有取得候车容量时，不生成该送箱步骤的Outbox命令。
- 设备等待：倒料设备被其他任务持有时，正式等待记录写入`WaitingCategory=Equipment`、原占用任务及原因；不会只写到任务错误文字里。当前覆盖设备归属等待，不宣称覆盖所有PLC条件等待。
- 取得设备归属只结束这条等待展示，PLC许可、车端命令和实际入站继续各自核验；不额外申请或释放道路资源。

等待表新增可空类别列，原记录保留；旧空类别按原路权记录兼容，不按旧文案推测设备身份。已验证旧表升级时保留原请求与异常占用。阻塞链说明也改为按适用契约核验，明确“保存新命令不等于释放许可”。

## 测试1：并行两单争用单等待位

隔离实例：`artifacts/web-single-vehicle-20261023-waiting-bay`，唯一管道、独立SQLite、回环S7及两辆独立Robokit TCP模型，Web端口58624。通过正常HTTP导入／保存／发布／激活地图，绑定坐标和MD5、启动恢复核对后测试。没有修改任务终态或传送车辆位置。

| 项目 | 实际结果 |
| --- | --- |
| 建单 | 车01在02:00:51建单，车02在02:00:59建单；第二单提交时首车仍取箱，未采用前车进倒料后才建第二单的旧错峰方式 |
| 容量争用 | 先取得R4的任务送箱；另一车完成取箱后停在原工位，未生成其送等待位的Outbox命令 |

| 等待观察 | 正式等待接口返回R4及原占用任务；持有车到等待位后另观察至少8秒才恢复连接 |

## 测试2：保护名额后的取消与重启

正常两单完成后另建两单。车01在载箱入站原运输中取消；同一取消请求重放后，车端原任务确认Cancelled，业务停在CancellationReview。车02载箱停在取货B，不能进入等待位。

后台仅重启本实验拥有且实际映像路径一致的Service；设备模型继续。新恢复session未批准放行，4条原租约的身份、PLC电平及Outbox状态／次数不变。其中R4在同一任务两个步骤各持有一条，名额仍只属于一个任务。后续心跳过期界面仍显示占用，未让后车抢入。结束前另保存冻结数据库backup及最终等待／恢复／地图／后台快照，41份故障证据有SHA256清单；两车静止后仅停止本轮私有进程，用户原程序未动。

证据：`cancel-restart-20261023-020620`。两单**预期冻结，不是完成**，未代替现场核对清PLC或解锁。车01约(35.7,12)仍载箱，车02在测试厂家站点`TEST-LM102`载箱静止。截图`bay-waiting-queue.png`、`bay-blocking-chain.png`展示正式等待行、R4占用方、心跳过期仍保留及只读释放条件。

## 发布与后续

本批三端同版本、自带运行时发布：`发布包/联调候选_20261023-021217`，1170文件哈希及三组件版本一致。旧用户实例继续运行，固定入口因原进程仍在使用被脚本拒绝切换，未停止用户进程；现场通信与控制仍关闭。既有ImageSharp依赖和前端大分块告警未在本批扩大处理。界面实核后又收紧了只读释放条件说明，最终包含该文案；先前截图保留当时观察，不覆盖为新画面。

下一批优先统一任务卡片的“候车等待”显示与同车多步骤占用汇总，再补实际离开等待位的可靠证据与提前释放；在具备现场尺寸、路线、身份和PLC资料后再做受控实车验证。当前逻辑资源门禁不等于未配置几何冲突区域的自动避碰。
