# 五车200单持续回归

本轮采用305工位地图、5辆虚拟车、0.75 m/s限速、单倒料机。选择跨区域25工位，每工位重复8次，共200次呼叫。正式调度选择车辆；脚本只产生PLC呼叫，不直接插单、指定车辆或删除路权。

重复呼叫逐工位等待上次任务九步完成、倒料出区证据通过、PLC回到基线且稳定1.5秒。不同工位独立继续，不要求整批车辆都完成后再呼叫。200是计划总量，不是同时写同一PLC位200次，也不是要求5辆车各固定承担40单。

## 本轮修正

前轮24单在AGV-01和AGV-04形成持续互锁后失败，原实例及报告保留。定位到安全停点分割边继承了原边两端路口保护，后半段仍占用远端已通过路口。`add_safe_stops.py` 现在只移除明确在该半段包络之外的有界路口引用；共享道路和未知资源不变。生成地图的审计保存解除记录，车端运动、PLC、容量和独立碰撞检查没有放宽。

测试脚本新增 `--cycles`，生成可保存及重跑的明确呼叫计划；总数限制1至500。正式场景仍由既有逐工位闭环队列执行，`call-plan.json` 记录顺序和轮数。

## 观察重点

- 已完成车辆的物理占道仍然有效，释放业务路权不代表车体消失。
- 查明阻挡车、受阻车、实际资源持有者和释放交接。
- 每车不能同时拥有两个未完成业务任务；忙车排除。
- 发生互锁、碰撞或容量超限时必须保留失败证据，不能为了200/200关闭检测。
- 空闲车辆自动让位闭环尚未在本批实现；本次地图绑定修正不等于该问题全部解决。

本轮最长观察预算48小时，是整个200单场景的预算，不修改车辆障碍升级、原厂家任务终态或PLC超时。当前启动不等于200单已通过。
