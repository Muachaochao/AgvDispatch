# 仿真测试中心

操作说明见 [SimulationLab/README.md](../../tools/SimulationLab/README.md)，ProfControl 功能对标见 [仿真能力对标-ProfControl-20261104.md](仿真能力对标-ProfControl-20261104.md)。日常入口是 `http://127.0.0.1:5199/#/simulation-center`。

页面采用五段工作台：运行总览、环境与地图、场景编排、故障注入、恢复与报告。顶部固定显示仿真方式、实例、车辆数、执行任务、场景和采样状态，并根据当前阶段给出唯一下一步提示。该布局吸收 ProfControl 的模式提示、统一启停、实时状态条以及“对象列表 → 当前对象详情”的组织方式，避免把全部配置和运行控制同时平铺。

## 执行链

Vue仿真页面 → 同源WebHost `/api/simulation` → 专属令牌认证的回环Python控制器 → 独立正式Service/WebHost → 虚拟Robokit TCP车辆及共享S7 PLC。

正式任务创建、Outbox、持久化握手、地图绑定、交通资源和启动恢复逻辑继续运行。设备模型仅在收到命令后移动，通过P侧外部输入产生呼叫及设备反馈，不改写调度数据库、任务终态、H输出或路权来完成测试。

现场5199后端与仿真后端使用不同进程、管道、数据库、地图存储和设备端口。WebHost只代理显式配置的控制器，禁止任意URL转发。控制器校验 `artifacts/web-single-vehicle-*` 目录、回环设备、独立数据库及管道。父Web进程退出时，控制器通过已持有的Windows进程句柄识别退出并清理自己创建的子进程，不按名称或重用PID结束用户程序。

## B07 全厂五车场景

日常 Web 仿真和“排策智演”实验统一使用 `B07-1F·305CNC·现场双线终端修订`。Web 仿真的日常保存方案是“B07-1F·305工位·5车·200单·双行线·安全停点v3·0.75m/s”，入口为 `http://127.0.0.1:5199/#/simulation-center`。

B07 原始地图包含1112个节点、1887条有向道路、1641个资源和305个PLC工位。775个普通路径点显式标记禁止停车，337个业务或安全停点显式允许停车。排策智演删除4个不可往返死端节点及8条关联道路后，实验副本为1108个节点、1344条道路；完整来源定义、删除清单和源边映射保存在集成记录中。

大图常驻文字只保留“铝屑终端处理与倒料区”和“双充电位”。港口、排屑机、甩干机、铝屑箱等 CAD 参考点不绘制常驻红框和文字，具体数据仍保存在来源定义中。终端区去掉与上方产线重叠的红色边框，充电区边界向两个充电位外侧留出完整包络。

五车200单用于持续调度回归。原有20工位、20单任务集继续保留用于算法快速对比；它不能代表305工位全厂验收结果。

Web 页面进入时读取完整 `/api/simulation` 快照。运行期间每1.5秒优先读取轻量 `/api/simulation/live`，只在首次进入、人工强制刷新或满60秒时重新读取地图、点表、方案和历史等完整配置。单次请求未结束前不会启动下一轮，避免 B07 大点表反复传输造成车辆状态过期或请求重叠。

## 控制与场景

- 页面提供环境启停、快速沿用当前地图新建或导入 `.agvmap.json`，配置1–8辆虚拟车的编号、唯一Station起点和合成包络半径，指定两个呼叫工位取货点及等待、倒料、检修节点和资源边界。
- 当前PLC模型固定为两个逻辑呼叫工位和一个共享倒料设备；更多车辆只有在自定义地图拥有足够Station起点时才能参与，不自动形成更多PLC工位。
- 内置完整循环、同时呼叫、用户呼叫计划、断连重连、PLC延迟、PLC卡位恢复、后台重启和恢复续接场景。支持轮次、轮间隔和超时。
- 同时呼叫通过一个 `calls` 批次在同一扫描周期置位，核对设备返回原批次 `externalInput.sequence/accepted` 后才经正常HTTP建单。
- 自定义呼叫支持最多500条记录，每条有工位、相对时间和可选车辆。控制器按同时间批次调用设备；批次完成原任务且工位周期稳定闭合后才推进下一批，自动选车只从任务接口给出的可达且可用车辆中选取。
- `simulation-control.json` 是完整设备控制快照；控制器将页面补丁合并并严格校验后原子替换。设备反馈原应用序号。一次性丢响应不能被后续无关补丁重新武装。
- 场景中止停止后续编排，保留已经受理的原任务。停止环境保留设备历史；新建实例复制配置模板的程序、地图及点表，生成新端口、管道和数据路径，不复制数据库、设备历史或环境配置覆盖文件。
- ProfControl `.rpj`在前端只读转换：按Global.Scale缩放，转换StationView、LineView、BezierView、PolygonView中的直线/贝塞尔/圆弧路径、ControlAreaView和AgvView元数据。圆弧采用受限步数折线近似；圆、矩形、图片、信号发生器和未被路线引用的视觉对象进入未转换清单。
- 通用协议服务器支持TCP、UDP、HTTP和行/4字节长度分帧。规则只执行JSON匹配、文本/正则匹配、状态更新和响应模板，不执行任意程序代码。延迟、丢响应和断连仍是一次受控请求；服务器只监听127.0.0.1。
- 电梯/门/信号发生器作为独立可选模型运行。电梯只在门关闭后移动；故障会中止目标并按显式复位解除。信号时间轴只改变模型状态，不自动写入正式PLC或突破派车门禁。

## 与 ProfControl 仿真机制的对应

已核对 `D:\ChaoChao\ProfControl-auth-test` 中由授权测试流程产生的反编译材料及 `ProfControl.xml`。其可借鉴能力包括：

- `VirtualHelper` 将原设备通信端映射到回环UDP/HTTP虚拟端，并保留原协议脚本；本系统用同类边界将Robokit TCP和S7映射到明确回环端口。
- `AgvVirtual` 维护移动、原地旋转、停车、动作四类状态，按路线距离更新世界坐标、角度、站点和电量；本系统在此基础上继续通过正式Robokit 3066命令与1100查询驱动。
- `MotorVirtual` 提供速度到轮速的换算、加速度、减速、行驶距离和仿真倍率；本系统的车辆配置包含速度倍率、加速度、包络和动作时长。
- `BatteryVirtual` 支持容量、电压、待机/使用耗电和充电增益；本系统实现初始电量、待机/里程耗电、充电增益以及2–20点多段线性电压曲线，1100查询返回插值电压和充电状态。
- `SignalGeneratorVirtual`、`ElevatorVirtual`和门状态由独立设备模型实现即时控制及时间轴；当前正式PLC业务模型仍以两个呼叫工位和一个倒料设备为准。
- ProfControl的 `SimulatorModeEnum` 区分全虚拟和数字孪生，并统一显示仿真倍率、运行时长；本系统使用隔离虚拟设备和正式后台这一组合，页面已提供正式结果与虚拟来源标识。

这些ProfControl类型依赖其专有 `ProfControl.Items`、通信协议脚本、WPF视图、全局单例和地图对象，且反编译源码不能直接作为本项目源码复用。本次吸收的是状态、参数和验收边界，在当前Domain/Application/Connector边界内独立实现；没有复制第三方反编译代码或授权实现。

当前 `.rpj`是只读转换，不保存ProfControl项目；通用协议工具不是当前正式AGV连接器；电梯/门和信号发生器不自动参与正式任务路由。要改变正式业务契约，仍需按实际现场要求确认设备、地址、联锁和恢复条件。

## 判定与证据

报告检查原任务九步、物理出区证据、每任务四条唯一运输命令、原Outbox尝试和设备3066接收数量、PLC最终闭合及剩余路权。

独立观察器从设备坐标和只读数据库检查资源容量及合成车体包络。相邻采样使用线性相对运动计算最近距离；该检查不是完整连续碰撞物理引擎。最长阶段停留及超时用于暴露长期等待，不构成死锁自由、公平性或现场安全证明。

故障检查必须确认设备实际应用输入，不能以文件写入成功代替故障生效。重启场景验证原任务、命令及非空路权保持和恢复屏障：报告 `recoveryHold:true`、`completedBusinessCycle:false`、完成业务轮数0，不能解释为业务完成。

恢复面板把私有后台的会话、条目修订号、车辆摘要、PLC摘要、资源摘要和载荷摘要返回给操作者。每次恢复决策必须提供物料引用、原因及车辆位置、载荷归属、PLC周期三项显式确认。只有整个会话全部条目 verified 后允许调用放行接口。恢复续接场景只观察原任务，不创建替代任务。

每次运行保存参数、原任务身份、请求响应、观察、原命令、结果及哈希清单。历史报告与当前场景编号不同会显示历史标签。失败、中止和证据不足不映射为通过。

## 仿真暴露的规范地图摘要问题

干净基线后台中，运输快照使用数字枚举序列化生成地图摘要，而28阶段绑定及出区事务使用字符串枚举的 `EngineeringRuntimeIdentity.MapHash`。相同地图ID/版本产生不同摘要，使车辆实际返箱后，出区事务仍拒绝交接。

失败实验 `web-single-vehicle-sim-20261104-164614-d9beca` 保留了这一问题：原运输摘要以 `415584687C0F` 开头，握手摘要以 `49339F12CC5D` 开头；事务日志明确拒绝摘要不一致。没有修改其命令快照或数据库来伪装恢复。

运输快照生成处统一使用 `EngineeringRuntimeIdentity.MapHash`。回归断言要求快照与出区证据摘要完全相同，包含实际枚举字段。测试的独立任务使用不同车辆，避免车辆占用门禁使地图事务用例提前返回。

此修复进入源码及仿真后台模板。日常接入只替换Web进程，保留原现场Service；不能据此声称已经替换现场调度后台或迁移历史命令摘要。
