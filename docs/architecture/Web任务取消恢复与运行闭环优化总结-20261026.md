### 原运行续接边界

1. 仅管理员可申请，必须是当前 Hold、原运行 ID 及最新观察版本，填写至少 10 字现场依据并确认。
2. 后台继续检查执行配置、恢复门禁、车辆/PLC 新鲜度、原地图和参数版本。原任务工位、车辆身份不一致时拒绝。
3. 已有确定的业务任务或待机导航时，仅续接原身份；不重新创建、不重发原运动。
4. 原任务取消待确认、取消核对、故障、已取消或查询缺失时拒绝，先走任务处置流程。
5. 原发送意图没有回执时拒绝；未知结果不能当作未发送。
6. 无原任务的等待边界还须验证无活动任务、握手/占用闭合和停稳，再检查空载、动作及路线配置。
7. `StopRequested=true` 不会被续接清除。同编号重试返回原结果；同编号更改依据拒绝。续接依据及操作者随运行记录持久化。

### 出区优化的安全边界

本次没有降低两次新鲜外区观察、整车最大载荷包络、定位误差、安全裕量、原冻结路线、PLC 周期闭合或设备/路权归属要求。未来曲线与倒料资源的分离仍沿用原较保守的整体边界检查。细分算法仅减少当前位置与曲线判断的矩形误报，真实曲线附近和多段路线歧义仍拒绝交接。

## Web 操作顺序

1. 进入“业务任务”，查看常驻原运行和原任务，不必再打开创建框找 Hold。
2. 要停止接续时用“停止新增呼叫并收尾”。此操作不取消当前任务，不代表车辆急停。
3. 要取消原任务时打开任务详情，填写原因申请取消；查询原取消进度、厂家动作和原占用，不能以“已受理”代替车辆结束确认。
4. 进入“异常恢复”，读取当前批次，核对车辆位置、载荷、PLC 周期和原命令身份，提交条目决定，再请求放行。全场恢复影响需要单独确认。
5. 返回业务任务：需要继续原流程时填写依据并“核对后续接原运行”；需要结束时用“核对原运行并结束记录”。两者均由后台复核，不清空原记录绕过条件。
6. 监视模式允许受审核的取消/恢复，但不允许启动或续接业务执行。要实际续接，必须通过原日常启动器显式选择业务模式；单车导航也仍须独立显式启用。不能通过访问页面自动获得运动权限。
