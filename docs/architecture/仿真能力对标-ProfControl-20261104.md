## 实际运行结构

ProfControl 把仿真分为两种明确模式：

| 模式 | 含义 | 驱动方式 |
| --- | --- | --- |
| `Virtual` | 全虚拟仿真 | 调度对象、车辆和设备都由软件模型推动，模型接收内部路线和动作事件 |
| `DigitalTwin` | 具有真实通信的数字孪生 | 保留原设备通信与协议脚本，将端口映射到回环虚拟服务或虚拟客户端 |

全局启停入口调用当前网络和仓储网络内每个对象的 `StartSimulator()` / `StopSimulator()`，再统一释放 `VirtualHelper`。这说明仿真是对象生命周期的一部分，并非只看某个窗口按钮。

所有模型实现统一 `ISimulator.Init()` / `Dispose()` 生命周期。根接口只负责初始化，具体模型通过状态、事件、通信映射和定时任务持续运行。

## 虚拟通信

`VirtualHelper` 维护“原通信端点 → 虚拟端点”的映射：

- 原对象使用服务器时，创建新的回环 UDP 或 HTTP 服务器。
- 原对象使用客户端时，创建对应的回环虚拟客户端。
- 新服务器继承原对象的 `ProtocolScript`，因此同一套协议规则可继续处理请求。
- 端口从本机空闲端口动态分配，设备端点被替换为 `127.0.0.1`。
- 启停仿真时统一初始化和释放映射，避免协议服务器残留。

当前系统的等价边界是独立正式 Service/WebHost、虚拟 Robokit TCP 车辆、共享 S7 PLC 和通用回环协议服务器。区别是当前不会执行 ProfControl 的任意脚本宿主，而是使用受控声明式规则。

## 虚拟车辆模型

`AgvVirtual` 是车辆仿真的总协调器：

- 状态分为移动、原地旋转、停车、执行动作。
- 订阅车辆的获取新路线、进入路线段、路线结束、任务结束事件。
- 根据路线距离、路径几何和控制点计算当前坐标与切线方向。
- 区分真实时间参数和普通仿真倍率，处理启动、停止、方向切换和旋转准备时间。
- 支持载具/托盘旋转、动作持续时间、动作完成事件、到地标事件。
- 速度会受到下一段需要停车、曲线、载货状态和最大速度等因素影响。
- 世界坐标和屏幕像素坐标同时维护。
- 空载/运行状态持续计算电量消耗。
- 每轮把里程、速度、角度、电量、电压和位置反馈给车辆对象或数字孪生通信事件。

`MotorVirtual` 以约 25 ms 周期推进：

- 车辆速度换算为轮速，再结合轮径和系数换算回速度。
- 维护目标转速、当前转速、最大/最小转速、加速度、里程和状态。
- 状态包括停车、加速、减速、匀速行驶。
- 仿真倍率同时影响目标速度、加速度和距离推进。

`BatteryVirtual` 统一维护容量、电压、充电增益和关机耗电。ProfControl 原始实现使用最小/最大电压线性映射；当前系统扩展为 2–20 点分段线性曲线，并通过 1100 查询返回 `battery_voltage` 和 `charging`。

## 电梯、门与信号

电梯模型包含：

- 多楼层、楼层高度、上下行速度、当前楼层和目标楼层。
- 上升、下降、停梯、开门、关门、开门中、关门中、开门等待等状态。
- 到达楼层后自动开门，开门等待超时后自动关门。
- 开关门耗时和仿真倍率。
- 数字孪生模式下通过虚拟通信发送楼层、门和电梯状态。

门模型单独维护关闭、关闭中、打开、打开中以及可配置开关门时间。普通门和电梯每层门可以独立运行。

`SignalGeneratorVirtual` 按信号编号和动画帧运行：

- 每个信号包含多帧、上一帧延迟和触发电平。
- 模型按仿真倍率推进时间，并在状态变化时发送完整触发字典。
- `Virtual` 模式直接回写对象；`DigitalTwin` 模式通过通信事件发送。

当前系统的电梯、门和信号模型独立运行，尚不参与正式派车与安全联锁；这一点没有用 UI 功能名称掩盖。

## 动作时间轴

ProfControl 的动作编辑器使用多轨时间轴：

- 一个 `ActionDefineType` 包含多条 `TimelineType`。
- 每条时间轴由若干 `ActionItemType` 动作块组成。
- 动作块有名称、持续时间、空等待标记和可选模块路径。
- 运行时把动作块按顺序转换为开始时间，并持续查询当前活跃动作集合。
- 支持开始、暂停、停止、恢复初始状态、保存和三维动作绑定。
- 动作发生变化时通知当前执行动作和新增动作，供三维模型或车辆对象联动。

当前系统已有固定业务场景和最多 500 次的呼叫计划，可以覆盖正常闭环、并发呼叫、延迟和故障恢复；通用多轨条件时间轴仍属于后续扩展项。

## 仿真操作窗

`SimAgvWin` 是一个独立手动协议测试端，页面组织为：

1. 顶部选择通信方式和 AGV/系统端口，提供“查看协议”和“运行”按钮。
2. 第二行提供前进、后退、左/右漂移、左/右转六个方向控制。
3. 中央区域显示车辆或地图视图。
4. 底部连续显示当前坐标、角度、地标、电量和速度。

`SimAgv` 支持 JSON、字节流和 Modbus 三类测试载荷，会解析路线、生成状态上传数据并按路线段推进。它适合协议联调，但不能替代当前正式 Robokit 契约，因此当前系统没有把这种私有协议格式直接搬入正式连接器。

## 配置界面组织

反编译 XAML 反映出一致的后台工具布局：

- 左侧为主对象列表，支持新增、删除和选择。
- 右侧只显示当前对象详情，避免所有配置同时平铺。
- 顶部是当前工作流操作，底部是状态或保存。
- 时间轴使用左侧轨道名、顶部时间尺、中间可拖拽动作块、当前红色时间指针。
- 电梯配置采用“电梯列表 → 楼层列表 → 当前楼层详情”的层级结构。
- 信号发生器采用“信号源列表 → 信号序号/名称 → 每信号时序条”结构。

## 日常仿真步骤

1. 打开 `http://127.0.0.1:5199/#/simulation-center`，先在“运行总览”核对实例和“下一步”提示。
2. 首次更换地图时进入“环境与地图”，导入 `.agvmap.json` 或 `.rpj`，绑定两个呼叫工位、等待、倒料、检修节点和资源边界，并核对车辆画像。
3. 返回总览启动隔离仿真环境，等待车辆、PLC 和采样时间显示有效。
4. 进入“场景编排”，第一次选择“完整业务循环”、1 轮和 600 秒超时。
5. 场景运行中在总览查看地图和进度；需要验证异常时进入“故障注入”，按目标车辆或 PLC 单点操作。
6. 结束或中止后进入“恢复与报告”，先处理恢复屏障，再核对任务、命令、PLC、路权和文件证据。
7. 报告未知或证据不足时建立新干净实例复测，不沿用失败现场宣布通过。

- 通用多轨动作时间轴和三维动作绑定。
- 将电梯、门、信号直接接入正式派车资源锁和安全 PLC。
- ProfControl 的 WPF 单例、地图对象、脚本编译器和专有运行时。

这些能力需要结合当前项目实际设备、协议和安全边界单独设计，不能通过复制反编译类完成。
