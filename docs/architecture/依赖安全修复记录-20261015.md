在 Infrastructure 明确引用 System.Security.Cryptography.Pkcs 8.0.2，设定间接依赖的安全版本下限，未升级数据库驱动或改变连接配置。刷新解决方案锁文件，并重新还原 CAD 测试工具依赖；Infrastructure、Service 的当前框架与 win-x64 锁条目均解析到 8.0.2。

## 未完成：CAD 图像依赖

对 ACadSharp.Image 0.1.6 临时添加 ImageSharp 4.1.3、Drawing 3.1.3 引用，并实际执行合成 DXF 全图/局部渲染测试，不只检查编译。

发现：
1. 渲染器抛出 MissingMethodException：`Rgba32.op_Implicit(Color)`。现有 ACadSharp.Image 二进制与新 ImageSharp API 不兼容。
2. Drawing 3.1.3 的随包构建目标执行许可证校验。无许可证 Debug 提示警告，非 Debug 构建未设置 ContinueOnError；日志明确提示 Release 需要有效许可证。未提供或购买许可证，也未跳过校验。
3. 当前 NuGet 查询 ACadSharp.Image 最新仍为 0.1.6，不能仅升级父包解决。

已撤回本次两条临时 ImageSharp/Drawing 引用并重新还原锁文件。保留原 CAD 依赖链，不能声称 ImageSharp 漏洞已修复，也不能把这次失败试验视作新版 DWG 现场兼容验收。

需要用户选择下一条路线：取得适用的 SixLabors 许可证并适配/重编 CAD 渲染组件，或授权更换不依赖该许可证的渲染实现。两者都超出单纯补丁升级，不自动执行。
