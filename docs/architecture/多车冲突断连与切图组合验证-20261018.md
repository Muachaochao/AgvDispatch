# 多车连续冲突、断连与地图切换组合验证

本批沿用快捷AGV/Robokit TCP主工程，只使用独立Service、WebHost、唯一Named Pipe、随机本机端口和新建临时SQLite。不是实车或PLC协议验收；厂家地址、身份字段、上传和现场控制仍不启用。

## 场景顺序

1. 图一中A持有R1并等待B的R2；B持有R2并等待R1；C、D同时等R1。C的阻塞链应展开到A/B循环。
2. 显式模拟A业务收尾，调用原正常释放路径；B取得R1并继续持有R2。C、D通过各自数据库连接连续并发重试不得抢占。已打开的C详情刷新后占用者从A变B，旧循环消失。
3. B进入取消待确认，模拟租约心跳过期。占用和等待继续保留。先请求地图收尾，再调用原激活入口，必须被任务/资源门禁拒绝。
4. 停止测试自身Service，保持WebHost运行。旧详情关闭、队列清空、定位失效，明确断连，不进入演示。以同一私有库重启Service，原租约所有字段保留，重新打开后仍要求核对B的取消占用。
5. 延迟原图C的只读阻塞详情响应。明确模拟其余任务安全收尾，并调用原正常释放；这不是通过超时/重启释放。工作区异常测试后补齐有效草稿，再由原地图激活入口切换图二。图二与图一共享资源编号但位置不同。
6. 地图变化清空旧详情；放回迟到的图一响应不能复活详情或定位。图二E持有新R1、F等待；新详情仅显示E/F及图二。旧图请求返回409，旧任务历史不改成图二归属。激活维持AwaitingResume，未调用恢复派发。

## 本批发现并修复

原ActivateAsync提交活动指针、运行图和切换阶段后，再GetWorkspaceAsync构造返回。缺草稿或草稿数据损坏时，可能发生“已经激活，接口却报错”。现在在提交前构造完整返回工作区；缺失/损坏明确拒绝，原活动图和Draining阶段不变。成功路径返回已预构造的活动图摘要与发布版本，提交后不再为返回详情读取/解析工作区。

组合重启还暴露启动竞态：ExecutionRecoveryWorker在Host尚未就绪时进入周期巡检并占用控制门，后续MapTransferLedger启动初始化超时。现在仍在StartAsync同步建立恢复冻结，周期巡检等ApplicationStarted后执行；未就绪时停止可取消等待，冻结初始化失败仍使启动失败。启动时不解锁、不放行、不跳过持久化核验。

这些修复不改变任务、车辆、PLC、未闭环命令和物理资源门禁，不新增现场放行。数据库事务仍不代表物理设备状态原子。

## 可复现入口

在主工程目录运行（参数须指向已完整构建的本地发布包）：

```powershell
dotnet run --project tools/TrafficCombinationSmokeTest -- . --candidate-dir ../发布包/联调候选_20261018-141338
```

工具创建私有目录，并启动traffic-combination-browser-check.mjs。浏览器只发送waiting/blocking只读POST；故障注入通过该私有目录内的命令/回执文件驱动测试程序，不给Web增加测试控制接口。工具打印Evidence路径，保存原生检查、浏览器结果、进程日志及截图。

只有测试程序持有的私有进程会被停止。测试夹具直接写入的任务状态、历史时间和模拟完成不是现场可执行操作说明。正常业务仍须原取消/恢复流程及现场证据。

下一批适合补地图切换提交后、回执返回前的进程中断与只读结果复核；之后完善阻塞方变化提示及事件时间线。
