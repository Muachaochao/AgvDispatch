# 版本化任务模板与可视化任务链

日期：2026-11-04

## 目标与边界

本批借鉴 ProfControl 的模板化、参数绑定和可视化表达，不复制其反编译源码，也不改变现有调度执行内核。

- 任务模板保存版本、车辆能力、输入、输出和受控节点。
- 模板只允许编译为现有 `DurableNineStepV1` 持久化九步计划。
- 模板不执行 Roslyn、LINQ、反射或任意脚本，不能直接写 PLC、AGV、数据库或文件。
- 路权、发送前安全复核、Outbox、28阶段握手、取消与恢复仍由原执行器负责。

## 模板契约

每项模板包含：

- `version`：模板不可变版本；编号和版本相同但内容不同时拒绝覆盖。
- `engine`：当前仅接受 `DurableNineStepV1`。
- `inputs`：取货站点、候车站点列表、倒料站点、车辆池、车辆成员和可选前置任务。
- `outputs`：执行车辆、取货到点、取货确认、倒料确认、任务完成和失败原因。
- `nodes`：选择车辆及固定九步节点，每个节点保存输入、输出和现场条件。

旧工程中的模板没有节点字段时仍可读取；校验产生兼容提示，预览使用内置九步契约。提升模板版本并保存到模板库后，节点定义被固化。

固定节点顺序：

1. `SelectAgv`
2. `AcquireTraffic`
3. `GoToPickup`
4. `PickupFullBox`
5. `DeliverFullBoxToDumper`
6. `WaitForDumperReady`
7. `EnterDumpingPosition`
8. `DumpFullBox`
9. `ReturnEmptyBox`
10. `PlaceEmptyBox`
11. `CompletePlcHandshake`
12. `ReleaseTraffic`

## 模板库

全局模板库位于 WebHost 的 `Web:EngineeringStorePath/template-library`，独立于单个工程草稿。

| 操作 | API | 约束 |
| --- | --- | --- |
| 列出模板版本 | `GET /api/engineering/template-library` | 校验每个条目的 SHA256 |
| 保存版本 | `POST /api/engineering/template-library/save` | 同编号同版本内容不同则拒绝，需提升版本 |
| 导入模板包 | `POST /api/engineering/template-library/import` | 格式版本为1；带摘要时先校验 |
| 任务链预览 | `POST /api/engineering/task-preview` | 纯计算，不保存、不创任务、不发设备命令 |

Web 支持保存、复制到工程、模板文件导入导出和刷新模板库。复制只创建本地工作副本，不改变库中已保存版本。

## 可视化任务链

`工程配置中心 → 任务模板` 页面可选择工位和模板，展开：

- 工位取货点、倒料位、全部候车位和车辆池成员。
- 每步来源站点、目标站点、车辆动作和 PLC/路权条件。
- 节点输入和输出绑定。
- 模板版本、执行器及 SHA256。
- 当前静态阻塞原因。

预览通过只代表配置绑定通过，不代表地图坐标已现场核定、PLC已联调或任务可以下发。实际执行仍在创建和每一步发送前重新检查。

## 第二阶段：输入实例化、类型化输出、异常分支和失败策略

工程任务参数新增 `TaskTemplate` 快照，随任务参数修订一起保存。创建任务选项会携带同一模板的输入、输出、变量、节点、连接、异常分支和失败策略：

- `fromStation`、`waitingSite`、`toStation`、`vehiclePool`、`vehicleIds` 由工位、车辆池、候车位和倒料设备自动绑定。
- `vehicleId`、`arrival`、`pickConfirmed`、`waitingArrival`、`dumperReady`、`dumpingArrival`、`dumpConfirmed`、`returned`、`placeConfirmed`、`taskCompleted`、`error` 均为类型化变量。
- 每个变量只有一个生产节点；节点输入必须引用模板变量，禁止用自由文本拼接绕过类型检查。
- 白名单异常分支包括 `VehicleUnavailable`、`RouteUnavailable`、`PlcSignalNotReady`、`TrafficResourceOccupied` 和 `HandshakeFaulted`，只映射到现有安全处置。
- 每个节点保存失败策略、超时处置和超时秒数。机械/握手节点禁止自动重试；0 秒表示只关闭提示，不自动推进或重发。

任务创建页将模板输入展开为“工位取货点、候车位列表、倒料点、车辆池、车辆成员”，用户仍只选择工位、车辆和优先级；后台在锁内重新推导并校验模板输入，并把完整的 `TaskTemplateBinding` 固化到任务记录。

运行层已经读取任务自己的模板快照，而不是读取以后可能变化的当前工程参数：

- 每个就绪步骤携带 `TemplateNodeId`、失败策略、超时动作、超时阈值和真实开始时间。
- `HoldUntilCondition`/`NotifyAndHold` 只记录条件或超时并继续观察，不创建替代命令，也不重发未知机械动作。
- `Pause`、`ManualRecovery` 将就绪步骤原子置为 `ManualIntervention`，任务置为 `Faulted`，停止自动推进。
- `Terminate` 将就绪步骤置为 `Failed`，任务同样进入 `Faulted`，不伪造完成、取消或释放。
- 所有冻结路径都保留原步骤、Outbox、PLC周期、交通路权、设备和返箱责任；恢复仍走现有核对契约。
- 异常原因只映射到五个白名单触发器并写入执行证据：车辆不可用、路线不可用、PLC条件未满足、交通资源占用、握手异常。未知原因标为 `Unclassified`，不会执行自由脚本分支。
- 运行时再次强制关闭自动重试位；模板中的机械/握手节点即使被篡改也不能获得自动重放能力。

`SelectAgv` 派车窗口也已经读取任务自己的模板策略：无车辆、路线不可达、交通资源占用和超时分别映射到白名单条件；`Pause`、`ManualRecovery`、`Terminate` 会冻结首个就绪步骤和任务，保持原路权及现场责任。

模板新增两个受控交通适配节点：

- `AcquireTraffic` 位于 `SelectAgv` 与 `GoToPickup` 之间，只调用现有 `DispatchTrafficReservationService`/交通资源层，不发送独立车辆命令。
- `ReleaseTraffic` 位于 `CompletePlcHandshake` 之后，只释放现有生命周期已证明可释放的资源，不伪造设备交接、PLC周期或返箱责任。
- 两者不允许自动重试，也不能连接任意脚本或绕过原九步执行器。旧 10 节点模板读取时会自动迁移为包含这两个适配节点的 12 节点视图，已持久化的历史任务快照不重写。

任务创建支持最多 8 个前置任务编号：

- 前置任务编号随创建请求持久化，重复请求必须保持完全相同的前置集合。
- 前置任务缺失、取消、故障或进入取消核对时禁止创建，避免把失败前置误判为完成。
- 派车配置只在前置任务全部达到 `Completed` 后进入车辆选择；否则保留原任务并显示明确门禁。
- `SelectAgv` 超时从最后一个前置任务完成时间开始计算，不把等待前置任务的时间误算为派车超时。
- 任务详情返回每个前置任务的存在状态和业务阶段。

新增显式任务暂停/恢复：

- 只允许暂停当前为 `Ready` 的步骤；执行中、发送中、命令待确认或结果未知的动作必须走原取消/恢复核对，不能用暂停绕过。
- 暂停原子设置步骤为人工处理、任务为冻结，保留 Outbox、路权、设备和返程责任。
- 恢复只还原暂停前的原业务阶段，并将原步骤重新置为就绪，随后仍经过全部安全和 PLC 门禁。
- 暂停、恢复均有请求幂等、至少 10 字依据、权限检查和持久化运行事件。

实际九步状态机、28阶段PLC、Outbox、发送前安全复核、取消与恢复流程保持不变。动态自由分支、受控插件执行和自由拖线仍属于后续阶段；当前交通节点是受控适配表达，不是第二套资源占用机制。不能以模板元数据代替现场执行验证。

任务运行详情同时显示模板编号、版本、输入、输出、节点、类型化连接和异常分支快照，便于从运行记录回看该任务使用的配置契约。
