# Web 工程执行接入开发与隔离验证报告

日期：2026-10-27。承接工程配置中心，不依赖 WPF 配置入口。

## 本批已实现

1. Web 工程中心可读取后台已发布地图目录，复制所选准确版本的拓扑到工程草稿；目标可以尚未激活。保留当前工位编辑，重新校验引用，不改写地图或厂家曲线。
2. 新增“工程工具 → 工程执行接入”（`/#/engineering-runtime`）。按冻结工程版本预检地图编号、版本、坐标、厂家站点编号、道路方向/限速/资源容量及当前生效通信，再显示具体阻塞。
3. 从预检进入现有地图管理与安全切换，携带目标地图及版本提示，切换后返回重新预检。激活继续使用原申请核对、路权和恢复屏障；没有另建绕过入口。
4. 编译工程工位、单组倒料设备及车辆池为现有九步执行参数。保存仍经过真实 Service 的逐步配置检查、修订比较、活动任务检查和原申请幂等机制。四段车辆动作、九步超时沿用当前后台参数，应用前展示核对。
5. 实际派车、手动指定车辆及持续运行校验均遵守工位车辆池；不能只在模拟器中限制。新任务与派车同时绑定完整地图摘要和版本，变化后阻止新派发，原任务仍保留原责任。
6. 参数保存及重载保留工程来源、车辆池和原申请回执。旧客户端不能静默移除来源/白名单；同一冻结版本不能在参数页改写绑定。动作和超时仍可按原检查流程调整。
7. 应用前保存原申请编号；断连或应答未知时查询原回执，重试沿用原编号，不自动新建申请。确定拒绝显示“未应用”。

## Web 操作路径

1. 在地图编辑准备运行图，保存地图草稿并发布。
2. 工程配置中心 → 工程总览 → 读取已发布地图目录 → 选择地图 → 复制所选发布地图到工程草稿。
3. 维护工位、车辆池等绑定，保存工程草稿 → 统一校验 → 发布工程版本。
4. 所选版本接入执行器 → 预检工程、地图与当前通信。
5. 若目标地图未激活，进入地图管理，核对准确发布版本并完成原安全切换；返回重新预检。
6. 核对工位/车辆池及保留的四段动作，输入 `APPLY 工程版本编号`，应用参数。应用本身不启动任务。
7. 运行条件通过后，按现有业务入口启动任务。

受控现场部署需显式启用 WebHost `Web:EnableEngineeringRuntimeApply=true`。默认关闭；独立模拟实例始终禁止现场接口。本批未更新、重启或改变日常 5199，也未连接真车/现场 PLC。

## 当前边界与后续

- 真实执行器仍是一组倒料设备、共用四段动作；多倒料设备/不同模板工程明确拒绝应用。
- 工程 PLC 地址、候选包络、模拟耗时与待机策略不会自动覆盖现场有效配置。现场点表、写许可、地图核验和包络仍由实际执行器检查。
- 当前持续运行/循环测试仍保留原两工位及单车运行记录模型；本批没有宣称其已扩展为 300 工位、多车持续运行控制器。
- 五车峰值来自离散模拟，不是五车真实执行器并发验收。集成测试故意保持单并发，未降低当前 28 阶段多车候车保护要求。
- 后续应补多倒料实例、通用工位组持续运行、车辆池待机分配及真实 28 阶段五车并发回环测试，再进行受控现场验收。
