# 候车均衡、路权交接与下游准入（2026-11-11）

## 1. 五个候车位均衡

先求当前可执行的候车路线，再在最低路线成本15%以内按本地图版本历史使用次数均衡，随后按路线成本和站点名排序。超出成本带仍先考虑短路线，避免为了平均次数绕远。候车位独占资源和首窗口仍在同一事务申请；既有任务绑定不改位。没有可执行路线时逐位记录不可达或受占用资源原因。

历史次数并不代表空位。实际车辆包络、交通资源和地图方向仍可排除某个候车位。均衡规则不保证五辆车同时都有候车位：车队总数5，倒料时也有车辆正在设备位、返箱或取箱。

## 2. 实际路权交接

新增取得、实际释放事件，与资源增删在同一事务提交；心跳续租不重复写取得事件。覆盖通过路段释放、离开候车位、步骤/任务释放及人工核验释放。

阻塞详情按原地图和版本、资源ID精确匹配历史，显示前车取得、实际释放和后车取得。前任占用方不会混入当前等待链；不提供未经证据支持的预计释放时间。详情最多50条并标明截断；仿真任务侧栏取最近全场100条中的匹配事件，最多展开12条，不能代替完整日志。旧版本未记载的交接不会补造。

## 3. 下游准入票

新增后台配置 `DownstreamAdmission.Enabled`、`DownstreamAdmission.Capacity`。默认关闭，兼容现有工程；仿真方案“同时放行取箱任务数”设为0也关闭，可独立保存和切换，单倒料设备先对比容量3。

准入票由持久化的原任务车辆归属承担，与第一条取箱命令同一事务提交；两个独立连接并发抢票也不能超过上限。满额时新呼叫保留未取箱状态，不提前发命令。原任务已有票时继续推进。

当前采用保守的整单责任票：返空箱也占名额，直到原业务核验闭合；故障、取消待核对、取消核对继续持票。即使任务已完成或已取消，只要还有原路权仍持票，心跳过期不能腾名额。它不是候车位预留，也没有按倒料机预计空闲时间提前取箱的预测模型，容量3是否提高吞吐必须通过对比验证。

## 4. 满箱续接公平排队

保留既有有效优先级和等待时长策略，只在有效优先级相同时，先续接满箱运输/进倒料位，再按原呼叫时间排序；不能抢占已授予资源。修复正在执行的运输步骤等待后续窗口时未进入有效排队集合的问题。前序候选被其他资源阻塞时仍不能替它占住空闲资源。
