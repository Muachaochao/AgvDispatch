# 增量补丁生成与启动模式切换

本轮单车改道修复包含通信失败与取消未闭合的状态同步、中文状态标签，以及日常单车选择与多车入口参数叠加冲突。更新采用增量文件，不因小修复重新创建带完整 .NET 运行时的发布包。

## 生成与安装契约

1. 使用当前发布清单的 releaseId 编译变动程序，保持依赖图、运行时及程序集身份策略一致；构建暂存和补丁目录可以选空间充足的其他盘。
2. 将审核过的文件按安装相对路径放入暂存目录：`Service`、`Web/host`、`WPF`、`Web/wwwroot` 或 `Docs`。不复制开发配置、数据库、现场输入或完整运行时。构建输出的依赖描述必须与基线一致；依赖升级另行验证发布。
3. 执行 `tools/Build-CommissioningPatch.ps1 -BundleDirectory <基线> -PayloadDirectory <暂存> -OutputDirectory <新补丁目录> -PatchId <唯一编号>`。工具核对基线、文件白名单、共享程序集各副本一致性，仅收集发生变化的允许文件并生成完整的新发布清单。保留 baseReleaseId，以 appliedPatches 记录补丁。
4. 核对并通过原入口停止目标程序。无法读取进程归属时，安装器拒绝继续；不得据进程名结束未知服务。
5. 执行 `tools/Apply-CommissioningPatch.ps1 -PatchDirectory <补丁> -BundleDirectory <基线> -BackupDirectory <新备份目录>`。备份可放其他盘；目录不得与程序、运行数据、补丁互相包含。安装前完整校验，保存原变动文件及共享运行数据，逐文件写入并校验，写入失败回滚程序文件。安装本身不启动程序、放行恢复或重新发任务。
6. 执行 `tools/Verify-CommissioningBundle.ps1 -BundleDirectory <基线> -AllowRuntimeData`；日常入口仍使用 5199。确认部署后分别核对接口版本、地图、任务及页面；模拟验证不等于实车复测。

生成器只接受既有项目 DLL/PDB、前端静态资源及文档，不通过此路径引入新程序集、依赖描述、运行时或配置。新清单不得遗漏基线文件或补丁中的新文件，不接受路径别名重复及清单版本变化。

## 默认模式与明确选择

日常入口保留的单车选择使用 `--default-navigation-test-vehicle`，默认自动改道使用 `--default-auto-navigation-detour`。这些参数由入口生成工具填写，不从上次运行会话恢复权限。

若此次通过导航、叉车、PLC、业务或多车入口明确选择模式，则替换日常默认选择；不会叠加默认车辆或自动改道权限。默认启动所选的单车自动模式须与用户此前明确配置一致，启动不会产生新的导航任务。

更新后的 `Set-LatestWebRelease.ps1` 需与支持默认参数的 WebHost 同步使用，不可只更新根入口后沿用不识别默认参数的旧适配器。模式变化仍须先停止原模式，不会结束其他程序或隐式切换正在运行的实例。

## 状态责任

取消回执只证明接口应答。任务链仍有活动分段时保留“取消待核实”；查询失效、未知发送应答与重启时，同步顶层任务、改道与自动审计的“不确定”状态，保留原/新任务编号和候选链。连接恢复只查询同一原链，不重复取消或补发。

## 回归

覆盖单车原链、部分取消、回执未知、断连与恢复、重启不重发、默认模式被明确选择替换；补丁测试只使用隔离目录，覆盖基线哈希、差量文件、新静态资源、共享程序集缺失副本、配置拒绝、完整清单覆盖、未知进程拒绝、独立备份及重复安装拒绝。
