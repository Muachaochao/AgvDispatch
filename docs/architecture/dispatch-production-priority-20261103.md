# 全流程优先级路权与正式业务启用（2026-11-03）

本次将全局匹配的优先级规则延伸到业务后续运输、候车位分配及倒料设备竞争，同时提供明确的正式 PLC 呼叫启动模式。日常入口保持 `http://127.0.0.1:5199/`，沿用现有地图、任务、PLC 点表和通信配置。

## 统一规则

- 等待任务和业务后续步骤共同使用 `DispatchTaskPriority`，按原任务基础优先级、等待补偿和已配置时限紧迫度计算有效优先级；步骤切换或重启不重置呼叫时间。
- 已准备好的后续步骤先发布候选，再按有效优先级、原呼叫时间和任务编号申请整组资源。覆盖送箱、两个独立候车位、进倒料、返箱和倒料设备归属。
- 公共资源容量不足时保持原任务等待；已有有效路权不被高优先级任务抢占。前序若被另一满资源阻挡且不能整组取得路权，不空占其他可用资源。
- 充电和业务返回待机的系统动作使用普通优先级 0、首次持久请求时间排队，不能凭空优先于有效业务等待。FleetTest 的全组结束后串行返回属于隔离测试入口，正式生产模式不使用该执行器。
- 无法满足条件的未授予候选可撤销推荐资格，撤销不释放已授予路权，不删除原任务。推荐时效与物理路权生命周期分别处理。

## 正式业务开关

正式启动显式启用任务创建、PLC 自动接单、业务编排、步骤执行、28 阶段握手、Outbox 发送、PLC 写入及 AGV 命令许可。并发上限来自配置，不按车号或固定双车数量写死。

优化策略保存为 `Global`，正式模式要求该策略有效；切到 Shadow、Disabled 或配置读取失败时暂停新增派车，不自动退回旧派车算法。既有任务的执行和恢复仍沿用原任务、步骤及幂等命令编号。

根入口通过 `最新版Web.json` 承接显式授权的正式模式和并发，后续更新保留这两个配置。未授权的候选包默认不启用执行；单次导航许可不会从历史会话自动恢复。

## 验证与现场边界

自动检查使用隔离 SQLite、合成地图、假车辆网关和独立启动解析，不向现场车辆或 PLC 下发测试动作。具体结果和实际部署状态见本次运行证据；这些检查不替代真车验收。

启用执行开关不解除启动恢复、地图、车辆健康和 PLC 许可检查。开始本次工作时活动任务为 0，配置 PLC `127.0.0.1:10200` 拒绝连接，AGV-01 与 AGV-03 无本次启动后的有效遥测。此时不能声称已经能够发车，不能将未知 PLC 信号当作零，也不能跳过现场恢复核对。
