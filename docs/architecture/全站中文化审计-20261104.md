# Web 全站操作语义中文化审计

## 结果

- 调度首页、任务、任务详情、异常恢复、告警、地图、六层监控、滚动派车、充电、工程配置、工程执行、通信、PLC 联调、导航调试、规划、现场参数、联调检查和仿真中心均已检查。
- 主视图优先显示“当前步骤、当前在等什么、下一步怎么做、需要恢复或核对哪些信号”。
- PLC 点表字段、握手契约、厂家任务号、道路编号和模板变量不作为主标题；需要技术排查时可在对应条目的“原始字段 / 证据”中展开。
- 厂家英文告警和常见连接错误会转换为中文操作提示；原始告警文本在告警详情中可展开。

## 任务详情

- 首屏显示当前第几步和该步骤的中文业务名称。
- “下一步操作”区分等待、暂停、故障、人工处置和已完成。
- 没有满足的 PLC 条件、数据过期或待确认写入时，会列出中文信号名、工位、期望值、实际值和质量。
- 条件满足只代表当前观察满足，不冒充 PLC 业务接收、机械完成或放行。
- 九步、持久化握手、车辆命令、执行时间线保留证据边界；原始状态码和字段可展开。

## 异常恢复

1. 从最近任务选择原任务，或输入任务编号。
2. 核对车辆和实际位置。
3. 核对箱体、载荷和任务归属。
4. 核对本轮 PLC 周期。
5. 提交本条目核对。
6. 等待后台核验并放行全场恢复批次。

恢复页按工位分组显示需要核对的 PLC 信号，主视图使用中文含义；点表变量名放在条目下方作为原始证据。恢复结果未知时只允许刷新原批次，不允许直接重发。

## 保留的技术信息

以下信息仍可能在编辑或展开区域出现，它们是复现和排障所需的原始证据：

- PLC 变量名、DB 地址和数据质量枚举。
- Robokit、厂家任务编号、地图/版本号和资源编号。
- 握手契约版本、执行引擎、模板节点编号。
- 车辆厂家返回的原始告警文本和结构化证据。

这些值不再用于替代现场操作说明。
