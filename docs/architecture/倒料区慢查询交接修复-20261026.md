# 倒料区慢查询交接修复

适用契约：`plc-28-stage-v2`。不改变28阶段信号责任、出区门槛或原任务的恢复要求。

## 故障机制

原执行器在检查车端地图和原返程任务之前保留两帧定位，查询之后只刷新第二帧。地图检查允许耗时15秒，而定位证据的常用最大年龄为3秒。查询较慢时，第一帧已经过期；即使车辆一直正常上报，最终评估也可能反复失败，停在 `ReleaseDumper`。

此前评估失败直接返回空结果，没有记录具体原因。第8步尚未进入放箱握手，任务详情却套用了放箱通知/箱体检测的通用说明，容易被误解为需要手工给PLC信号。

这解释了一个确定可复现的缺陷，不证明每一次现场停顿都由同一原因造成。旧记录缺少当次拒绝原因时，不能用后来发生的断线或缓存急停倒推最初原因。

## 修复行为

- 查询结束后重新读取车辆定位。如果原定位对已经过期，在原任务查询的有效期内等待两次独立的新鲜定位；不延长数据最大年龄，不重复使用过期首帧。
- 定位停更、质量不合格、置信度不足、阻塞/急停、时间倒退、地图变化、原任务不匹配，仍保持设备和区域占用。
- 采集失败只更新原检查点同一阶段的等待原因，不清除未知写入，不推进完成阶段，不发送额外动作。相同原因不重复保存。
- 最终释放仍由原事务核对冻结返程、出区包络、原设备归属和最新PLC退出闭合值，并原子保存 `ExitHandoverComplete` 和本任务资源释放记录。
- 第8步显示原返程交接阶段及实际等待原因，尚未进入放箱通知时不再提示用户补放到位信号。时间线的拒绝原因标明是记录时观察，不能当作当前放行证据。

## 验证边界

使用隔离SQLite数据库、模拟车辆缓存、模拟PLC和查询接口验证。覆盖慢查询期间持续采集、定位停更、低置信度、地图变化、PLC闭合反弹，以及同车重复任务的交接与收尾。代码测试不替代现场连续多轮验收；不得通过手工改完成状态或删占用来制造通过结果。

- `Handshake28IntegrationSmokeTest`：98项通过，包括3.4秒地图查询期间每500毫秒采集、查询后定位停更、置信度降至0.85、查询期间换图，以及同一车辆A/B交替三轮共六次九步任务闭合。
- `DumperExitSmokeTest`：139项通过；`HandshakeRuntimeSmokeTest`：39项通过。
- `TaskCenterSmokeTest`：完整通过，包括实际交接阶段、未知写入、完成交接后的放箱提示及历史原因边界。
- 服务编译通过；仅有现有ImageSharp依赖漏洞告警，本次未调整该依赖。

日常实例仍为5199。部署前按项目约定备份现有数据，保留未完成原任务与检查点；重启后的现场恢复核对独立生效，不自动启动循环。
