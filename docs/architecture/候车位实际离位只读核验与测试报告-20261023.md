# 候车位实际离位只读核验与测试报告-20261023

## 这一批实现了什么

在任务详情第5步“进入倒料位”增加“候车位实际离位 · 只读证据”。由正式WebHost通过唯一Named Pipe调用Service，再从数据库原入站命令、发送时路线快照及原租约构造上下文。浏览器只提交原步骤/资源编号及当前地图摘要，不能提交坐标、包络或自行批准离位。

该功能只评估证据，不发车、不改PLC、不删租约，不生成释放凭据。即使结论通过，ResourcesReleased与ReleaseAuthorized仍固定false，继续按整单闭环保持候车位。既有逐段释放/提交开关没有启用。

## 如何使用

1. 打开大屏任务卡片或任务列表“详情”。
2. 选择第5步“进入倒料位”，在“候车位实际离位”区域选择原持有的候车资源。
3. 点击“只读核验实际离位”。选中普通倒料资源会被后台拒绝，不会把普通资源猜成候车位。
4. 结果分为“资料不足或当前条件不可核验”“离位证据未满足 · 占用保持”“离位证据通过 · 未释放”。通过时可展开核对本次涉及的全部候车原租约。
5. 结果过期、切换步骤/资源/地图、后台断连或任务取消后需重新核验。页面合成演练不会生成权威证据。

当前生产注册中没有核定的IAuthoritativeTrafficProgressReader和ITrafficGeometryProfileProvider。原运输、恢复及地图门禁合格后会明确提示缺资料；门禁关闭或原步骤不符则先说明该条件。不能把“按钮已接好”当作已具备实车自动离位确认。

## 核验条件

| 类别 | 当前检查 | 不通过时 |
| --- | --- | --- |
| 原运输 | 必须原EnterDumpingPosition步骤正在执行，原任务/车辆/厂家任务/命令唯一一致，原命令Sent且有发送时路线快照 | 不重新规划代替，不用送至等待位或返程冒充 |
| 地图/配置 | 等待与倒料配置唯一映射，不同节点；原路线由等待至倒料；候车资源容量1，独立于倒料资源；地图ID/版本/快照保持一致 | 占用保持 |
| 全部候车归属 | 核对该资源全部租约；可保留同一任务已完成送箱步骤与当前入站步骤各一行；归属与原步骤完整、未过期 | 不能只删一行当作放行 |
| 后续资源 | 原入站步骤完整持有倒料节点绑定资源；资源有有效边界和地图定义；原租约身份及有效期完整 | 不能仅凭离位坐标交接 |
| 两帧来源 | 已注册权威源，原命令/路线/车/地图/坐标系一致，同控制器会话且相邻序号；时间、进度不倒退，至少间隔0.2秒，两帧在5秒内 | 断连、缺帧、旧/未来样本均不通过 |
| 全车离位 | 已核定报告参考点、包含最大载荷的车体圆包络；置信度至少0.9；定位误差界不大于0.25m，取核定界与实时值中较大者；额外安全余量0.15m | 仅中心出区、贴边或任一帧覆盖边界不通过 |
| 路线进度 | 两帧通过候车资源最后一次使用，路线连续/方向有效，不提前释放未来重入区域 | 保守等待；可能晚于实际离位才合格 |
| 采集中变化 | 门禁外读取设备；随后门禁内复核任务、命令、配置、地图实例及全部候车租约身份/取得时刻，核定资料修订/有效期复核 | 取消、切图、租约重建/删除或后续资源丢失使结果失效 |

这些是应用层证据契约，不声称Robokit已有同名字段。控制器会话、相邻采样序号、原任务进度、车体与定位误差的取得方式仍需现场核定。圆包络是保守模型；两帧检查也不证明采样间任意轨迹都已被观测，更不等于全场几何避碰。
