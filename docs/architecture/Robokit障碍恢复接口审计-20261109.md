# Robokit 障碍恢复接口审计（2026-11-09）

## 结论

厂家 Robokit 文档确实包含从当前位姿继续运动、倒退、短距离平动、转动、脚本路径和指定任务取消能力。此前“厂家不能从道路中间处理”的说法不准确；准确结论是：

1. 当前正式恢复状态机只实现了“车辆位于可信命名站点后发送替代 3066”。
2. 道路中段尚未实现“取消原导航、低速退回后方安全站点、停稳后再续接原业务”的自动闭环。
3. `3051` 从 `SELF_POSITION` 导航可以处理道路中段，但厂家原页明确警告它不能直接用于多车调度场景，因为可能出现速度不连续和不跟随路径。因此只能在冻结该车后续业务、隔离相关道路并完成停稳、定位、载荷、PLC、路权和车辆包络核验后，作为单车受控恢复接口使用。

## 推荐的恢复闭环

### 第一阶段：现在的正常自动改道

1. 车辆先上报 `Blocked=true` 或 `52200`。
2. 连续受阻阈值到达后，仅搜索从可信命名站点出发的明确替代路径。
3. 冻结受阻方向、保留原业务任务、载荷、PLC 责任和路权。
4. 精确取消挡路原 3066 链。
5. 原链全部终态、车辆连续停稳、位置可信后，发送一条逐段替代 3066。
6. 每条业务步骤最多形成一条有效替代命令；结果未知只查询、不重发。

### 第二阶段：道路中段自动退回安全站

该阶段需要新增正式状态机，不得把当前位置直接冒充已有站点：

1. 原车持续受阻，`TargetStation` 和 `SourceStation` 唯一对应地图中的一条实际路段。
2. 选择后方最近、可停车、可重新规划的命名站点作为 `SafetyPointTarget`。
3. 冻结后续派车和相关道路，保持原业务任务、载荷和 PLC 责任。
4. 精确取消原 3066 链，等待全链终态、车端队列清空和连续停稳。
5. 再核验通信、定位、急停、报警、载荷、PLC、原任务身份、交通路权和车辆包络。
6. 只发送一次 `3051 source_id=SELF_POSITION` 到 `SafetyPointTarget`，使用 `method=backward`、低速和受限加速度。
7. 用新恢复任务编号查询 1110；结果未知时只查询，不重发。
8. 车辆到达安全站、停稳且定位与站点唯一匹配后，再规划去原目的站的替代 3066。
9. 到安全站本身不完成原业务步骤，也不释放载荷、PLC 责任或路权。

`3051` 是厂家提供的后备能力，但原页对调度场景有明确风险提示。生产环境默认应关闭该自动步骤；只有在隔离仿真通过、现场完成低速参数和道路条件确认后，才允许逐车型启用。

## 仍需现场确认

- 当前车型是否支持 `3051` 的 `source_id=SELF_POSITION` 与 `method=backward` 组合。
- 当前固件是否保留 3051 的 `task_id` 并通过 1110 返回稳定状态。
- `max_speed`、`max_acc` 的实际下限以及车端是否严格采纳。
- 倒走经过弯道、窄道和道岔时的速度与路径跟随表现。
- 后方安全站点的停车精度、车体扫掠包络和最大允许倒走距离。
- 3051 执行过程中再次受阻、取消或通信中断时的车端行为。
- 3051 完成后的 `current_station`、`last_station` 和实时坐标一致性。

这些项目不能用本机回环仿真替代现场签字确认。
