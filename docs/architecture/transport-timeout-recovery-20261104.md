# 运输任务超时恢复状态（2026-11-04）

本文记录正式业务运输超时的第一批落地实现。适用取箱、送满箱、进入倒料位和返空箱四个 Robokit 运输步骤；不改变车端安全控制、PLC 契约、原任务编号或交通资源归属。

## 已实现

- `SeerAgvGateway` 保留 Robokit 原始状态码。状态 `7` 不再只显示为普通失败，`AgvTransportTaskStatus.VendorStatusCode` 可明确区分导航超时与其他失败。
- `DispatchTaskOrchestrator` 在正式业务执行中遇到状态 `7` 时，将原执行步骤交给 `TransportTimeoutRecoveryService`，不再只写一条普通故障。
- 超时任务立即退出 `Executing`：
  - 原业务步骤改为 `ManualIntervention`；
  - 原业务任务进入 `Faulted` 并保留原Task、Step、VendorTask编号；
  - 不取消车辆任务、不补发导航、不释放路权、不推进PLC或箱体步骤。
- 恢复服务持久化 `TransportTimeoutRecoveryCaptured` 证据，包含原始状态、原路线、当前站点、候选路线和地图身份。
- 诊断结果分为：
  - 等待障碍清除；
  - 安全故障保持；
  - 必须移动到可信安全站点；
  - 人工处置；
  - 已形成只读受控改道候选。
- 若车辆仍处于阻挡/避障状态，只保留任务并等待，不生成发送动作。
- 若定位失效、通信过期、急停或严重报警，优先进入安全保持。
- 若车辆不在原路线可信站点、地图不唯一或原路链缺失，必须人工移动到安全位置，禁止把最近站点或历史起点冒名为当前起点。
- 若能从实际可信站点推断当前受阻边并找到替代路线，恢复页面显示正式候选；现场人员核对车辆位置、载荷归属和PLC条件后，可正式发送一次替代3066任务链。
- 替代导航发送前再次核验原厂家任务全部超时终态、车辆连续停稳、实际站点、运行地图身份、新路线资源、PLC和28阶段条件；发送意图先落库，发送结果未知时只查询新编号，不重发。

## 三种业务阶段

| 步骤 | 超时后保留内容 |
| --- | --- |
| `GoToPickup` | 原取箱任务、工位呼叫和取箱责任；尚未取箱 |
| `DeliverFullBoxToDumper` | 满箱归属、原倒料工位和路权；禁止自动换车 |
| `EnterDumpingPosition` | 倒料任务和已取得资源；不得误报已经到位 |
| `ReturnEmptyBox` | 倒料完成、空箱返程和PLC收尾责任；不得误报返箱或放箱完成 |

## 验证

`tools/ObstacleSafetySmokeTest` 新增隔离验证：

- Robokit 状态7与普通失败可区分。
- 取箱、送满箱、返空箱三个运输阶段都能形成 `H→D→X` 的安全改道候选，避开推断受阻边。
- 超时后步骤离开执行中、任务进入故障冻结、恢复证据落库。
- 车辆仍受阻时保持等待，不生成替代命令。
- 整个超时恢复过程不发送取消、替换导航或PLC输出。

软件验证使用临时SQLite和合成地图，未连接实车、PLC或5199日常实例。候选路线可行性仍需在真车地图和现场通道核对。

## 操作入口与边界

后台通过命名管道提供超时恢复快照和执行操作；Web恢复页新增“运输超时替代导航”面板。只有恢复写操作启用且现场人员明确勾选车辆位置、载荷归属、PLC条件和“只发送一次”后，按钮才可执行。自动化模式仍不跨车转交满箱任务。

正式替代导航按照以下顺序执行：

1. 原厂家任务全部终态确认；
2. 至少两次连续停稳和实际站点核验；
3. 车端地图及逐相邻站点线路核验；
4. 新路线交通资源整组取得；
5. 原任务、新任务编号与载荷归属持久化；
6. PLC及28阶段当前条件复核；
7. 一次性发送及回执丢失后的只读恢复。

本批仍不自动解除道路封锁，也不把满箱任务转交其他车辆。替代导航失败、部分接受或回执未知时，原业务任务保持冻结，必须现场核对。
