## 算法和后台

NearestAssigner 按当前节点到取货节点的欧氏距离选任务。GreedyEtaAssigner 用 A* 估计空驶与送达的道路耗时。SimulationEngine 使用 100 ms tick，默认每次装卸 5 tick、等待 30 tick 触发重规划、最大 200000 tick。ReservationTable 以节点或弧 ID 保存逐段滚动的时间区间预约。节点与弧的容量语义由算法模型定义。

Spring Boot 负责路网和任务集 CRUD、每用户仿真实例、WebSocket 帧、实验历史、认证和审计，H2 文件库可独立运行。前端使用 /api/sim/*、/api/roadnet/*、/api/taskset/*、/api/experiment/* 与 /ws/sim。makespan 与 totalWaitTick 使用实验 tick，totalPathLen 使用米。

## 当前 Web 仿真地图验证

主工程 `/api/simulation` 当前绑定 B07 “全厂305CNC·五车仿真图”，实例为 `web-single-vehicle-sim-20261113-114236-13ac61`。方案包含 647 个节点、1304 条有向道路、305 个业务工位和 5 台虚拟车，当前正在执行 305 工位自定义呼叫场景。

独立模块直接读取同一实例地图，转换后保存为“全厂五车仿真”。双向道路合并后为 647 个节点、652 条实验道路。编辑器在总览状态隐藏密集中间编号，搜索和缩放后可定位具体节点。

当导入图节点超过 30 个时，编辑器自动隐藏中间分段与路口的编号，并仅保留业务站点名称。搜索、选择和属性查看仍能定位全部节点和路段。

B07 三维预览使用大图精简模式，缩小 647 个节点模型，隐藏方向箭头和普通节点标签，只保留两个充电位标签，避免总览被数千个标签遮挡。

道路简化默认启用，曲线道路在实验副本中画为起终点直线，保留原长度、速度和方向。B07 源图有成对反方向道路，导入器将长度、速度和资源一致的两条道路合并为一条双向道路，两个源 ID 均写入映射记录。实验副本因此保持 647 个节点、652 条道路。

Web 仿真已切换到保存方案“CAD全厂·305CNC·五车·V5矢量地图”。当前实例绑定 B07 发布版，5 台虚拟车在线运行。导入器会将端点相反、长度和速度一致的两条有向道路合并为一条双向道路，两个源 ID 都保留在映射记录中。该规则用于降低五车全厂图在排策智演中的节点和标签密度。

此前导入的“全厂五车仿真”及旧全厂副本属于错误来源，已从独立后台清理。转换记录保留在本地 `.runtime`，现场输入未提交到 Git。
