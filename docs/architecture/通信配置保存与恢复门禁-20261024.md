# 通信配置保存与恢复门禁

## 问题与处理

WPF「系统设置 → 通信连接」保存 PLC/AGV 连接配置时，原管道入口使用新增任务执行门禁。地图已经正常运行、仅启动恢复核对未放行时，也会拒绝保存，并误报「地图切换期间不能修改通信配置」。地图绑定另有例外，导致同一页面的保存行为不一致。

现在由 `CommunicationSettingsService.SaveAsync` 统一持有地图控制锁，允许地图处于 `Running` 时保存待重启配置；不要求业务恢复屏障放行。地图尚未初始化、切换收尾和保持暂停时分别给出明确提示并拒绝保存。权限、版本冲突、未结束业务任务、参数和 CSV 点表校验仍然有效。

保存不修改当前连接实例或 Active 配置，不启用 PLC 写入、车辆指令或调度，不切换地图、不放行恢复批次。重启对应后台后才应用保存的连接配置，重启后的恢复核对独立执行。日常实例继续使用 5199 的统一启动/停止入口；升级不自动恢复单次导航发送许可。

## 模拟 PLC 配置

在连接到目标后台的 WPF 中填写模拟 PLC 地址和端口，例如本机 `127.0.0.1:10200`。启用采集前，必须将联调台「连接与点表」导出的后台用点表 CSV 放入该后台的 `config` 目录，并填写相对路径，例如 `config/plc-lab-signals.csv`。工具配置 JSON、会话 CSV 均不能代替点表。工位与地址关系来自点表，不由连接地址自动推导。

TCP 测试仅验证端口可达；协议读数和点位质量须查看通信诊断。保存成功与采集运行是不同状态；PLC 写入和自动调度还有各自的开关与运行门禁。

## 验证

- `CommunicationSettingsSmokeTest`：真实地图门禁下，恢复关闭仍可持久化而新增执行仍被禁止；真实切图状态、无效点表、过期版本、无权限和未结束任务均拒绝保存，且不改原文件。
- `RobokitBindingSmokeTest`：地图绑定保存与坐标依据校验继续有效。
- `ConnectionSettingsUiSmokeTest --recovery-closed`：隔离后台中从 WPF ViewModel 经实际命名管道保存，保存前后地图运行状态、恢复批次和未放行状态保持不变。
- `ConnectionSettingsUiSmokeTest --after-restart`：重启隔离后台后恢复已保存配置，运行连接数量更新，设备采集和写入开关保持关闭。
