# 调度判断表、状态机与Web真实接入说明

核对日期：2026-10-16。依据为当前主工程代码、当前PLC CSV和基础配置。未读取失效旧项目资料，未用朋友系统截图推断现场协议。本文说明代码行为，不代表现场设备已经完成联调。

## 1. 现状结论

原C#后台已有PLC/AGV采集、工位判断、自动/手动建任务、九步任务编排、路径规划、交通资源、持久化命令队列、恢复核对、SQLite及IPC接口。Web应复用这些服务。当前逻辑不是浏览器里的动画，也不是一个可任意编排的通用规则引擎。

“判断表”主要是把C# if/switch中的条件展开成人能检查的表；点表CSV负责PLC地址、变量、方向、确认状态与启用映射，中文置位/复位说明不自动执行。九步业务流程由代码生成，动作、工位站点映射、倒料位置、并发及部分超时提示可参数化。

此前Web页面默认演示确实不等于真实运行。本次移除主页面演示数据入口和演示模块依赖，改为启动即连接真实后台；无后台时保留明确未连接/过期状态，不注入车辆、任务、告警或地图。启动脚本默认管道改为AgvDispatch.Service。单元测试夹具仍独立保留，不进入主页面数据源。

当前基础配置：Plc.Enabled=false、Plc.AllowWrites=false、Agv.Enabled=false、Agv.AllowCommands=false、Dispatching.Enabled=false；TaskCreation、Outbox、Steps的部分配置为true也不能越过其他门禁。车辆IP、倒料位置、工位站点映射尚未在基础配置填齐，默认最大并发1。实际生效配置还可能来自保存配置、启动参数和已激活地图，不能仅用appsettings.json断言现场正在运行什么。

当前源码点表2445行，仅21行enabled=true且addressStatus=Confirmed。这些是软件映射状态，不等于本次已经逐点现场测通。检查时没有发现运行中的AgvDispatch.Service进程；Web接入层在运行。未为解释流程而启动主服务或开启设备写入。

## 2. 各层分工

浏览器(Vue/TypeScript) → HTTP/WebSocket → C# AgvDispatch.WebHost → Named Pipe → 原AgvDispatch.Service → 原Application/Domain/Infrastructure/Connectors → SQLite、PLC和Robokit TCP。

- Web：操作入口、实际数据展示、地图/方案编辑、请求提交；不能自行宣告任务完成。
- WebHost：接口适配、同源限制和错误转译；只转发明确支持的操作，不直接向小车或PLC发送运动/握手命令。
- Service：中央调度与业务状态的执行主体，持续运行；关闭网页不会停止它。
- PLC：工位传感器、倒料设备状态和约定握手位，控制其本机设备动作。
- 小车控制器：接受厂家任务，执行导航/避障/运动和配置的顶升等本体动作，回报任务结果。
- RoboShop：厂家配置与调试工具；不是中央调度业务状态的数据库。

前端技术以本地package.json为准：Vue 3、TypeScript、Vite、Three.js、Tabler图标；大屏地图使用Three.js，工程编辑画布使用SVG，状态环图为Canvas。后端是现有C#/.NET主工程；WebHost使用ASP.NET Core，数据库和调度继续用原后台实现。没有改成朋友项目的Java/Spring服务，也没有接入RDS。

## 3. 实际处理链

1. PLC轮询和AGV轮询更新缓存：数值、在线状态、质量、时间戳、坐标、站点、车端任务状态。
2. StationStateService按工位汇总必要PLC信号和未完成任务，StationStateEvaluator计算State、CanCreateTask和BlockReason。信号变化触发刷新，另有周期刷新。
3. 自动创建器监听可建任务的工位；手动创建走ManualTaskCreationService，先取得当前可选条件，再在提交时重新验证。
4. 创建任务及九步步骤并持久化。Created表示数据库有记录，不表示车辆已收到任务。相同工位已有未结束任务时不再重复创建。
5. 创建器写FullBoxRequestAcknowledged=true，成功后变为WaitingForVehicle。应答失败保留Created和错误，按配置重试。
6. 派车器按任务优先级高到低、同优先级创建时间先后取候选。检查并发、空闲车辆、有效位置、工位站点映射、可行路径及交通资源。
7. 对候选车计算到取货点的路径成本，成本低优先，同成本电量高优先；指定车辆的任务仅接受指定车。不是全局最优车队分配算法。
8. Robokit地图预检核对车端地图/站点/路段等既有规则。取得本步骤所需路权后，事务写入持久化Outbox，状态进入SubmittingToAgv/CommandPending。
9. Outbox取得发送租约后调用原AGV网关。默认按指定路径模式，使用稳定步骤身份关联车端任务/路径链，发送前仍校验开关、车辆状态、起点和地图条件。
10. 收到接受/任务号后记录Sent；后续按厂家任务状态查询。接受不等于完成；查询失败保留原状态，不用前端动画或经过时间推断完成。
11. 四个运输步骤由车端任务完成推进；五个PLC业务步骤由当前信号和写入结果推进。每一步成功后数据库事务激活下一步。
12. 第九步收尾成功，业务任务Completed，并释放任务路权。故障、取消或重启恢复走对应处置，不能靠网页刷新跳过。

## 4. 自动建任务判断表

下表按StationStateEvaluator主要判断顺序整理。A=FullBoxRequested，B=BoxPresent，F=Faulted，C=CommunicationOnline；均是逻辑变量名，实际DB地址以当前点表为准。

| 判断 | 工位结果 | 可自动建任务 |
|---|---|---|
| 缺少A/B/F/C任一必要信号 | Unknown，列出缺失字段 | 否 |
| 未完成任务数>1 | SignalConflict | 否 |
| 必要信号质量不是Good | Unknown或Offline | 否 |
| C=0 | Offline | 否 |
| F=1 | Faulted | 否 |
| A=1且B=0 | SignalConflict：呼叫却无箱体 | 否 |
| 未完成任务数=1 | 按既有任务阶段显示，含故障/取消待核对 | 否，避免重复 |
| 没有未完成任务，A=1、B=1、F=0、C=1、质量Good | FullBoxWaitingForPickup | 是，仍需创建器总开关及执行门放行 |
| 没有未完成任务且B=0 | SignalConflict | 否 |
| 其余（有箱但无满箱呼叫） | Idle | 否 |

自动建任务不等于立即派车：可先产生任务并应答PLC，再等待车、站点映射、路权等条件。手动入口当前更严格：要求创建/调度/步骤服务启用、地图/参数版本一致、工位条件成立、九步配置通过、候选车辆可用及路径可达，配置Robokit核验时还必须明确选车并核对车端地图。

## 5. 九步业务状态机

所有PLC读取条件要求Good且值匹配；未知值不等于false。以下是当前执行器实际顺序，不能把逻辑位名称当成额外物理传感器。

| 步骤 | 操作与推进条件 | 成功后 |
|---|---|---|
| 1 GoToPickup 前往取货点 | 规划车辆当前站点→取料点，取得路权，发送运输任务；等待厂家任务完成。基础动作配置JackLoad，取箱动作附在这一运输步骤，需现场核定 | 激活步骤2 |
| 2 PickupFullBox 确认满箱取走 | BoxPresent=false；若FullBoxRemoved或EmptyBoxTaskAcknowledged尚未读到true则写true并等待后续观察；两位均Good/true后复位FullBoxRequestAcknowledged、FullBoxRemoved | 激活步骤3 |
| 3 DeliverFullBoxToDumper 送到倒料等待点 | 取料点→倒料等待点，重新规划、占资源、经Outbox发送；等待厂家任务完成，基础动作Wait | 激活步骤4 |
| 4 WaitForDumperReady 等倒料机 | 倒料Faulted=false；写并观察AgvAtWaitingPosition=true；等DumperReady=true，再复位AgvAtWaitingPosition=false | 激活步骤5 |
| 5 EnterDumpingPosition 进入倒料位 | 等待点→倒料点；重新取得路权和发送；等待厂家任务完成，基础动作Wait | 激活步骤6 |
| 6 DumpFullBox 等待倒料完成 | 倒料Faulted=false；写并观察AgvAtDumpingPosition=true；等DumpingCompletedMayLeave=true，再复位到位信号 | 激活步骤7 |
| 7 ReturnEmptyBox 返回取料点 | 倒料点→原取料点；等待厂家任务完成，基础动作JackUnload，放箱动作附在这一运输步骤，需现场核定 | 激活步骤8 |
| 8 PlaceEmptyBox 确认放空箱 | 写并观察EmptyBoxPlaced=true，等待BoxPresent=true | 激活步骤9 |
| 9 CompletePlcHandshake 收尾 | 将EmptyBoxTaskAcknowledged、EmptyBoxPlaced、FullBoxRequestAcknowledged、FullBoxRemoved复位false；等待网关写调用成功，不另等协调器下一轮全部读回 | 任务Completed，释放任务路权 |

第2步和第8步不是另外再发一条取放箱命令。第6步不是前端控制倒料计时。顶升动作的厂家含义、PGV参数、PLC置复位与电平/边沿/任务身份对应关系仍须现场核定；目前上述协调器使用电平+质量判断，不能宣称已实现所有工艺防重触发条件。当前配置VerifyWrites=true还会经过PLC网关的写校验，但网关写成功也不能替代未配置的机械动作反馈。

## 6. 三种状态分别存储

1. 业务任务阶段DispatchTaskStage：Created → WaitingForVehicle → GoingToPickup → PickingUp → GoingToDumper → WaitingForDumper → Dumping → ReturningEmptyBox → WaitingForPlcConfirmation → Completed；四段运输准备期间会反复进入SubmittingToAgv。Faulted、Cancelled、CancellationPending、CancellationReview为另外的处置分支。业务阶段是粗粒度，不与九步逐一对应。
2. 步骤状态DispatchTaskStepStatus：Pending、Ready、CommandPending、Sending、Executing、Completed、RetryScheduled、Failed、Cancelled、ManualIntervention。当前步骤与其等待条件最能解释“卡在哪里”。PLC业务步骤可由Ready直接完成，不要求每步都经过车辆Sending/Executing。
3. 命令状态AgvCommandStatus：Pending → Sending → Sent，失败可RetryScheduled，达到上限Failed，另有Cancelled。Sent仅表示网关接受并持久化，不表示业务或物理动作完成。

同一个任务可在“业务GoingToDumper、当前运输步骤Executing、命令Sent”同时成立。不能把其中任何一个字段单独翻译成整个任务已经完成。

## 7. 路权、异常与恢复

- 当前后台路径成本按距离/速度和交通惩罚构成，排除不可用资源、禁用路段及不允许方向；不是Web航点列表中仅按距离的静态检查。
- 共享资源有容量、占用任务和步骤身份。先申请成功才准备命令；占用时等待或规划其他可用路径。资源定义、边界和绑定须正确，场景矩形不会自动成为交通资源。
- 故障/失联不自动宣告完成。路权租约到时不自动证明车辆已离开，不因前端刷新释放。
- 车端Failed/Cancelled进入相应业务处置；命令普通失败指数退避、受最大尝试次数限制；部分接受异常会缩小自动重试范围，不承诺任意固件上的“绝对只执行一次”。
- PLC条件未满足通常停在当前Ready步骤；写异常记录错误并继续由后台周期处理，不跳下一步。超时参数当前主要形成耗时/超时提示，不等于每个步骤都有自动强停或自动恢复。
- 重启先读取数据库、车端/PLC证据和恢复屏障，不直接从第1步重新跑。恢复核对本身不创建运输命令、不写PLC输出、不释放路权。取消/恢复/解锁等正式处置继续使用已有WPF入口。

## 8. Web真实接入进度与边界

| 能力 | 目前接入 |
|---|---|
| 系统、车辆、任务、设备字段、告警、交通资源、运行导航图 | WebHost串行读取原Service，WebSocket推送；含质量与过期检查 |
| 任务历史列表、详情和创建条件/四段路线核对 | 复用原GetTasks/GetTaskDetail/GetTaskCreationOptions/GetTaskRoutePreview |
| 手动任务创建 | 已有CreateTask适配，Web提交开关默认false；本次修正申请编号为后台要求的32位Guid N格式；结果不明保留原编号，不生成新号重发 |
| 地图导入、完整草稿、新建、保存、发布 | 复用原地图服务，EditToken防覆盖；运行切换仍用WPF |
| 车辆新增/通信配置 | 复用原保存配置服务，revision防覆盖，保留其他通信配置，服务重启生效 |
| 场景与综合方案 | 浏览器本机编辑存储，尚非统一后台项目库；加载不会改变后台真实运行地图 |
| 厂家激光/CAD背景和3D点云 | 主工程有相应能力，本次Web仍未完整迁移；不能称Web地图功能与WPF完全一致 |
| 操作人员身份 | 当前NamedPipe用Windows身份审计和LocalOperation，无独立软件登录/角色隔离；Web仍仅监听本机127.0.0.1，不可据此当作局域网多人生产服务 |

浏览器默认真实后台不等于自动启用PLC/AGV或自动启动主服务。本次不修改现场地址、执行开关、活动地图和任务数据，也不为填满页面生成任务。

达到现场交付需要核定并联通：正确主服务/数据库；PLC地址、读写方向、握手与有效点位；实际车辆IP/端口/固件；运行地图与车端地图版本/站点/路段及坐标绑定；取料、等待、倒料位置与动作参数；从单工位单车全流程、重复呼叫、断网、重启、超时、取消到资源竞争逐项验收。Web和WPF可并存迁移，无需重写原后台调度内核。
