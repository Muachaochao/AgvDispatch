# 任务取消与全链路恢复补丁（2026-11-06）

## 现场目标

- 取消当前四工位测试任务后，不留下活动任务、残留路权、PLC 握手输出或启动恢复屏障。
- 车辆导航、取消、恢复、任务暂停和交通资源释放都必须沿用原任务身份。
- 明确的车端拒绝不能被误判为“发送结果未知”，也不能自动重复发送。
- Web 能看清任务为什么等待、受哪辆车和哪些资源影响，并能进入对应任务详情。
- 补丁只替换程序与前端静态文件，不覆盖现场数据库、地图、通信配置和 PLC 点表。

## 已修复问题

1. **3051/3066 明确错误被误当作发送结果不确定**

   - 车端返回明确错误时，现在进入发送前终态拒绝。
   - `40020 control is preempted` 只尝试一次，命令立即失败闭环，不再查询后重发或创建第二条任务。
   - 只有真正丢失响应且无法证明是否接收的情况才保留原命令等待人工恢复。

2. **无厂家任务号的取消记录可能卡死**

   - 当原命令明确未发送、车辆在线、定位有效、车辆停稳且车端没有活动任务时，取消可以进入人工核对关闭阶段。
   - 仍要求现场确认车辆、载荷、PLC 周期和路权；系统不会因为超时自动认定取消成功。

3. **完成路段没有及时释放路权**

   - 新增完成运输路线释放服务：车辆到达目标站并满足车体包络与定位证据后，释放已经完全通过且后续不再使用的资源。
   - 终点资源、未来步骤仍需使用的资源和证据不足的资源继续保留。
   - 发布配置已恢复 `TrafficSegmentRelease.Enabled=true` 与 `CommitEnabled=true`。

4. **短暂交通等待被误判为车辆故障**

   - 正常交通排队与急停、非 52200 报警、设备故障分开处理。
   - 单车等待公共资源时不会因为短时静止冻结全组；持续异常仍进入受控等待或故障处置。

5. **取消、暂停、恢复和历史记录口径混杂**

   - 后台任务数只统计仍处于运行、等待或挂起中的业务任务。
   - 车端历史记录数不再被解释成调度活动任务数。
   - 取消、暂停、恢复保留原任务、原步骤和原命令编号，页面明确显示原因及当前阶段。

6. **Web 任务中心信息不足**

   - 任务关键时间、等待阶段、关联车辆、占用资源、阻挡资源及释放条件可在任务详情查看。
   - 任务列表增加历史时间范围和筛选，前后台总数分开。
   - 同一车辆、同一工位和相关测试入口完成归并，减少重复页面跳转。

7. **只读查询断连造成重复日志**

   - Web 刷新或切页导致只读 `Get*` 管道回执无法送达时，不再连续记录两次 Warning。
   - 写操作、发送结果未知和后台处理异常仍保留 Warning，不影响安全审计。

8. **模拟 PLC 四工位能力**

   - 联调工具支持 CNC-001 至 CNC-004 批量呼叫。
   - 复位工具覆盖四工位和倒料共享输出。
