# Web 单车协议闭环联调

用户要求使用现有 Web 的地图、车辆配置、任务提交、大屏和详情运行一台虚拟车，而不是新增演示或模拟验收按钮。本次使用正式 Service/WebHost 和独立 SQLite，虚拟设备只监听回环端口，分别经过真实 Robokit TCP 客户端及 HSL S7 驱动。没有直接改写业务步骤或任务终态。

地图来自本地已保存的规范化 JSON，经过导入、草稿、发布、激活及坐标绑定。它是已有离线构造地图，不是实车导出；地图/点表原始文件、数据库、配置、截图及报文证据仅留在本地 artifacts。当前握手采用已实现的 sender-owned-return-confirmed-v1，不宣称兼容尚未实施的最新拟议现场时序。

## 本次发现与修复

- 启动时多个后台组件重复初始化数据库，资源定义删除与重建发生竞争。现在在启动 HostedService 前完成初始化，同一初始化器串行且只成功初始化一次，避免后续调用清除活动地图资源。
- 自动呼叫创建与手动任务应答共用一个开关，难以仅手动联调。新增 TaskCreation.AutomaticCreationEnabled，默认 true 保持既有行为；关闭它保留已持久化手动任务的应答和重试。TaskCreation.Enabled=false 的全关闭语义保持。
- 顶部创建任务链接未消费 create 查询参数；提交成功也没有打开详情。现在消费一次入口参数、移除触发参数，并在接收成功后转入原任务详情。
- 详情只加载一次，打开后持续过期。现在随后台快照刷新，避免重叠轮询，旧选择或断连后的迟到结果不会替换新详情。
- 无资源路线的路权申请返回 NotRequired，但发送快照只接受 Acquired/Held，导致合法路线无法准备命令。现在仅当申请、节点和路段均不包含交通资源时接受 NotRequired；真实资源不能借该状态绕过核验。

## 验证与边界

新增数据库并发启动、重复初始化保护、自动模式兼容及只手动建单应答 7 项回归。运输快照回归扩展为 34 项，包含真实无资源路径及节点/路段隐含资源的拒绝和事务回滚。另执行持久化握手 37 项、独立后台九步两车 18 项、前端 109 项及生产构建。

浏览器实际编辑车辆名称并保存后台，按原激活及恢复门禁准备运行图，由正常任务表单提交。虚拟设备收到 3066 后按导航文件路径移动，1110 返回逐段状态，S7 按执行器契约反馈箱体和倒料状态。成功任务保留四段命令、九步详情、原始报文及诊断 ZIP。

联调中重载虚拟设备曾使旧导航 TCP 连接失效，后续任务在发送结果不明/404 时保守故障并保留路权；未把它强改成通过。另一个工位任务暴露无资源路径缺陷，其原记录也保留。修复版本在新独立实例复测，不能删除旧失败后重新计算全程成功率。

工具说明见 tools/WebSingleVehicleLab/README.md。运行环境及逐任务结果以本地 ready.json、任务详情和本轮结果报告为准。初次源码上传扫描发现用户原有 outputs 内一个超过 10MB 的检查数据文件；该目录不属于本次修改，不加入提交。源码及回归工具独立核对，现场输入与所有运行产物不上传。
