# 项目分类与定位指南

## 原则

先按架构层确定项目，再按业务模块找功能，再按职责找文件。保留7个生产项目，不为目录分类而增加类库。每个文件只放在一个明确职责目录，跨模块复用才进入 Shared。项目根目录保留启动入口、项目文件及运行配置；数据库、地图、点表、日志的运行路径不变。

本次只整理源码目录：现有 namespace、公开类型、Prism 路由、数据库实体映射及配置键不变。文件夹和命名空间暂时不强制一致，避免机械重命名影响跨层接口和 XAML 类型。不要仅为匹配文件夹而改动 x:Class。已有接口文件中部分 DTO 暂时仍与接口同文件，后续改具体模块时再细分。

## 解决方案分组

| VS分组 | 项目 | 职责 |
| --- | --- | --- |
| 01.Domain | Domain | 领域模型、状态、纯计算规则 |
| 02.Application | Application | 应用契约、DTO、业务接口 |
| 03.Connectors | Connectors.Plc / Connectors.Agv | 设备协议与连接适配 |
| 04.Infrastructure | Infrastructure | 数据库实现、地图资产、路权、审计 |
| 05.Service | Service | 后台循环、编排、进程内组装、Named Pipe服务器 |
| 06.Wpf | Wpf | 界面、交互、显示模型、Named Pipe客户端 |
| 07.Tests | tools 中15个冒烟项目 | Backend / UI / Protocol分类验证 |

## PLC 与 AGV 连接层

```
AgvDispatch.Connectors.Plc/
├─ Configuration/  PLC型号、地址、超时等选项
├─ Connections/    多PLC连接组、连接监督
├─ Signals/        CSV点表目录、信号缓存
└─ Siemens/        HSL西门子S7适配

AgvDispatch.Connectors.Agv/
├─ Configuration/  多车及协议选项
├─ Connections/    多车连接管理
├─ State/          状态缓存
└─ Seer/
   ├─ Protocol/    报文编解码
   ├─ Client/      单车TCP客户端
   └─ Gateway/     业务命令到厂家协议的转换
```

## 应用层与领域层

Application按Plc、Agv、Stations、Tasks、Maps、Traffic、Alarms、Recovery、Diagnostics、Settings、Persistence、Ipc划分，各模块接口和传输对象进入Contracts。Application/Maps保留地图定位分析等应用算法。

Domain继续按Agvs、Devices、Stations、Tasks、Maps划分。Tasks细分Commands与Steps，Maps细分Geometry、Routing、Traffic、Versioning；纯领域模型不得依赖WPF、HSL、SqlSugar或Windows Service。

## 后台服务

```
AgvDispatch.Service/
├─ Program.cs          依赖注册及进程启动
├─ Hosting/            服务心跳与生命周期
├─ Ipc/                Named Pipe服务器、诊断与传输选项
└─ Modules/
   ├─ Plc/             Polling采集 / Evidence写入证据
   ├─ Agv/             Polling采集 / Tracking轨迹
   ├─ Stations/        工位组合状态
   ├─ Tasks/
   │  ├─ Creation/     任务创建及应答
   │  ├─ Dispatching/  车辆分配和调度编排
   │  ├─ Steps/        PLC条件推进
   │  ├─ Commands/     Outbox命令发送
   │  └─ Queries/      任务中心查询
   ├─ Maps/            运行地图加载及CAD后台工作
   ├─ Traffic/         路径选择、交通状态监测
   ├─ Alarms/          报警规则循环
   ├─ Recovery/        重启恢复工作循环
   ├─ Diagnostics/     系统快照
   └─ Settings/        通信配置服务
```

## 基础设施

Persistence/Database仅负责数据库创建、初始化和连接。Tasks/Repositories负责任务与命令持久化；Agv/Tracking负责轨迹。Maps分Import、Validation、Calibration、Cad、Runtime、Management、Entities。Traffic、Alarms、Recovery、Settings各自保留模块实现及Entities，不把所有业务类都塞进Persistence。

Entities表示数据库表结构，不等同于Domain领域对象。Service负责后台调度循环，Infrastructure负责具体持久化和资产实现，不按页面名字跨层搬运业务逻辑。

│  ├─ Maps/
│  │  ├─ Overview/     地图管理总览
│  │  └─ Editor/       编辑Views、ViewModels、独立Windows
│  ├─ Recovery/        重启恢复
│  ├─ Diagnostics/     通信诊断
│  ├─ Alarms/          报警记录

├─ Shared/
│  ├─ Ipc/             后台客户端
│  ├─ Theming/         主题服务
│  ├─ Maps/            共用运行地图显示模型

每个模块自己的Views和ViewModels放在同一模块下，页面专用Converters也放回对应模块。AGV管理位于Wpf/Modules/Agv，设备监控位于Wpf/Modules/Equipment；两者已接入后台只读快照，不是占位入口。共享刷新和样式位于Wpf/Shared/Monitoring。快照契约位于Application/Monitoring/Contracts，后台聚合位于Service/Modules/Monitoring，不在页面直接读取PLC或AGV。

## 故障定位顺序

| 问题 | 首先查看 |
| --- | --- |
| PLC连接失败 | Connectors.Plc/Connections与Siemens → Service/Modules/Plc/Polling |
| AGV报文或任务响应错误 | Connectors.Agv/Seer/Protocol、Client、Gateway |
| 满箱未建单 | Service/Modules/Stations → Tasks/Creation → Infrastructure/Tasks/Repositories |
| 任务不继续 | Tasks/Steps、Tasks/Commands → Recovery → PLC/AGV现场证据 |
| 路径/占用问题 | Domain/Maps/Routing、Traffic → Service/Modules/Traffic → Infrastructure/Traffic |
| 地图编辑或发布异常 | Wpf/Modules/Maps → Infrastructure/Maps → Domain/Maps |
| UI后台调用失败 | Wpf/Shared/Ipc → Service/Ipc |

## 移动记录与验证

source-layout-migration.json逐条记录177个文件的旧/新路径，可据此核对及反向移动；移动脚本tools/Organize-SourceLayout.ps1预检全部路径，不覆盖目标，重复运行不重复移动。它只移动文件，不更新引用；相关测试Compile链接和窗口资源路径已经在本次整理中同步调整。命名空间保持兼容，因此入口依赖注册不变。

所有测试项目已纳入解决方案。至少执行解决方案编译、HeaderUiSmokeTest、MapEditorSmokeTest、MapTrafficSmokeTest和SeerProtocolSmokeTest；其他任务、恢复、配置专项测试按修改范围补跑。运行测试不代表完成现场PLC/AGV联调。
