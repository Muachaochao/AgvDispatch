# 主干道旁停位与滚动切窗（2026-11-28）

## 本轮改动

- 不改原 CAD 节点、原路段方向，也不把主干道节点直接改成可停车。
- 在主干道相邻节点近似共线、两侧净空足够、且没有支路/路口的一侧，生成独立短停位（旁停位）。
- 旁停位是死路：主干道锚点 → 旁停位 → 同一锚点，只用于交通窗口停车，不用于倒料或充电等待。
- 每个旁停位独立容量 1 个资源，车辆停入后让出主干道。
- 滚动窗口优先使用地图原有安全点；只有在最大窗口范围内没有原安全点时，才用最远的可用旁停位切窗。
- 分批路权新增车体占位约束：车辆实体仍占用的路段不能被选作分批停点。

## 已知观察

- 窗口切换瞬间，`traffic_request` 可能已指向下一窗，而 `step.VendorTaskId` 仍指上一窗，逐资源“通过即释放”会记录一次“当前发送载荷与选定的滚动窗口不一致”并保持原路权。该状态是保守拒绝，不会误释放；编排器仍按窗口交接流程释放不再复用的资源。
- 新增旁停位只改善窗口切换的资源占用，不改变倒料口 `J0652` 的整车清场规则。
