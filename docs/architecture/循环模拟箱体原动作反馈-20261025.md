# 循环模拟箱体原动作反馈（2026-10-25）

## 修复范围

原循环模拟器收到 H:FullBoxRemoved 才撤 P:BoxPresent，而正式28阶段执行器要先收到无箱才发 FullBoxRemoved，造成互等。1.5.1 联调台增加本机原动作反馈端点，后台只在本轮原运输步骤已完成、原车端整链成功、原车在正确工位停稳且定位及反馈新鲜时，模拟箱体离开/返回。

- 取箱必须是原步骤 GoToPickup 的 JackLoad；返箱必须是原步骤 ReturnEmptyBox 的 JackUnload。纯导航不能作为取放箱成功证据。
- 校验运行、呼叫序号、原任务、原车辆、步骤、车端任务、地图版本、路线终点和动作；前序步骤未闭合、取消、暂停、断连或恢复门禁均不推进。
- 控制端点只对本机默认模拟PLC（127.0.0.1:10200）开放，拒绝浏览器Origin和无控制头请求。反馈新鲜度5秒；同一原动作重试幂等，换动作身份拒绝。
- 后台先读取 capabilities，确认 business-box-action-v1 才产生循环呼叫；旧工具不能直接用于新版自动循环。
- 停止新增呼叫保留本轮收尾。重连或后台重启保持暂停，不自动续发、清通知或释放原占用。

这里是**模拟PLC箱体输入**，日志明确注明非物理传感器。真实PLC仍由真实传感器驱动；模拟闭合不能作为厂家PLC或实车物理取放验收结果。

## 验证和使用

`dotnet run --project tools/PlcHandshakeLabSmokeTest` 覆盖动作反馈先于H通知、错误任务/序号/过期反馈拒绝、HTTP接口限制、两工位两轮、停止收尾和重连暂停，以及原有S7、28阶段、导出回看和界面投影回归。

`dotnet run --project tools/BusinessRunSmokeTest` 覆盖本轮步骤证据、取消/暂停/错误工位/错误车辆/旧动作拒绝，以及原有循环调度和暂停记录收尾。

`dotnet run --project tools/Handshake28IntegrationSmokeTest` 验证正式SQLite/Outbox/28阶段及独占交接；`tools/ManualTaskCreationSmokeTest` 验证请求注销与创建串行门禁。

先启动最新网络联调台并使用本机模拟PLC，再启动5199正式业务测试模式；依次验证工位一单轮回LM7、工位一到工位二回LM7、连续两轮及故障恢复。每次以原任务、全部握手和路权闭合、车辆实际停靠LM7为结束条件，不能以发出导航或计时器到点代替。

源码回归和模拟验证不等于实际车辆测试通过，实车结果须另存当次运行证据。
