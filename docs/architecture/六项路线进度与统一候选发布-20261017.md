## 本批继续开发内容

新增`tools/Build-CommissioningBundle.ps1`：在全新目录生成候选包，不调用原来的覆盖式统一更新脚本，不停止/替换当前运行程序。

发布批次写入三个.NET程序集的InformationalVersion及Web页面构建常量。WPF窗口标题/页头显示客户端批次，WebHost返回自己的程序集指纹及批次，联调页核对页面/WebHost/主服务三方批次。

- 候选批次一致：只表示当前软件声明来自同批发布，文件内容仍按清单核对。
- 混用旧页面、接入层或主服务：显示阻塞，不把版本号相同的1.0.0.0当成同一程序。
- 未取得身份或使用独立开发构建：显示待核对。
- 后台断连或观察过期：不能继续以旧主服务身份显示当前核对通过。

此核对不替代PLC固件、地图、参数、设备状态、恢复及现场验收，也不通过修改版本标记来授权任务。

## 候选包内容与使用

候选包包括`Service`、`WPF`、`Web/host`、`Web/wwwroot`、许可证、README和`release-manifest.json`。

1. `Start-Service.cmd`启动候选后台，保持窗口打开。
2. `Start-Web.cmd`启动候选接入层，按提示访问本机5198端口。
3. `Start-WPF.cmd`打开同批WPF，使用相同候选管道。
4. Web进入联调检查，核对三方批次，并查看空配置产生的实际缺项。

CMD直接调用程序，不依赖PowerShell脚本执行策略。候选为Windows x64自带运行时。原5188预览和原主服务不被停止、覆盖或重定向。

候选采用独立管道和独立空数据库，使用受版本管理的禁用配置示例；不复制现有`config`、`data`、`logs`目录或开发机appsettings。所有通信/写入/派车/新握手/Web提交默认关闭，不自动造地图、车辆或任务。缺少现场输入是当前真实状态，不是启动失败。

配置迁移必须逐项处理地图版本、车辆地图/坐标绑定、IP端口、PLC点表及归属、站点/动作、任务参数、恢复状态和执行开关。不能将空候选目录替换现场data后直接开跑。本批没有执行配置迁移或现场部署。

## 可重复构建与核对

构建脚本先完整Rebuild，再以`--no-build`发布，避免WPF缓存清单仍引用已缺失BAML的问题。输出已存在时拒绝覆盖；失败目录没有完整清单，不作为可用发布包。

同批候选检查三个组件的Application/Domain共享程序集SHA256一致，并列出全部初始文件的哈希与大小。程序运行后新增数据库、日志、保存配置不在原始清单内，不能再声称运行目录与初始包完全一致；保留原包作为部署基线。

Web接入测试新增`--candidate-dir`，复制候选后台到唯一临时目录、生成自己的空点表/私有数据库、使用独立管道和回环端口，实际启动候选Service/WebHost。它检查同批身份、页面批次及原查询、地图/车辆编辑、诊断、导出和默认写入口拒绝；不连接现场设备。

本批有效候选为`commissioning-20261017-143301`。同批创建235项、两车集成61项、独立进程18项、恢复132项、候选Web接入63项、前端18项通过。前三项加载的Service/WPF程序集已逐个核对与候选相同，恢复测试的Infrastructure程序集也与候选相同；Web测试实际启动候选Service/WebHost，并核对页面内嵌批次。

完整日志在`artifacts/commissioning-20261017-143301/`，随包验证摘要见`VALIDATION.md`。所有测试仍属于隔离/模拟，不能替代真实S7网络和机械动作验收。长时间浏览器检查曾暴露测试只检查前5帧的缓冲假设，已改为在15秒预算内排空旧快照并读取断连帧，最终63项通过；没有改生产断连判定。

开发侧可用`tools/Verify-CommissioningBundle.ps1 -BundleDirectory 候选目录`逐文件验证初始包。它拒绝越界/重复路径、链接跳转、哈希或大小差异、未列入清单的文件以及组件批次不符；它是完整性核对，不是数字签名或现场验收。
