# 可配置多车、多工位调度：开发与隔离验证报告

日期：2026-10-28。范围：源码开发、合成设备及独立数据库验证、隔离 Web 演示。没有连接现场机器人或 PLC，没有更新、重启日常 5199，也没有恢复现场发送许可。

## 本批完成

### 参与范围与并发来自配置

- 多车联调不再要求恰好两辆车。启动配置提供车辆清单和独立并发上限；并发允许 1 至配置车辆数。清单、申请数量有显式输入上限，不能理解成无限规模承诺。
- Web 读取后台车辆、业务工位列表，支持筛选、多选、批量选择和调整呼叫顺序。选中数量、配置数量及后台并发上限可见。
- 可以选择启动配置内的一部分车辆。每个所选工位必须有可服务的参与车辆，每台参与车辆必须属于至少一个所选工位的车辆池；实际调度仍按原调度器选择车辆。
- 运行归属限制到本组参与车辆，其他已配置车辆不能接走本组任务。原申请未取得确定结果时保留车辆、工位和顺序；不会在轮询时把用户清空的选择自动补回。
- 根入口与候选包使用同一个脚本生成器，支持任意配置车辆清单、可选并发、后续启动选项和带空格路径。兼容原双车别名及带引号的旧入口。

当前多车联调是“一组所选工位、每工位一次呼叫”，保留错峰、同时和前后交接用例；它不是任意业务流程的通用编排器。

### 未受理申请可以明确核对注销

原申请因参数校验未受理时，网页过去会一直锁住参数。新增“核对并注销未受理申请”：后台在与启动相同的互斥区检查当前运行和历史记录，再持久化注销记录。已受理申请拒绝注销；已注销编号的迟到启动拒绝执行。重复注销幂等。

网页只有收到对应申请编号的确定注销回执后才解锁。通信失败、未知结果、历史损坏均继续保留原申请。这个操作不取消任务、不释放占用、不发送设备动作。

### 交通循环等待风险可见

- 从完整数据库快照分析任务、原步骤、车辆和租约，分析范围不受页面分页或筛选截断。
- 先进行资源容量化简，再找强连通等待分量，减少容量大于一时单纯图环产生的误报。
- 页面报告等待车辆、持有车辆、资源和稳定风险编号。身份冲突或非路径历史等待不拼成确定循环。
- 失去心跳的租约继续保留。分析是只读诊断，不自动解锁、倒车或重发，也不能证明物理死锁。

### 工程模型的待机分配与静止占位

使用车辆→物理待机点→共享容量的最大匹配，统一工程校验与模拟的判断。物理停车节点容量始终是一辆车，共享资源容量由配置控制；车辆池、路线可达性和封锁也参与判断。匹配可通过残余边调整早先选择，避免简单贪心遗漏有解配置。

本次复核发现并修复：只给部分车辆派任务时，原模型可能把未出车车辆的停车点分配给另一辆车。现在所有车辆的初始停车节点及对应待机容量都保留给原车，含未接任务、低电、能力不匹配、离线和停用车辆；不假定其他车辆已经移动。原车回原位使用已保留名额，不重复扣容量。必须通过独立调位才能成立的配置会明确拒绝。

这是保守的规划模型，未实现在线全局最小成本停车优化或独立车辆调位执行。

### 修复直线路线终点的倒料出区误判

真实执行组件模拟暴露了一个实际缺陷：直线终点候选先插入，导致正常终点的候选索引顺序反转，被误判为“多个不相邻路线位置”。将终点候选放到有序路段候选之后，正常直线、多段直线及折线终点可以完成出区核对。非相邻重叠、回区、环路歧义仍拒绝；双帧、包络、地图与新鲜度门限保持原要求。

### 新执行组件模拟的具体边界

`tools/MultiFleetRuntimeSmokeTest` 实际使用调度器、步骤协调器、持久化 28 阶段握手、命令出站队列、交通资源服务和独立 SQLite。只有设备边界是进程内合成 AGV/PLC，没有网络。

检查包括：单车不能同时接两项业务、配置并发达到且不超限、容量一资源不重叠、资源争用产生等待、每个任务九步正常完成、四段命令各发送一次、最终设备/路权/握手闭合。断线注入前记录原任务与原命令，断线期间逐项保留其对应关系；其他车辆必须比断线前新增完成步骤，不能用累计历史步骤冒充继续推进。

测试还在设备及路权已持有时重建执行组件，确认归属保留。这里的重建复用合成网关、缓存及数据库客户端，**不是完整服务进程重启、通信重连或启动恢复页面验收**。合成设备以离散状态跳转表示行驶完成，不能证明碰撞规避、制动性能或真实机械动作。原生 Robokit 网络协议、现场地图激活和实车多车并发均未在本批执行。

## 查看与复现

临时演示地址：`http://127.0.0.1:5297/#/engineering?tab=simulation`。5297 是隔离验证入口，日常入口仍为 5199。隔离实例底部明确显示设备、任务与现场恢复接口已禁用；车辆列表没有真实车辆属于正常情况。

在工程配置中心选择已发布版本，再选择参与工位、模拟离线车辆或封锁资源，运行隔离模拟；配置和结果存于独立工程数据目录。示例中的 CNC/AGV 编号只是可替换数据，不是业务代码必须使用的编号。

从仓库目录运行：

```powershell
./tools/Start-WebEngineeringSimulation.ps1 -Port 5297 -Build -NoBrowser
dotnet run --project tools/EngineeringCenterSmokeTest -c Release -p:NuGetAudit=false
dotnet run --project tools/MultiFleetRuntimeSmokeTest -c Release -p:NuGetAudit=false
dotnet run --project tools/FleetTestSmokeTest -c Release -p:NuGetAudit=false
./tools/FleetTestSmokeTest/Test-LaunchConfiguration.ps1
dotnet run --project tools/TrafficCycleSmokeTest -c Release -p:NuGetAudit=false
dotnet run --project tools/DumperExitSmokeTest -c Release -p:NuGetAudit=false
dotnet run --project tools/Handshake28IntegrationSmokeTest -c Release -p:NuGetAudit=false
```

若 5297 已启动，启动脚本会拒绝接管。需要更新隔离实例时先用 `Stop-WebEngineeringSimulation.ps1` 停止本脚本记录的实例；脚本核对 PID、路径及启动时间，不停止其他实例。数据库、配置、截图和生成报告不提交 Git。

## 当前仍有限制与后续优先项

1. 实际九步执行器仍使用一组倒料设备、等待点、倒料点及公共动作参数。工程规划模型可以配置多个设备，不代表真实执行端已完成多设备路由和独立交接；应先补这层执行绑定。
2. 工程模型支持各车独立待机分配；多车联调结束不自动发送回待机导航。真实回待机需要持久化申请、原命令核对、动态容量和静止车辆占位联动，不能直接把模型结果发给车辆。
3. 当前 PLC 健康/基线检查仍含全局已配置工位。选择部分工位不等于已实现分区故障隔离；大厂区需定义通信域和共享资源影响范围。
4. 已有资源互斥、等待和循环风险诊断，不具备完整时空多车路径规划、自动死锁解脱或物理防碰撞认证。道路必须配置参与管制的资源，画出区域不会自动获得交通控制能力。
5. 输入数量可配置，当前检查是有限样例和预算内模型；不能据此承诺任意车辆/工位数量的吞吐、延迟或可用率。现场仍需按实际拓扑、车型、设备周期逐步做多车并发和长时运行验证。

下一批优先：多倒料设备执行绑定、持久化独立待机分配、分区故障影响控制，再做隔离长时故障注入。现场部署与实车验证应另行按当前数据和许可进行，不把这次模拟结果当作现场放行依据。
