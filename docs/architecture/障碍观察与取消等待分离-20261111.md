# 障碍观察与取消等待分离（2026-11-11）

## 结论与依据

不再沿用“第一个阈值既规划又取消”的行为。默认30秒开始只读评估，60秒提醒，120秒报警并允许考虑受控取消，300秒升级人工处置及实际受阻方向的封路建议。120秒是阻挡观察时间，不是厂家释放时间；任何时间线都不能代替原导航全链终态和安全核验。

本轮只读核对日常5199数据库、历史执行审计和已归档的厂家原协议，没有修改日常数据库、配置，也未向真车或PLC发送指令。

## 配置与实际行为

| 参数 | 默认值 | 行为 |
| --- | --- | --- |
| DetourAfterSeconds | 30秒 | 只读核对、停稳观察、搜索候选，不取消、不发送 |
| WarningAfterSeconds | 60秒 | 提醒人员关注持续受阻 |
| CancelAfterSeconds | 120秒 | 独立受阻观察期；满足安全前置条件才允许请求一次精确取消 |
| AlarmAfterSeconds | 120秒 | 持续报警；不自动跳过安全条件 |
| ClosureSuggestionAfterSeconds | 300秒 | 升级人工及封路建议；无安全路线时明确冻结 |
| CancelTerminalWaitWarningSeconds | 30秒 | 自持久化取消意图计时；未确认原链终态就提醒核对，继续只读查询 |

急停、严重报警、定位失效、交通互锁等由原有安全门立即处置，不等满300秒。原任务、原车、原目的地、满/空箱责任、PLC和交通资源继续保留。后方通道、地图、包络、位置或厂家能力不明确时不允许自动退站。

保留旧配置键 DetourAfterSeconds 以兼容读取，但语义明确为只读评估。旧配置即使仍是5或10秒，也不会因此提前取消，新取消门默认120秒。已有部署不会被源码默认值自动更新；下次完整发布必须核对实例实际配置及启动日志。隔离仿真新实例生成器同步采用新策略。
