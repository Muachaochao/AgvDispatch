# 循环测试原申请核对收尾

当第一次业务创建被配置校验拒绝时，循环已保存申请编号但没有任务编号。旧实现把它一直视为未知发送，人工结束记录也无法通过；反复启动不会解决。

## 处理边界

只在管理员明确请求“核对原运行并结束记录”时处理。先确认原运行暂停、车辆在待机点静止、无活动任务、呼叫及握手闭合，再在与任务创建、待机发送相同的独占门禁下查询原创建回执及原待机发送链。任意一项存在，保留原记录，禁止注销。两项均不存在时，先持久化该申请的禁止创建记录，再清除循环中的待确认编号。业务运行仍须通过原配置与恢复校验才能结束，不自动续跑。

禁止创建记录位于后台数据目录 `business-run.json.retired-requests.json`，保存原申请、运行、车辆、地图版本、参数版本、原运行操作人及注销时间。原创建回执和待机链并未删除。该记录必须随运行数据一起备份和迁移；损坏时启动失败，不静默丢弃。重启后及运行归档后，原编号仍不可用于创建新任务。原任务已受理时继续返回原回执。

界面只读查询不会注销申请；网络失败不视为拒绝。该处理不发送车辆动作、不取消原车端任务、不清 PLC 位、不释放其他任务路权。

## 验证

BusinessRunSmokeTest 覆盖持久化注销、重启、重试、损坏记录、与正在创建任务互斥、原回执优先、原发送链保留。ManualTaskCreationSmokeTest 使用隔离数据库验证迟到请求被拒绝且未创建任务。所有夹具均不连接现场设备，不能代替实车循环验收。
