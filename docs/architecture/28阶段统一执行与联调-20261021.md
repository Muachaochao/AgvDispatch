# 28阶段统一执行与联调

生效依据：用户于2026-10-21明确已与电控统一，要求按既有28阶段改主执行器、实际出区交接、恢复、Web和实验台。当前实现契约为 `plc-28-stage-v2`。这次确认优先于2026-10-20“取箱前置通知、无箱由PLC清零”的30阶段提案。

## 信号责任和三处统一

以CNC-001默认模拟地址为例，现场仍需按实际CSV点表核定。`0.5`为取箱结果保持通知，不是取箱前许可，也不是瞬时无箱传感器；由H取箱后置1，返箱闭合后清0。P不因无箱清该H位。`0.6`保持本轮返空箱责任。`610.1`保持本轮倒料周期至车辆及箱体实际出区，不能以返回命令接受替代出区。

| 信号 | 责任 | 置位 | 复位 |
|---|---|---|---|
| FullBoxRequested / 0.0 | P | 本轮满箱需求 | 看到H受理应答后撤销，内部忙碌保持 |
| BoxPresent / 0.1 | P | 物理有箱 | 物理无箱 |
| FullBoxRequestAcknowledged / 0.4 | H | 本轮任务保存并受理 | 取箱结果及返箱责任核实后 |
| FullBoxRemoved / 0.5 | H | 本轮取箱成功并确认无箱 | 第25阶段，返箱及退出交接已核实 |
| EmptyBoxTaskAcknowledged / 0.6 | H | 本轮承担返箱责任 | 第27阶段最后清零 |
| EmptyBoxPlaced / 0.7 | H | 本轮放箱动作成功 | 第26阶段 |
| AgvAtWaitingPosition / 610.0 | H | 实际到等待点、获得设备归属 | 本轮Ready消费持久化后 |
| AgvAtDumpingPosition / 610.1 | H | 实际到倒料点、Done旧低已确认 | 第19阶段实际出区证据已保存后 |
| DumperReady / 610.2 | P | 本轮入站许可与内部保留建立 | H撤等待申请后，内部保留继续 |
| DumpingCompletedMayLeave / 610.3 | P | 本轮倒料完成且允许离开 | H撤本轮周期后，PLC处理退出闭合 |

阶段表表达业务条件，不保证跨PLC扫描、网络轮询的多个位在同一瞬间变化。写入后读回只证明该地址采样值，不能替代实际机械结果。

满箱呼叫需在第4阶段撤销，取箱回读和清应答时仍要求呼叫0。第27阶段清返箱责任前，必须已新鲜核实本轮呼叫低、取箱通知和放箱通知闭合。清0.6的意图及下一阶段先持久化；之后PLC可以锁存新的满箱事件，即使主机尚处于第28阶段回读，也不阻断前轮结束、不清除新呼叫。前轮任务结束后按正常去重入口受理新需求。PLC仍须区分新的满箱事件和上一轮残留需求，不能因旧满箱条件持续立即重复呼叫。

## 实际出区及资源交接

`ReturnEmptyBox`检查点独立执行：`AwaitPhysicalExit → ClearDumpingAfterExit → AwaitDumperClosed → ReleaseDumper → ExitHandoverComplete`。原返回命令继续按原任务号追踪，不生成新号替代。只有实际出区证据和PLC退出握手闭合后，才在持久化交接中释放本任务倒料设备归属及明确验证的倒料区域租约；其他道路资源继续保留原流程约束。

需显式配置 `HandshakeExecution:DumperExit`：

- `ResourceIds`：实际倒料区域的地图资源ID，必须有有效边界，倒料节点与该区域对应。
- `BodyProfiles`：每台车的实测车体及最大约定载箱包络、定位误差和校准确认。箱体外伸必须计入，不能只用车中心点。
- 最小双帧观察间隔、最大数据年龄、最小定位置信度、安全余量和最大路线偏差。
- 地图须使用已核定的米制坐标，车端地图绑定、运行图身份及原命令路线一致。

手动创建选项会按车辆检查唯一包络、标定、有效边界和倒料节点关联；缺失时说明原因并阻止建单。真正准备和发送运输时再次校验原绑定、当前故障、返箱责任、设备归属和返程许可，避免准备命令后条件变化仍发车。原命令重试保留原编号，不能重新建命令规避核对。

首段准备及Outbox实际发送前均需核实原站有箱、呼叫0、受理应答1，且取箱通知0.5、返箱责任0.6及放到位0.7均为0。首段已绑定后点表地址变化也不能改用新地址继续发车。仓库的`AgvDispatch.Service/appsettings.example.json`列出新版配置结构，默认仍关闭执行，区域及实测包络留空；正式运行配置和旧活动数据库未由本次代码提交覆盖。

原工位可按项目已有规则使用逻辑节点ID或厂家站点别名；返箱核对要求唯一启用映射，不能因别名、大小写差异卡住，也不能用缺失、重复、禁用节点或实际倒料节点代替原工位。

具体配置结构以 `DumperExitConfiguration`、`DumperExitBodyProfile` 和代码校验为准。默认阈值是软件保守初值，不能当现场测量结果。当前位置进度只在可核定直线段上建立；原返程包含曲线时，只有曲线完整的保守边界加整车/载荷误差包络也完全在倒料区域外，才允许将该曲线作为后续不再入区的证据。曲线包络可能碰区、当前位置可能位于曲线保守边界内或进度有歧义时保持占用，等待可核定的区外直线定位；界面观察按钮不能代替这些判断。

`ExitHandoverComplete`只表示本任务实际出区交接已完成，不表示返程任务或放箱已完成。前车之后只处理自己的原工位；后车可使用共享倒料位。前车最终收尾不检查、不清后车共享H位，也不重新申请倒料设备。

## 版本、恢复与取消

必须显式启用持久化执行且 `PlcContractVersion=plc-28-stage-v2`。旧 `sender-owned-return-confirmed-v1` 检查点和活动任务保留，不静默迁入，不复用旧任务制造新28阶段通过记录。升级前备份并按原流程处理未完成任务；测试用新独立数据库和新任务，不删除旧证据。

每次启动仍通过恢复屏障核对原车辆、位置、载荷、原任务号和PLC周期。待确认写入不自动补写；人工确认必须取得本次启动后的新鲜、同地址期望值回读。旧契约不能通过人工确认入口变更成新契约。

若重启核对时车端原返程已完成，而出区检查点尚未交接，允许在原任务号、车辆、目的站、定位及停车证据一致后，仅补记原返程运输的机械终态。`AwaitPhysicalExit`、`ClearDumpingAfterExit`、`AwaitDumperClosed`、`ReleaseDumper`及原设备、道路占用继续保留，不以到站补记生成出区证据。若恰好停在出区清位的`WritePending`，还必须明确确认该原写入并取得同地址期望值回读；写入确认与机械补记在同一事务提交，审计失败一起回滚，不重新写PLC。

机械补记只激活原`PlaceEmptyBox`通知节点，屏障仍关闭。操作者继续核对本次启动后的原工位八个信号、取箱及返箱责任保持和全场状态，才可放行恢复屏障。放行后仍由原返程的独立出区执行器核实几何、原路线、PLC闭合并交接；`PlaceEmptyBox`仍等待`ExitHandoverComplete`，恢复页面不会代替该门禁发送放箱通知或释放设备、路权。这样避免“恢复等出区、出区执行又等恢复放行”的互等。

未完成出区交接时，保留倒料设备归属和必要路权；返回接受、取消应答、超时或心跳过期均不等于退出。已保存本任务 `ExitHandoverComplete` 且无待确认写入时，前车恢复及取消关闭不再要求共享倒料位低，避免后车活动被误当成前车未闭合。前车原工位通知、载荷、停车、原任务结束及路权仍必须核实；记录与残留本任务设备归属矛盾时继续阻断。

取消关闭不发送PLC复位、不自动释放道路资源，设备删除严格限定本任务；不操作其他任务归属。

## Web和实验台操作

Web任务详情按本任务契约显示28阶段要求、实时当前检查点、实际出区证据和交接结果。未来步骤不以当前电平判定完成，旧版本只回看原契约。返回执行中的出区检查点也显示当前条件，不再等到第9步才显示退出核对。

人工PLC网络模式：操作者只写P输入，H由正式后台经S7写回。第3阶段看到H应答1后撤P呼叫，未撤前首段不开始；第7阶段后不要手动清H取箱通知；第19阶段观察真实退出及H周期0，之后按测试条件撤Done；第25～27阶段观察H顺序，清返箱责任前原工位有箱、P呼叫0持续成立。选择表行或“记录实际已退出”仅写观察日志，不改变调度执行证据。工具没有AGV派车功能。

离线演示不接PLC；本机虚拟设备模式只作用于匹配的独立实例。更新工具不等于更新旧后台、旧配置或旧任务；禁止把旧实例截图作为本版本测试结果。

## 必须验证的场景

1. 单车完整四段循环：取箱通知全过程保持，出区及PLC闭合后交接，返箱责任最后清零。
2. 同工位再次呼叫：前轮闭合后新呼叫合法建单，同站首段必须保留真实配置动作，不能跳过取箱。
3. 出区保护：缺边界、包络未核定、车中心出区但箱体仍在、定位过期/低质量、地图不符、曲线保守包络可能碰区或当前位置进度不能唯一核定时保持占用。
4. 失应答及重启：写入待核对不重复触发，原任务号和出区检查点可核对；原返程已完成但出区未交接时可只补机械终态、保留原出区阶段并逐项核对后恢复；PLC重启初值不能当旧周期完成。
5. 后车共享位高时前车返箱收尾和取消：只处理前车原站，不清后车共享信号、不影响后车设备归属。
6. 至少三车竞争同一倒料设备：设备归属唯一、排队不串许可、实际退出前后资源交接正确；虚拟协议回归与厂家实车结果分别记录。
7. 残留呼叫：未撤呼叫不开始取箱首段，取箱回读和清应答阶段保留呼叫0门禁；清返箱责任前出现呼叫1时阻断。第27阶段清返箱责任后产生的新呼叫应保留，不能让第28阶段等待旧呼叫低而卡死。
