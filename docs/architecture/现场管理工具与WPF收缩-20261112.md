# WPF 现场管理工具

日常业务界面统一为 http://127.0.0.1:5199/。原 `AgvDispatch.Wpf` 工程现在仅编译 Management 下的现场管理工具，关闭窗口不停止后台。

## 使用

发布包根目录双击「启动现场管理工具.cmd」。工具从同目录最新版Web.json读取当前版本，再验证发布清单和 Service/WebHost 实际程序集版本。不能手工填写任意可执行文件作为管理目标。

按用户参考图调整为浅灰侧栏、橙色选中与行内操作的「AGV 软件助手」。默认进入服务管理，以数据服务、调度服务分组展示实际组件。

五个入口：服务管理、版本与备份、软件信息、日志管理、系统设置。系统设置承接原网络检查、通信诊断及启动配置；软件信息承接原运行概览。发布包根目录「启动软件助手.cmd」与原「启动现场管理工具.cmd」均打开同一工具。

SQLite 是内嵌数据库，数据服务行提供只读完整性检查、目录和备份入口，不提供虚假的进程启停。Service 与 WebHost 行的启停按钮都调用统一启动器、作用于整个系统，表下明确显示联动范围。当前项目没有 MySQL、Redis、Nginx 独立组件或授权管理，不展示这些无实际实现的行。版本切换仍沿用现有受控发布流程，版本页提供真实版本信息和已有备份恢复能力。

- 启动：调用当前版本自带的 WebLocalLauncher，传入现有日常配置与数据路径。不开辟新日常端口，不恢复单次导航许可，不另建数据库。
- 停止/重启：确认后校验启动记录中的 PID、启动时间和路径。后台必须有新鲜状态、任务清场、无路权、无待发送命令，在线及降级连接的车辆须有有效停稳数据且未充电；离线、未启用或正在重连的车辆不因缺少遥测阻止空闲软件停止，但其已报告任务或充电仍会阻止停止。SQLite 短事务阻止清场检查到停止之间的新派车写入。允许关闭离线时的空闲软件不代表确认车辆停稳；工具不向车辆发送停车指令，也不是车辆急停装置。
- 并发配置：系统停止后可修改下次启动的并发数，保存前备份入口配置，不更改生产/导航/PLC/AGV许可。其他业务参数继续在 Web 维护。
- 网络：列出现有 IPv4 网卡，可打开 Windows 网络设置及进行显式 TCP 连接测试。Web 当前只允许回环访问，显示网卡不代表已开放远程访问。工具不关闭防火墙。
- 通信：从同一后台 Named Pipe 读取当前设备状态、当前及保存配置；进入 Web 工程配置页编辑。后台不在线时显示未知，不制造示例或正常状态。
- 备份：后台及 Web 全部停止，锁住当前启动器后对完整运行数据生成哈希清单及 ZIP；检查数据库 quick_check。不在后台运行时直接复制 SQLite 文件。
- 恢复：只接受本工具生成的同版本备份；路径穿越、重复条目、清单缺失、哈希错误及不完整数据库均拒绝。在独立临时目录核验后替换运行数据，旧数据保留，失败时回退。不自动启动服务或放行恢复屏障。不恢复日常入口版本指向，跨版本恢复需迁移流程。
- 诊断：导出当前观察、网络、本次操作及最多12份各256KiB的日志尾部。诊断包不包含原数据库与完整通信配置。包可能包含现场日志信息，按现场规则保管。

## 构建与发布

`dotnet build AgvDispatch.Wpf/AgvDispatch.Wpf.csproj -c Release`

`powershell -File tools/Publish-SiteManager.ps1` 自包含发布到新的版本目录，只更新管理工具入口，不替换或重启日常后台。旧管理工具包可用于回退。常规联调包仍将同一工具放在 WPF 目录。

## 历史界面

原 Shell、Modules、Shared、Views、ViewModels、Themes、Styles 的业务界面和依赖不进入新工具。已有历史界面及联合测试改引用 tools/LegacyWpf/LegacyWpf.csproj，以保留回归夹具；该宿主不进入日常发布包。后续可随测试向 Web 迁移逐步删除旧源文件。

## 验证边界

新工具核心维护流程使用隔离临时目录验证。工具能检查空闲不等于可以代替现场确认；实车运行和设备握手的正确性仍由后台及现场验收负责。

首轮验证：新工具27项检查通过，包含备份/恢复、篡改/越界拒绝、配置备份、进程身份及时效、充电占用、未知速度拒绝、只读管道通信，以及各页渲染。历史控件35项检查通过。Release解决方案编译0错误，原基础设施依赖及旧代码的既有警告仍在。旧任务页联调测试因未启动其预置隔离服务而超时，不计通过；没有为此启动现场设备通信。此次未以实车运行验证启停。
