# 多候车位持久选位与待机位绕行保护

任务参数增加 `WaitingSites`；旧文件只有 `WaitingSite` 时仍按单候车位处理。列表首项与兼容默认点相同，每个候车节点需绑定独立容量 1 的交通资源。Web 工程参数可读取和保存完整列表，工程版本绑定仍受原有保护。

送满箱步骤在取箱点选择可达且可取得路权的候车位。选位与本路径租约在同一 SQLite 事务提交，`task_waiting_bay` 按任务保存车辆、送箱步骤、地图版本、站点和资源，禁止更新或删除。没有空位时不登记车辆命令；命令准备失败可回滚该步骤租约，但原选位不改变。后续进入倒料、待发命令核对和设备等待记录使用原选位，重启不会回到默认点或自动换位。

首段车端核验覆盖全部候车点，参数校验覆盖每个工位至各候车点及候车点至倒料点。当前仍使用 28 阶段契约；候车位的保留路权在原任务闭环时释放。本次不增加驶离候车位自动释放功能，不能据此声称此前的候车位延迟释放已解决。倒料设备及已核验倒料区域仍按已有实际出区证据交接。

普通运输禁止把候车、倒料或配置待机位当作中间捷径；允许这些点作为当前运输的真实起终点。同点取箱仍需实际启用的出入闭合路线。修复了不同起终点的运输规划曾忽略中间禁行点集合的问题，避免公共环路被更短的停车支路绕过。

验证使用隔离 SQLite 和合成路网，不连接现场车辆：多候车资源互斥、两车选不同空位、第三车等待、事务并发不超卖、重启及命令准备回滚保留选位、换车改位拒绝、待机捷径禁止且正常离开允许。另回归 28 阶段握手、持久执行、多车测试和候车位只读出区核验。实车空载测试不能替代带箱、机械倒料及真实总 PLC 验收。
