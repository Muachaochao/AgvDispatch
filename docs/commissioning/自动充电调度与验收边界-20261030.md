# 自动充电调度与验收边界（2026-10-30）

本次依据用户明确提出的充电开发需求、当前主工程及本地 Robokit 协议档案补充自动充电。日常 Web 入口继续为 http://127.0.0.1:5199/，新增“充电管理”。没有现场充电桩、车型充电动作和实车样本确认，默认不自动发车或开启充电继电器。

## 已实现的流程

电量≤25%生成持久化充电需求；同车不再接新业务，当前完整箱体循环及设备握手继续收尾。严重电量≤15%即使自动充电关闭也禁止新增业务。低电量车辆优先，同电量按申请时间排队，车辆可用的充电位按可达路径成本选择。30%/15%告警保持原规则。退出门限默认80%，充到40%不会因高于启动门限中断充电。

持久会话依次经过排队、等待业务结束、预留充电位、前往充电点、确认导航完成和实际停靠、继电器开启、等待充电状态及正电流、持续充电、停止继电器、确认停止、退出、确认实际离位、释放资源。控制动作前先落盘原命令身份；发送超时、回执未知、断网或重启都不自动重发。进出完整路径和容量为1的 ChargingBay 一并保留，期间不会因租约超时释放。

业务门禁同时检查未结束任务、车端原任务、未闭合 Outbox、PLC 设备责任及其他路权。新业务分配和充电使用共同串行锁，按“充电锁→地图执行锁”的顺序获取。充电归属阻止同车手工业务、独立导航、升降测试、断开连接；已有物理充电会话阻止切图和通信配置变更。纯排队需求不占物理路权，切图后重新规划。

无电流、过温、充电状态消失、手动充电器连接信号、导航中止、对接超时、地图/定位异常均保留充电位待核对。能够读取到原充电会话的保护异常时只发送一次停止继电器；发送未知时保留原停止意图。停止申请不等于释放；正常退出和人工关闭都要证明停止充电、停稳、实际出口位置及原任务终态。

重启后原动作阶段转为 Hold。可以查询原命令后人工续接观测；未确定的开启/停止/导航不会重发。启动恢复期间也可通过“核对离位”进行只读现场证据核验，关闭并释放已确认实际退出的会话；恢复页随后核对本次启动保存的原车辆、步骤、地图及完整资源快照，不能凭 CHARGE 前缀、空任务表或资源消失放行。

人工停止包括启动恢复期间的停止，均只尝试一次关闭继电器并保持 Hold，不自动退出或释放；须人工核对后续接原流程或确认实际离位。网页定时读取不会覆盖操作失败提示，也不会自动重试写命令。

## 厂家接口及现场条件

依据 `docs/vendor/robokit/README.md` 指向的当前467文件档案，已逐项验证SHA256。使用1007读取电量、charging、current、battery_temp等，使用其他API端口6005发送 `{ "status": true/false }` 控制车端继电器，必须收到明确 `ret_code=0`。不自动重发6005。

6005只控制车端继电器，不证明完成桩握手；`auto_charge`/`manual_charge`是连接信号，不证明实际充电或控制来源。现有档案未给出此现场充电桩通用握手、精确对接动作。当前支持的模式为已现场核定的 `Relay6005`：厂家需确认配置站点的导航到位已完成安全对接，以及桩在车端继电器控制下能自行完成所需握手。需要额外桩通信/PLC握手/专用对接动作的设备必须补充其有效协议并扩展接口，不能直接套用本模式。

当前策略以充电正电流大于配置门限作为通电证据；停止要求 `Charging=false` 且电流不大于门限（允许已核定的放电负电流）。本地协议仅说明电流单位A，没有定义方向，必须现场核定本车型极性。温度上限默认45℃，须依照厂家/电池要求核定。退出点必须处于充电资源以外，车辆实际报告站点和坐标均须匹配；当前停靠坐标容差0.3m，不能据此宣称已证明充电触点的机械精度。

## 配置示例

在当前发布包 `Service/appsettings.json` 中配置，下例全部是示例编号，不能直接作为现场参数：

```json
{
  "Charging": {
    "Enabled": false,
    "StartBatteryPercent": 25,
    "CriticalBatteryPercent": 15,
    "TargetBatteryPercent": 80,
    "NavigationTimeoutSeconds": 600,
    "CurrentTimeoutSeconds": 60,
    "ChargingTimeoutSeconds": 14400,
    "StopTimeoutSeconds": 60,
    "StateMaxAgeSeconds": 5,
    "MinimumChargingCurrent": 0.1,
    "MaximumTemperature": 45,
    "Sites": [{
      "Id": "示例充电位",
      "ChargingSiteId": "示例厂家充电站点",
      "ExitSiteId": "示例厂家出口站点",
      "ResourceId": "示例独占资源ID",
      "AllowedVehicleIds": ["示例车辆ID"],
      "ControlMode": "Relay6005",
      "Commissioned": false
    }]
  },
  "RobokitCharging": { "OtherApiPort": 19210, "RelayControlConfirmed": false }
}
```

还须启用已有AGV采集、动作许可和运行地图门禁，完成厂家地图/坐标绑定。地图充电点须为 ChargingPoint 并关联容量1的 ChargingBay 资源，进出路线连通、出口不再属于同一充电资源。`Commissioned` 和 `RelayControlConfirmed` 只在完成现场核定后设置；网页不提供绕过现场核定的一键启用。导航/PLC空载/多车联调启动模式独占测试范围，不混入自动充电。

当前安全交接依据业务整轮结束、设备责任、任务和Outbox证据；没有新增1027实时货物状态采集。厂家还需核定本车型能否带载充电、结束箱体循环后的实际载荷及安全返程余量。未证明现场载荷策略前不得启用。多车按低电量排队，等电量按申请顺序；未配置桩功率加权或估算耗电量的调度模型。

持久会话位于当前数据库旁 `charging-sessions.json`；日常数据继续保存在“发布包/运行数据/后台5199”。更新前备份数据库、通信设置、工程方案和充电记录。升级不会自动提升原执行许可。

## 隔离验证与现场验收

可重复执行：

```powershell
dotnet run --project tools/ChargingProtocolSmokeTest
dotnet run --project tools/ChargingSmokeTest
dotnet run --project tools/ChargingRecoverySmokeTest
dotnet run --project tools/ExecutionRecoverySmokeTest
dotnet build AgvDispatch.WebHost/AgvDispatch.WebHost.csproj
./tools/Test-ChargingHost.ps1
cd AgvDispatch.Web
npm run build
```

隔离验证覆盖协议分端口/严格回执、不确定发送不重发、任务完成再充电、两车抢位、滞回、导航对接超时、无电流、过温、断网、人工干预、真实SQLite交通占用及重启、设备责任和Outbox残留、连续业务安全交接、真实后台与Web进程/Named Pipe接入。合成夹具和模拟器通过不能替代现场验收。

本次验证结果：充电状态机69项、协议适配24项、充电恢复20项通过；既有执行恢复228项、地图切换93项、多车联调199项、业务运行96项及反馈23项回归通过，通信设置与派工流程烟测通过。Service/WebHost及前端发布构建、真实Service/Web隔离进程接入通过。

现场必须逐项验证：目标电量停止、两车竞争一个充电位、整轮业务结束后充电、人工操作、对接失败、无电流、过温及BMS报警、断网、后台重启、停止失败、实际退出后释放，以及充电完成后可重新接单。每项记录车辆/固件/桩型号、原命令、1007采样、桩侧证据和离位结果。当前结论为软件流程及隔离验证已实现，实车自动充电尚未验收。
