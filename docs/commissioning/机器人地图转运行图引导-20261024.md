# 机器人地图转运行图引导（2026-10-24）

## 问题与修改

原 SMAP 拉取或导入生成 SmapWorldTranslated 显示预览，站点和道路默认停用。此前允许发布后进入切换，直到激活才发现无有效道路及停靠点，留下未提交的 Draining 批次。

- 地图编辑新增“准备运行地图”，逐站确认用途，并明确确认车端坐标及按原始 SMAP 重建导航编辑稿。原始文件按 SHA256 留存、校验；从原字节重新解析，不能通过更改坐标系文字假装完成转换。
- 后台使用既有 PrepareRobotWorldRuntime 还原站点、曲线控制点和区域边界，启用道路，重新附上厂家路径证据；保留方向、编号和源摘要。请求缺少站点用途、没有停靠点、源摘要不符或不支持的节点/路径时拒绝准备。
- 仅改变当前导航编辑稿，保持现有后台关联；不自动保存、发布、激活、恢复派单或发送设备命令。原始图重新生成会替换导航手工编辑，窗口明确提示。
- 切换开始前检查预览坐标系、有效停靠点、有效启用道路，失败不创建切换记录、不关闭原执行门。
- 对升级前留下的未提交预览图批次，人工取消仍要求全体任务、资源占用、命令、步骤、实车状态及 PLC 核验；不依赖从未投入运行的预览坐标。关闭后保持 Held，不能借取消预览恢复原地图业务。
- 只读复核增加进入安全切换入口；人工取消前重新读取原编号观察，避免填写依据期间七秒观察过期造成操作无路可走。取消后仍须复核关闭结果。

## 操作步骤

1. 若存在失败的原切换：地图管理 → 只读复核原激活 → 查看阻塞并处理原切换。核对现场和原批次、填写依据后“重新核对并取消切换”。复核关闭结果，再进入地图编辑。取消保留暂停。
2. 已有 ZM-test 草稿：读取目录 → 选择该地图 → 读取完整草稿并替换，不必再新建项目。
3. 新图：选择车辆 → 从机器人拉取当前地图 → 核对并加载到编辑稿。读取的是机器人已保存地图，不含工具中尚未推送到车端的修改。
4. 准备运行地图 → 每个站点选择用途。纯导航测试停靠点可选择“测试停靠 / 等待位”；业务点、路口、途经点、充电位按现场分别确认。
5. 确认车端原始坐标、重建编辑稿 → 还原坐标并应用到编辑稿。
6. 保存地图草稿；首次未关联后台时先新建后台地图。已有项目继续发布新版本，不覆盖历史版本。
7. 去地图管理发布／激活 → 发布草稿 → 核对车辆实际停靠位置及目标地图兼容性 → 激活 → 安全切换核对后放行。地图切换不自动解除独立启动恢复屏障，也不启用单车发送许可。

- MapSwitchSmokeTest：86 项通过，包括预览、停用道路、无停靠点提前拒绝；旧预览批次取消必须静止且不恢复执行。
- SingleNavigationTestSmokeTest：83 项通过，仅仿真。
- Web：142 项测试通过；vue-tsc / Vite 构建通过。
- Service、WebHost self-contained 发布通过。备份运行数据与旧组件后更新现有 5199；发布包校验 1365 项初始文件哈希及三组件身份通过。
- 在线接口使用现场 ZM-test 留存原图进行非持久化准备：7 站、12 有向边、5 区域；7 站坐标与原图误差不超过 1e-9；厂家路径证据保留；缺失用途明确拒绝。
- 浏览器核验运行图引导窗口，未选择用途及确认时应用按钮禁用。未保存、发布、取消现场批次或执行设备动作。

限制：本次准备入口支持现有 2D JSON SMAP；原始源文件缺失需重新拉取或导入，不猜测坐标偏移。厂家区域只显示，不自动生成交通锁或 PLC 业务；源图未转换的厂家行为仍按已有提示核对。
