# AGV Web 可视化接入版

在原 C# 调度后台上增加浏览器视图。复用 medicalprogrammer/agv-web-visible 的实际 Three.js 绘制代码，保留原 MIT 许可证；不是上游整仓原样迁移。

## 已有功能

- 深色调度大屏：中央地图、左侧车况及告警、右侧任务与资源、底部设备状态；默认2D，可切换3D。
- 车辆、任务、告警及地图版本管理视图，支持搜索、筛选和详情弹窗。
- 三维/俯视导航图、站点和路线、共享资源范围、车辆选择及路段高亮。
- 车辆原始位置、电量、连接/质量、任务列表筛选、九步任务详情、PLC 条件及设备字段。
- 生产页面启动即连接真实C#主服务；未连接/过期明确提示，不生成车辆、任务或地图。合成数据只保留于测试夹具。
- 本机 C# WebHost 提供 HTTP/WebSocket，串行调用现有 Service Named Pipe。
- 创建条件/路线核对及任务提交接口；提交默认关闭，开启后仍由现有后台核验、落库和派发。Web 不报告“动作已完成”。
- 工程工作台：地图/场景编辑、方案保存与JSON导出加载、车辆新增配置、航点排序和路线展开；用法及生效边界见 [WORKBENCH.md](WORKBENCH.md)。

## 直接试用

项目根目录 `发布包/Web可视化试用` 为独立试用包，不替换现有 WPF/Service 发布文件。

双击 `Start-WebPreview.cmd`，看到 `Now listening` 后，在浏览器访问 `http://127.0.0.1:5188/`。CMD直接运行WebHost，不调用PowerShell脚本，不要求改变系统执行策略。保持启动窗口打开，按Ctrl+C停止该Web进程。

默认连接目标为原主服务管道 `AgvDispatch.Service`，页面只显示后台真实观察。主服务未启动时显示未连接，不自动回退演示。启动入口不启动主服务、不启用PLC/车辆执行或Web任务提交。旧PS1入口仅在系统允许脚本时使用，隐藏启动的旧进程由同目录`Stop-WebPreview.ps1`核对身份后停止；该停止脚本不负责CMD前台进程。

需读取现有后台时，先停止旧预览，在试用包目录执行：

```powershell
./Start-WebPreview.ps1 -PipeName AgvDispatch.Service
```

管道名按实际后台配置替换。此命令仅选择已有后台连接目标，不负责启动调度主服务。页面自动读取后台；服务不可用会明确报错，不自动换成演示。后台仍按其现有配置控制设备通信和执行。该接入版只有本机访问，不用于局域网多人登录。

## 源码构建

在本目录安装/构建前端：

```powershell
npm ci --registry=https://registry.npmjs.org
npm run build
npm test
```

在 DispatchingSystem 目录启动接入层：

```powershell
dotnet run --project AgvDispatch.WebHost -- --Web:PipeName=AgvDispatch.Service
```

接入层默认从 `AgvDispatch.Web/dist` 提供前端。更换静态目录用 `--Web:StaticPath=绝对路径`，更换端口用 `--Web:Port=5188`。Vite 的 `npm run dev` 仅用于前端开发，实际接口验收使用 WebHost 同源服务。

WebHost 的 `Web:EnableTaskSubmission` 默认 false。联调需要开启时应使用隔离后台先验证，生产行为仍以主后台门禁为准。本次没有启用现场提交。

## 当前限制

1. 实时页面使用后台当前运行地图的导航几何。第一版没有转发厂家激光底图、CAD 高清背景或三维点云；不把导航图称作完整厂家地图展示。
2. 车位须有当前地图版本的已核定坐标绑定，并且位置在线、Good、新鲜、定位正常。平移 Smap 目前没有通过 IPC 传递坐标变换，车位只显示原始数值，不叠加。未知坐标不猜测。
3. 多接口采集不是设备原子快照；观察到运行地图变化会拒绝该次快照。断连/过期取消车位显示，保留数据只作为最后一次观察。
4. 大屏快照最多50条任务，不作为全历史统计。任务页可查询后台搜索/状态筛选及分页，每页50条；任务详情可导出单任务联调包。告警为最近100条，只读查看，确认与恢复分别显示。
5. 地图草稿编辑及发布、车辆配置保存已有Web入口；正式地图切换、坐标绑定核定、取消/解锁及PLC参数修改继续使用WPF。Web恢复入口复用原后台，写操作默认关闭。场景与综合方案存于浏览器，需导出备份，不自动覆盖运行配置。
6. 页面只接入真实后台，不再提供运行示例入口。任务提交申请编号保存在当前浏览器 sessionStorage；结果不明时保留原编号，无自动补发。跨浏览器找回尚未实现。
7. WebHost 固定监听 127.0.0.1；现有后台以本机操作模式处理管道请求。本版不新增用户认证，不对外发布，也不宣称具备远程多用户权限隔离。
8. 地图显示预算为5000节点/10000道路/2000资源，单个WebSocket消息8MiB。超预算或不支持几何会明确拒绝/提示。

## 2026-10-17 任务运行诊断

任务列表/大屏中打开任务详情，可选择九步查看后台完成依据、当前观察条件、未满足原因、原车辆命令和关键事件时间线。新增字段需要本次更新的主Service；旧后台未提供时页面会提示。

第一批阶段解释是对原执行器的诊断。第二批新增独立契约执行器，配置未启用时仍按原执行器观察。当前值满足、写回成功、PLC业务接收和机械完成分别对待。第一批记录见`docs/architecture/Web任务运行诊断开发记录-20261017.md`（相对主工程）。

## 第二、三批：持久化握手和联调闭环

任务详情新增握手周期/阶段/revision/原始基线、待核对写入、返程定位及资源交接诊断。信号变化支持类型、变量、时间和固定序号窗口分页；联调ZIP附CSV及SHA256清单。恢复入口读取原后台全场批次；`Web:EnableRecoveryActions=false`默认只读，不绕过原权限和恢复门禁。

新执行契约`sender-owned-return-confirmed-v1`由主Service执行，默认关闭，需PLC按明确的Ready消费及倒料通知延后复位时序联调匹配；不把Web界面更新当作现场协议已生效。旧任务不自动迁移，已绑定新契约的任务不能静默降级旧执行器。试用包仅更新接入层，主Service需另行部署本次源码。

完整信号时序、推进条件、复位责任、断电恢复及导出限制见主工程[持久化握手与Web联调闭环](../docs/architecture/持久化握手与Web联调闭环-20261017.md)。该批通过前端15项、隔离Web53项、持久化握手37项、恢复132项及任务中心回归；没有连接现场设备。截图`evidence/task-signal-query-20261017.png`、`evidence/task-runtime-20261017.png`来自隔离后台。该批遗留WPF创建/提交问题的最新复查见下一节。

## 联调检查、后台版本与缺项导航

顶部“联调检查”统一读取主后台：执行开关、恢复门禁、运行地图、九步配置、车辆状态、地图绑定及13位信号。选择工位/车辆后重新检查；缺项可跳到地图/车辆配置、实时车辆列表，或显示WPF任务参数、绑定及恢复的具体路径。只读四段核验复用原后台预检，不创建任务。

顶栏和检查页显示主Service版本、程序集SHA256、启动时间及执行模式。15秒观察窗口过期、断连、后台重启、构建或地图改变后不再显示当前通过。检查结果不作为提交放行凭证。旧后台未提供新接口会明确提示，需部署匹配主Service；页面不会自动更新后台或开启执行。

本批通过前端17项、Web接入60项、手动创建235项、WPF两车集成61项、独立进程18项。此前创建/提交断言在本轮当前代码未复现；首次遇到的WPF生成缓存缺失经Rebuild恢复。完整使用顺序和测试边界见[本批记录](../docs/architecture/联调检查页与创建提交回归-20261017.md)。截图`evidence/commissioning-*`来自隔离服务。
