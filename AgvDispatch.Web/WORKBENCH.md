# Web工程编辑与建图使用说明

本次扩展使用现有C#后台与Robokit TCP，没有替换厂家导航控制器，也没有新增激光SLAM。入口为顶部“工程编辑”；车辆列表和地图查看也有对应入口。

## 建图与使用顺序

1. 使用厂家RoboShop完成激光扫图、导航站点和车端地图配置，取得现场导出的SMAP。Web中的空白导航图不是激光扫图。
2. 在Web连接后台，进入工程编辑→加载文件，选择SMAP（当前上传限8MiB，较大地图先用WPF导入）；解析使用现有主工程导入器。规范化地图JSON及Web方案JSON也可加载。
3. 核对导入预览后加载编辑稿。已有后台地图应先读取目录，再“读取完整草稿并替换”，以保留曲线、关联和编辑令牌。
4. 编辑航点、道路、共享区域；每个对象的属性需点“应用属性”。本地结构检查仅检查基础数据，后台仍执行正式几何校验。
5. 需要保存后台时，新图先“新建后台地图”，再“保存地图草稿”。已有地图直接保存关联草稿。发布操作只发布后台已保存的版本；不会自动保存当前未应用属性，也不会自动激活运行地图。
6. 地图管理已有版本激活与安全切换入口，仍由原后台核验；车辆地图及坐标绑定核定继续用主工程WPF流程。编辑草稿、发布版本与运行切换是三个独立动作。
7. 用场景编辑补充车间、设备区域和标注；用车辆配置录入控制器IP及端口；用航点顺序核对道路路径。保存/导出方案备份这些编辑内容。

## 文件格式与持久化

- Web方案：`schema=agv-web-plan`、`version=1`，包含地图定义、场景、车辆配置及航点顺序；不含PLC点表、执行开关或权限。加载有预览，不直接覆盖后台。
- 地图JSON：导出主工程可导入的规范化MapDefinition。此格式不称为厂家SMAP，不承诺可直接写回车端。
- SMAP：通过WebHost临时文件交给后台解析，返回后删除上传临时文件。需要同机后台具备文件读取权限。原生地图大文件、附件、CAD背景和3D展示继续沿用主工程；本次没有把它们完整迁移到Web。
- 本机方案按页面来源分别保存：例如5188与5190是不同存储空间。清除浏览器数据会删除本机方案，应导出文件备份。地图草稿保存不保存场景；方案保存也不自动写后台车辆配置。

## 联调边界

生产入口现已默认连接AgvDispatch.Service，未连接不生成数据。车辆新增默认不启用；填写端口仅是配置，不会立即建立连接。后台保存保留原有PLC、地图绑定、全局通信和协议配置，仍受权限、任务、地图切换/恢复门禁及revision核验；网页不会自动重启服务。

大屏运行数据与工程编辑稿分开，加载方案不替换大屏真实数据。场景暂仅在工程画布显示，不作为调度避障依据。路径计算根据图中距离，既不是厂家路径核验，也没有交通时间窗、实时占用或PLC动作语义；保留正式任务的九步流程。浏览器路线计算有预算保护，较大图应使用后台路线预览。

## 验证

前端类型检查、生产构建和15项状态/模型测试通过。隔离真实Service→NamedPipe→WebHost的53项验证通过，覆盖地图/车辆原有操作及任务事件查询、导出校验、恢复只读和默认写入拒绝。另通过37项持久化握手、132项恢复测试及任务中心回归。所有设备执行关闭，未连接现场。此前浏览器实测场景属性、车辆新增、航点展开、方案保存和文件导出后再加载，保留8航点/9道路/1场景/1车辆/2顺序航点。

任务详情中可查询信号变化并下载联调ZIP；恢复入口操作默认关闭。新契约的阶段、周期、意图及返程证据均来自主后台数据库；没有检查点时明确提示。完整推进条件和现场边界见主工程`docs/architecture/持久化握手与Web联调闭环-20261017.md`。

本轮新增顶部“联调检查”：选择工位/车辆→重新检查→处理缺项→只读核对四段路线→进入任务列表。地图与车辆配置可直接跳转；任务参数/地图绑定提供Web工程配置入口，恢复继续受原后台门禁保护。构建身份、启动时间及执行模式来自主Service；窗口过期和身份变化撤销当前通过。最新验证：前端17项、Web60项、手动创建235项、两车集成61项、独立进程18项通过；不代表现场验收。详见主工程`docs/architecture/联调检查页与创建提交回归-20261017.md`。
